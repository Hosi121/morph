# 構造を保持して算法を選ぶ

[ハンドブック](../../HANDBOOK.md) / [確率と情報幾何](probability-geometry.md)

この章は、検査した性質や構成過程を保存し、その後の演算で使うための設計をまとめる。
値を一度検査して汎用の行列・テンソルへ戻すと、利用側で検査や分解を繰り返し、既知の零や対称性も利用しにくくなる。

## 条件・由来・表現を分ける

| 型が保持するもの | 具体例 | 選べる演算 |
| --- | --- | --- |
| 検査した条件 | 正の有理数、正定値形式 | 安全な逆数、正の行列式、解が一意なsolve |
| 構成過程から従う関係 | Gaussian・指数型分布族のHessian構造 | 計量と3次cumulantからの曲率、双対接続の零曲率 |
| 分解・表現 | 正のpivotを持つLDL、直和、正の定数倍、逆のview | 分解を共有するsolve、ブロック別演算、逆の逆の消去 |

`Semiring[A]` のような演算辞書は操作を揃える。結合則や可換則などの法則は、その辞書の利用条件として別に必要になる。
構造名を示すBoolだけを追加しても、その法則を使う計算の根拠にはならない。
検査済みの入力からだけ構成する、あるいは性質を保存する演算から構成する入口を設ける。

## 正の有理数と正定値形式

[positiveform](../../src/positiveform/positive.mbt) の公開型は外から構築できない。

`PositiveScalar` は正の有理数とその逆数を保持する。
構築時に正性を検査し、逆・積・自然数乗は正性を保つ演算として同じ型を返す。

`PositiveDefinite` は次の構成を保持する。

| 構成 | 不変条件と処理 |
| --- | --- |
| `Dense` | 正方・対称性を検査し、一度のSchur補元再帰で正のpivotを持つLDLを作る |
| `Inverse` | 元の正定値形式を保持する。applyとsolveを入れ替え、逆の逆は元を返す |
| `Scaled` | 正の係数と元の形式を保持する。連続する定数倍をまとめる |
| `Blocks` | 正定値な各ブロックを保持する。直和は平坦化し、solve/applyは各ブロックで行う |

`inverse`・`scale`・`direct_sum` は密行列の生成やLDLを行わない。
`matrix()` が明示的な展開境界となり、既存の汎用行列APIへ接続する。
`determinant()` は正の有理数の型を返し、直和では積、逆では逆数、定数倍では次元乗を使う。
零次元では行列式1、空ベクトルのsolveが成り立つ。

`Eq` は準備済み構成の一致を表す。線形写像としての一致は `equivalent()` で確認する。
これは共通の標準基底すべてへの作用を比較する。有限個の任意点の標本検査と異なり、線形性が既知なので作用素の一致を判定できる。

## 既存の利用側へ性質を渡す

Gaussianは共分散の正定値形式を保持し、`covariance_form` と `precision_form` から取得できる。
`gaussian_from_form` は既存の正定値構成を受け取り、再検査・再分解を行わない。
既存のモーメントAPIが必要とする共分散・precisionの密行列は一度生成してcacheする。
Gaussianの等号は平均・共分散・precisionの値で判定し、準備の構成やcacheを分布の同一性へ混ぜない。

一般の計量jetは引き続き不定値も受け付ける。
`riemann.positive_metric` は正定値な場合にだけ分解を保持した形式を返す。
この型が示すのは一点の計量の正定値性であり、計量場の平坦性やHessian性ではない。

## Hessian構造の由来を保持する

指数型分布族の基準分布と十分統計量、Gaussianの自然座標は、Hessian構造を与える構成過程を持つ。
汎用の点の `(g,T)` にはこの由来が残らないため、Hessian性を仮定する曲率経路への無条件な変換を設けない。
[ExponentialFamily](../../src/infogeom/exponential.mbt) は、正の基準分布と十分統計量、中心化した統計量と2・3次cumulantを保持する。
`point()` で要求したときだけ、従来の標本ごとの確率3-jetへ展開する。

[HessianPoint](../../src/statgeometry/hessian.mbt) の入口は、これとGaussianの `Information` に限定する。
正定値なFisher形式・逆計量・3次テンソル・最後の添字を上げた `K` と、縮約したRicci/scalarを一度準備する。
一般の `ModelPoint` や `(g,T)` から、この型へのuncheckedな変換は設けない。
冗長な統計量による特異なFisher計量は構築時に拒否する。

`curvature(alpha)` は作用素のviewを返す。
Hessian構造から `R^(alpha)=(1−alpha²) R^(0)` が従い、双対端点と1次元以下では零曲率の構成を使う。
`scalar()`・`ricci()` は準備済みの縮約を使い、4階テンソルや4次cumulantを作らない。
`apply(u,v,w)` は `K_u K_v − K_v K_u` の作用を求め、`riemann()` が座標成分への明示的な展開境界になる。
接続係数の簡約式は、保存した自然座標に対するものとして提供する。

## 接空間と双対空間を混同しない

[HessianTangent・HessianCotangent](../../src/statgeometry/hessian_fibers.mbt) は別の型で、それぞれ点と成分を保持する。
`tangent`・`cotangent` は構築時に次元を検査する。
加算・pairing・曲率作用などは、生成元の基準分布と統計量、あるいはGaussianのパラメータも照合し、異なる場合は `PointMismatch` とする。
次元や偶然一致した `(g,T)` だけで座標系を同じとみなさない。

添字上げ `raise_index` は共変ベクトルから接ベクトルへ、`lower_index` は逆方向へ写す。
traceは共変ベクトルを返し、これを接ベクトルとして使うには明示的な添字上げが必要になる。
同じ空間内の加算・定数倍は型と点を保持する。
ベクトルと共変ベクトルの区別は型検査、点・座標・次元の一致は実行時検査で支える。

## 微分形式の閉性と原始形式を保持する

[forms](../../src/forms/closed.mbt) の `ClosedForm` は、閉形式を検査して構築する。
零形式と最高次数以上の検査済み形式は、外微分を作らず閉じていると分かる。
以後の和・符号反転・閉形式同士の外積・多項式写像の引き戻しは、閉性を保って同じ型を返す。
`exterior_derivative()` は既知の閉性から正しい次数の零形式を返し、係数を再微分しない。

`exact_differential(eta)` は `d eta` と原始形式 `eta` を一緒に保存した `ExactForm` を返す。
`as_closed()` は `d²=0` から閉形式を得る。正次数の `ClosedForm.primitive()` は、既存の多項式Poincare homotopyを使って原始形式を保存する。
対象は固定した標準座標の有理affine空間であり、穴のある領域や一般多様体で「閉なら完全」と仮定する入口ではない。
次数−1を表現していないため、0次の閉形式から原始形式を求めると `ZeroDegree` となる。

完全形式は原始形式を伴って演算する。
`wedge_closed` は `(d eta)∧beta=d(eta∧beta)` を、`wedge_exact` は `alpha∧d eta=d((-1)^p alpha∧eta)` を使い、符号も保存する。
加算・符号反転・引き戻しも原始形式の等式を保つ。`check()` で実際にその等式を再計算でき、通常の演算経路では再検査しない。
`ExactForm` の等号は形式の値だけを比較し、異なる原始形式の選択を値の違いにはしない。

外積は検査済み形式の整列した基底添字を線形に併合し、符号と重複を係数計算の前に判定する。
重複した微分を含む組や、合計次数が次元を超える組では、多項式の積を作らない。
生の `form(...)` の入力検査は維持し、不正な添字・係数次元を零化で隠せない。
基底1項同士では、係数が非零の有理多項式であり、その積も非零であることを使う。
添字が重ならない場合は結果を1項の正規形として返し、項の収集・再検査を行わない。
これは有理多項式環が整域であることに依存する簡約であり、零因子を持つ係数環へ無条件には移せない。

これらの不変条件は公開入口の制限と法則を保存する演算で支える。新しい算法の形式証明ではない。
既存Fraction参照の微分・homotopy例、次元6までの全5461基底対、左右の完全形式の符号、非線形引き戻し、次数・空間違いを検査する。
[統合検証記録](../measurements/forms-structure-integrated-20261118-validation.json)は、ソース `5deb372` を固定した3パッケージのWasm GC・JavaScript・native releaseでそれぞれ814/814を記録する。
全体の3ターゲット型検査、82件のPython検査、文書・生成物・公開API・381 kernelファイルの純粋性検査、既存Lean検証も通過した。
既存Leanモデルの通過は、新しい閉形式・完全形式や併合算法を形式証明したという意味ではない。

[初回の100プロセス比較](../measurements/forms-structure-20261118-summary.json)は、同じnative release実行体で従来経路と比べ、全成分・次数・次元をFraction参照と照合した。
5 ABBA blockの従来/構造経路の中央値比は、重複基底で1.707、多数の基底を含む外積で2.216、既知の閉形式の外微分で1.857、原始形式で1.084。

## 次の表現候補

対称テンソルの独立成分、既約多項式で作る有限体なども、構成が演算を制約する別の例となる。
それぞれ、何が検査済みか、何が構成から従うか、どの展開や演算を省けるかを明示してから専用表現へ移す。
[Hodge演算の章](hodge.md)では、固定した正定値内積と向き、体積の平方根、外積の構成を保持する実装を説明する。
接続1形式・曲率2形式は今後の段階とする。
変数に依存する計量場のHodge星では、有理関数や平方根を含む係数を扱う必要がある。余微分や接続形式へ進むには計量の微分も必要になる。
一点のFisher計量を、そのまま空間全体で一定の計量とみなさない。

## 検査の範囲

正定値構築は2次の対称整数行列を全列挙した首座小行列の条件、Gram行列、既存の別方式の消去法と照合する。
逆・定数倍・直和は値と構成の両方を検査し、形違い・非対称・特異・不定値・零次元も扱う。
Hessian経路は一般の確率jet・計量2-jetからの曲率と全成分を比較し、球面によるsimplexの閉形式、Gaussianの既知曲率、異なる点や座標の拒否も確認する。
型検査だけでLDL算法やすべての数学的法則を形式証明したものではない。
実際の速度・記憶使用量は別に比較し、構造を保存すること自体を未計測の高速化率へ読み替えない。

統合したソース `f75f80a` の[検証記録](../measurements/structure-modeling-20261118-validation.json)には、変更前後の依存グラフから選んだ8パッケージと、再実行用runner・各段階のログを保存した。
影響範囲の66件はWasm GC・JavaScript・native releaseでそれぞれ66/66。
全体の3ターゲット型検査、80件のPython検査、文書・公開API・生成物・380 kernelファイルの純粋性検査、既存Lean検証も通過した。
Lean検証の成功は既存の形式モデルに対する結果であり、今回の正定値・Hessian型の法則を新たに形式証明したという意味ではない。
[比較用worktreeの片付け記録](../measurements/structure-modeling-20261118-cleanup.json)には、重ねたCLIソースと依存ソース一式の保存・hash照合を残した。

Gaussianの通常構築は、[旧版との60プロセス比較](../measurements/structure-gaussian-20261118-summary.json)で全出力が独立Fraction参照と一致した。
5 ABBA blockの旧/新中央値比は `diag2=1.074, dense3=0.993, dense6=0.957` で、改善方向のblockはそれぞれ4/5・3/5・3/5。
この比較から通常構築の全般的な高速化は主張しない。正定値の構成・分解を保存する機能と、速度上の採否を区別する。

Hessian経路の[初回80プロセス比較](../measurements/structure-hessian-20261118-summary.json)は、同じnative release実行体で一般の計量2-jet経路と比較した。
標準Gaussianの元の次元1・2（自然パラメータ次元2・5）を対象とし、各出力の全成分を独立の有理数モーメント・Christoffel微分から再計算した。
構築とJSON出力を含む5 ABBA blockの一般/構造経路の中央値比は、スカラーで1.717・3.152、曲率作用で2.997、全成分展開で0.568だった。
最初の3ケースは5/5 blockで改善し、全成分展開は5/5で遅くなった。
この結果を受け、展開時は `K_k` の行と列を一度取り出し、内積を逐次走査する行列積としてまとめた。
平坦なテンソルの連結リストを、各成分の縮約の内側から何度も索引する処理を除く。
