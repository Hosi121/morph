# 小さな実験

[ハンドブック](../../HANDBOOK.md) / [ドキュメント](../README.md)

1. binaryで数として等しい `[true]` と `[true,false]` を、生ワードとして連結してみる。
   数の正規化で失う桁幅が、ペアの区切りには必要だと分かる。
2. fftの入力へ一つずつ矢印を足し、独立DFTとの係数比較を保ったまま位相を変える。
   リストの構造上の一致と、同じ複素数を表すことの違いを追う。
3. `zeroone` の `2x<=1` に `-2x<=-1` を加え、`2x=1` に変える。
   有理解が存在することと、Bool割当てが存在することの違いを証拠木で確認する。
4. reedsolomonで消失と誤りを増やす。
   `2*誤り+消失<=n-k` の保証の内外で、拒否だけでなく別の近い符号語があり得ることを追う。
5. sturmで重根や近接根を与え、燃料を一歩ずつ足す。
   浮動小数点の誤差ではなく、正確な根数で区間が分かれていく様子を確認する。

変更したパッケージのテストから始め、共有核を変更したときは `tools/check` を実行する。
nativeは `tools/moon test --target native` で検証する。
環境の版、アーカイブのhash、fixture再生成は[検証環境](../ENVIRONMENT.md)にまとめた。

MoonBitでは、例えば `let xs : @core.Chain[Bool] = Cons(true,Nil)` のように
期待する型を明示すると、外部パッケージのコンストラクターも文脈から解決できる。
型がまだ分からない `let xs = Nil` は解決できない場合がある。
タプルは分解パターンを使い、関数を持つrecordの呼び出しは `(field.multiply)(a,b)` とする。
公開APIの記録は `tools/moon info` で再生成し、pkg.generated.mbtiを手編集しない。
