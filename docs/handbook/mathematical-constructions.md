# 数学的構成から演算を作る

`quotient` は、係数体の演算と monic な正次数多項式 f から、商環 K[X]/(f) の演算を作る試作です。
QQ、Fp、F₂のために商の加算・正規化・一般積・単元判定をそれぞれ書く代わりに、この構成規則を一度記述します。
既存の数体・有限体・複素拡大を置換する段階にはありません。
[構造の監査](../research/mathematical-constructions-20261118.md)と[試作の評価](../research/quotient-prototype-20261118.md)に、共有できる部分と費用を残しています。

## 何を渡し、何が得られるか

| 構成への入力 | 構成から得る演算・不変条件 |
| --- | --- |
| `rowreduce.Field[A]` と係数の正確な零判定・有効性判定 | 係数の加減乗と零の意味。体の法則は辞書の契約 |
| monic な正次数 f | 一意な次数 < deg(f) の代表元、逆数を使わない先頭項相殺 |
| 係数体・追加の埋め込みを識別するキー | 親の異なる元を混ぜない境界 |
| 上記を含む `Context[A,K]` | `normalize/add/subtract/negate/multiply/unit_inverse` |
| 既存の checked `numberfield.Field` / `galois.Field` | 非零元が単元であるという保証を使う体のアダプタ |

コードの型変数 `K` は識別キーの型です。数式の係数体 K そのものを表す型ではありません。
係数値は `A`、係数体の演算は辞書に保持します。
キーの等しい辞書は、同じ体・同じ係数表現・同じ零判定を意味する、という呼出側の契約があります。
有効な係数は零・単位元を含み、係数演算と非零元の逆元に閉じている必要があります。
一般のユーザー定義辞書の体公理を自動証明する仕組みではありません。

`Context` と `Residue` は opaque です。代表元は昇冪の不変 `Chain[A]`、零は `Nil` です。
入力を検査・還元してから格納し、和・差で保たれる次数制限を使って余分な還元を避けます。
構築時に多項式の全乗算表や逆行列を作ることはありません。
一般積は必要になったときに畳み込みと法還元を行います。商の多項式は生成しません。
この試作は代表元自体を遅延する式グラフではなく、法と計算経路を保持するものです。

## 環と体を分ける

f が可約でも商環は作れます。例えば QQ[ε]/(ε²) では ε は非零ですが逆元を持ちません。一方、1+ε の逆元は1−εです。
`unit_inverse` はこの区別を扱い、零と非零の非単元の両方に `Ok(None)` を返します。

逆元の試作では、掛け算作用の冪基底行列を作り、既存の `rowreduce` で ab=1 を解きます。
有限次元の可換体上代数では、解があれば作用素は全射、従って単射なので逆元は一意です。候補の積も確認します。
これは多項式Euclidの複製を避けた横の接続ですが、**逆元要求時には d×d の行列を作ります**。
高次数向けに速い逆元を得たという主張はありません。

`quotientfield` のアダプタは、既存 checker を通って構築された opaque な Field だけを受け取ります。
未検査の `irreducible: Bool` を受け取る入口はありません。
checked な拡大で非零元の逆元が得られなければ、単元でないという結果ではなく不変条件違反として返します。
既存 API の証明書の形・error・零逆元の扱いは変更していません。アダプタの結果は別のAPIです。

## 数体の選択実根を失わない

`real_extension(source)` は元の `numberfield.Field` を保持し、選択根の証明書を商のキーにも含めます。
同じ最小多項式の別の実根、あるいは現在のAPIで別と扱われる根区間は、零であっても混ぜられません。
`real_source` から元の Field と実現・区間精密化の経路へ戻れます。

`enter_real/leave_real` は疎な既存多項式と密な係数列の境界です。商の内部で繰り返す加算・乗算には、この往復を挟みません。
その境界の変換と既約性検査の費用を、内部乗算だけの速度比から推定しないでください。
既存の逆元証明書・独立 checker は変更していません。

## 数学的構造・表現・カーネルを分ける

| 層 | F₂の商の例 |
| --- | --- |
| 数学的構造 | F₂[X]/(f)、monic f、可約なら環 |
| 係数表現 | `Bool`、多項式は `Chain[Bool]` |
| 計算経路 | `Generic` の畳み込み＋還元、`Carryless` のXOR＋shift-and-reduce |

`gf2_context(key, modulus, policy)` は係数の型を Bool に固定する小さな factory です。
一般型の動的な認識やキャストはありません。`gf2.field()` の既存辞書を再利用します。
F₂以外にも標数2の体はありますが、その係数を Bool と見なすことはできません。
例えばGF(4)の全ての係数で a²=a が成り立つわけではありません。
機械語のビットパッキングを導入した実装でもありません。

実行方針は親の数学的同一性に含めません。同じ法・キーの一般経路と専用経路の元を混ぜることができ、左オペランドの経路で計算します。
`bit_extension` は既存 galois の素体が F₂ であることを確かめ、変換を入口・出口に置きます。
既存 galois の専用積も比較基準に残します。新しい経路の方が速いとは限りません。

FieldからSemiringを得る例は `quotientfield.semiring` です。
zero/one/add/multiply を取り出すだけで、新しい算術を実装しません。BoolのOR半環をF₂のXOR体から選ぶこともありません。

## 次の構成へ広げる前の判断

直和・外冪・双対にも、構成から得られる規則があります。正定値形式の直和やHodgeのせん断列は、既存実装でも構造を保持しています。
一方、ADTのsumは数学的な直和ではなく、有理線形空間の商は整数商群のtorsionを保存しません。
同じrecordやlistに見えることだけでは共通化しません。

今回確かめるのは、少数の構成規則で複数の商環を構築でき、専用カーネルと同じ意味を保てることです。
既存の重複コードの削除量、アダプタ込みの総量、実際の時間・メモリは別に評価し、悪化した部分も採否に反映します。
