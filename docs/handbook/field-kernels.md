# 体の共通算法と専用カーネル

[ハンドブック](../../HANDBOOK.md) / [線形代数](linear-optimization.md)

同じ消去法を複数の体で共有しながら、表現から分かる性質を使って不要な演算を省きます。
共通化の単位は型と演算の辞書です。値の表現、正規形、零判定の条件まで同じとは限りません。

## 型と演算を分ける

`matrix.Matrix[A]` は係数の型をパラメータに持ちます。行列積は `algebra.Semiring[A]`、
消去法は `rowreduce.Field[A]` を受け取ります。辞書には零・単位元・加減乗算・逆元などの関数が入り、
同じ算法に有理数や有限体の意味を与えます。型ごとの継承階層を作る必要はありません。

| 係数・表現 | 共通化するもの | 専用化するもの |
| --- | --- | --- |
| 一般の体 `A` | `rowreduce` の型・解空間・消去手順 | 係数の演算は渡された辞書に従う |
| 正規化済み有理数 | 同じ消去手順と `Reduction` / `Solution` | 分子の零判定で、変化しない行を共有する |
| GF(2) の `Bool` | 行列・消去結果・証拠の形 | 正規化不要、加減算はXOR、非零の逆元は真 |
| GF(p) の `Binary` | 検査済み素数と体の辞書 | p=2では任意長・未還元の入力を下位bitで評価する |

辞書の型は体の法則そのものを証明しません。例えば逆元関数が零でだけ `None` を返すことは、
辞書を作る側の条件です。一般の `rref` と `solve` はその境界を保ちます。

## 有理数の零判定

`rowreduce.rref_with_zero`・`solve_with_zero`・`inverse_with_zero` は、正確な零判定を追加で受け取ります。
係数と演算結果が正規形であり、零の行をそのまま返しても意味と表現が保たれることが条件です。
`linear` は正規化済み有理数にこの経路を使います。

消去係数が零なら、行全体に零を掛けて差を作る代わりに、既存の不変リストを返します。
密な非零行列では省ける仕事が少なく、同じ倍率を期待できません。
未還元の有限体入力では「整数として零」と「体として零」が異なるため、汎用の経路を残します。

## GF(2) の分解を再利用する

`gf2.rref` は結果だけを計算します。`gf2.factor` は入力AとRREF、行変換U、逆順の行操作記録を保持します。
`solve_factor`・`nullspace_factor` はその分解を利用し、同じAを消去し直しません。
`inverse_transform` は、GF(2)で自己逆な行交換・行加算を逆順に再生してUの逆を構成します。

一度だけ解く `gf2.solve` はAと右辺だけを消去します。再利用の予定がないときに
完全な変換行列を作ると、小さい問題ではその費用が増えるためです。
ピボットだけ必要な箇所も `rref` を選び、証明を使わない箇所で証明を生成しません。

CSS符号は分解からrank証拠を作ります。コホモロジーは同じδの分解からrankと零空間を取り出します。
CSS・コホモロジーの直接の証拠検査は汎用行列積で `R = UA`、変換の両側逆、ピボットや商基底の条件を検査します。
GF(2)自身の検査で共有する`gf2.multiply`は専用Bool積へ進めたため、旧汎用積・独立Bool参照との照合も行います。
生成方法を変えても、検査を省いた速度比較にはしません。
変換行列Uには一意性を要求していないため、旧生成器と証拠の成分が異なる場合があります。
RREFとピボットの順序は、汎用の消去法と比較しています。

係数は引き続きBoolの不変リストです。機械語へのbit packingやSIMDを実装したものではありません。
`gf2.multiply`はBool専用の積を使い、コホモロジーのincoming coordinatesの生成にも接続しています。
shapeの検査は維持し、上位全体への効果は直接の積の改善と分けて評価します。

## すでに型が保証している範囲を使う

`fppoly.Polynomial` は、法と正規化済み係数を一緒に保持するopaqueな型です。
公開constructorを通った係数a,bはp未満なので、和は2p未満です。
`binary.subtract(a+b,p)` がSomeなら差、Noneなら和を返せば、一回の補正で正規形になります。
零の符号反転は零、それ以外はp-aです。

この保証を内部の係数演算で再利用すると、各係数に対する汎用の剰余計算を省けます。
新しい型を足す前に、すでにあるADTの生成箇所と不変条件を調べるのも有効です。
[今回のFp比較](../research/canonical-fp-20261117.md)では、符号反転・減算・多項式除算に改善がありました。
加算の小差、GF(2)対照の揺れ、有限な検査の範囲も同記録に残しています。

## 正規形と増分状態を再利用する

前回挙げた五つの候補を実装・計測し、四つを採用しました。
[統合比較と採否](../research/algorithm-kernels-20261117.md)に入力、条件、生値、対照の限界を残しています。

| 対象 | 採用した処理・判断 |
| --- | --- |
| 数体の加減算 | 体の一致を検査し、次数d未満を保つ和・差では再簡約を省く。乗算は簡約を維持 |
| 数体・複素数体の座標 | 整列済みの項を一度進め、零を補う。乗算行列も同じ抽出を共有 |
| 最小多項式・FGLM | `linearspan.State`に独立な列の残差と元列への係数を保持し、新しい列だけを還元 |
| Smithの列操作 | 各行の対象位置を直接更新し、全転置の構築を省く。U/D/Vと燃料の遷移を維持 |
| 持続性のpivot索引 | 常時構築・最初の衝突時構築とも安定した改善がなく、本体を元に戻した |

`linearspan.insert`は、従属なら元の独立列への係数、独立なら新しい状態を返します。
状態を変更しないため、既存状態から分岐できます。FGLMは停止・再開時にも同じcacheを引き継ぎます。
列が増えるたびに全連立系を解く費用を省きますが、保持した有理数の大きさや検査の費用は残ります。
生成側と検査側に共有の演算もあるため、旧経路との照合と別の参照値を併用します。

今回のnative入力では、座標2.535〜4.368倍、最小多項式1.258〜1.607倍、FGLM1.166/1.379倍でした。
未変更の数体乗算の対照は約3.5%遅い結果も出ています。全経路の一律な改善とは扱いません。
JS/WasmGCは動作検証の対象で、速度は今回測っていません。

固定した体の高い冪の剰余は、その後[準備済みの法](../research/night-nf-20261117.md)として実装しました。
反復乗算と一度だけ使う場合を分け、準備時間も含めて比較しています。
汎用 `matrix.multiply` はすでに列を一度構築して共有し、`transpose` も先頭・末尾を順に分離します。

## 使わない中間結果を作らない

正規形だけが必要な`polynomial.normal_form`では、商の列を保持せずに余りを計算します。
公開`divide`は残し、同じdivisor順序とエラーの優先順位を旧経路・独立Fractionモデルと比較します。
数体では同じ法を繰り返し使うため、検証後に法を準備し、乗算の余り専用経路へ渡します。
準備の費用があるので、一回だけの利用まで一律に速くなるとはしません。

Fpの`scale`と`evaluate`は、任意の入力を最初に還元し、その後は正規係数の演算を共有します。
空・定数の評価では、点を調べる必要もありません。QQの積はsortedな部分積を平衡mergeし、
奇標数Fpの畳み込みでは零の行を省き、単位の行を共有します。いずれもopaqueな値の不変条件を利用しています。

GF(2)の零空間は、整列したpivotと列を一度ずつ進めます。
一方、既知の零の接頭部を省く新しいrow cursor ADTは、密・幅広の行列では改善しても小・疎行列が遅くなり、不採用でした。
表現や走査回数だけで判断せず、構築・共有・参照カウント・検査を含む通常経路の費用を比較します。

[8件の採用とcursorの見送り](../research/night-kernels-20261117.md)に、最終実装・全生値・負の結果・検証と片付けをまとめています。

## 表現が分かっている積と余りを選ぶ

標数2の多項式を自分自身と掛けるときは、係数の間へ零を挿入すれば平方になります。
`fppoly.power_mod`の既知の平方へ接続し、一般の積・奇標数・指数の手順は維持しました。
さらに、powerが余りだけを必要とする還元では、公開`divide`を変えずに商を生成しない内部経路を使います。
零・定数の除数や体の不一致で、検査とエラーの優先順位を変えないことも条件です。

QQ多項式では、単一の定数項が正規な±1かを既存ADTから判定します。
+1の積は他方のimmutableな多項式をそのまま返し、-1は既存のnegateを使います。
係数が1でも変数の指数が非零の単項式には適用しません。次元違いの検査も先に維持します。

減算を一走査に融合する案と、GF(2)の零空間の係数を列へ準備する案は、一般入力の利点を確認できず見送りました。
変換や中間値を減らす仮説でも、準備・走査・検査を含めた実測が採用条件です。
[26時枠の採否と全記録](../research/late-kernels-20261117.md)に、4件の採用と2件の見送りをまとめています。

## 恒等元でも条件の範囲を分ける

同じ係数1でも、積の恒等元とmonicの恒等条件は異なります。

| 操作 | そのまま返せる条件 |
| --- | --- |
| 多項式の積 | 一方が定数多項式の+1。変数の指数も全て零 |
| monicへの正規化 | 先頭係数が+1。変数の指数や項数には条件を加えない |

opaqueなQQが既約な分子・正の分母を持つことを使い、符号と二つの1bit形を確認します。
大きな整数全体の比較や、Rationalのfactoryの再構築は要りません。
+1以外のmonicは従来の逆数・係数mapを維持し、零は最初に返します。
checkerもこの算術を共有するため、旧monicと独立Fraction期待値を併用します。

Smith座標では、同じformから作る商群contextを最初の非空列で一度準備し、列間で共有します。
各列の基底変換・剰余・None判定は残し、空列には準備を加えません。
[統合後の比較](../research/conversion-kernels-20261117.md)では、直接のhelperと写像全体、小入力と対照を分けて掲載しています。
