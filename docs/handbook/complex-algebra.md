# 複素代数的数と全複素根

[ハンドブック](../../HANDBOOK.md) / [厳密代数の計算経路](algebraic-solving.md)

実代数的数を実部・虚部に使い、複素数の演算と、有理係数一変数多項式の全複素根を扱う。
浮動小数点の近似値へ変換せず、選択根と証拠を次の演算へ渡す。
`tools/moon run src/cmd/complex` で[計算例](../COMPLEX_TOUR.txt)を実行できる。

| したいこと | 入口 | 結果 |
| --- | --- | --- |
| 複素代数的数を作る | `complexalgebraic.number(real, imaginary)` | 二つの厳密な実代数的数を持つ `Number` |
| 四則演算・共役を求める | `add` / `subtract` / `multiply` / `divide` / `conjugate` | 結果と演算証拠、または再開状態 |
| 数として等しいか調べる | `complexalgebraic.equal` | 厳密な等号判定と証拠、または再開状態 |
| 有理多項式を分解して全複素根を列挙する | `complexfactor.prepare` → `start` → `run` | 因数分解と各因子の被覆に束縛した `RootFamily` |
| 因数分解せず直接列挙する | `complexroots.prepare` → `start` → `run` | 全根と重複度、被覆証拠、または再開状態 |
| 根を複素数の演算へ渡す | `complexroots.materialize` | `complexalgebraic.Number` と座標取り出しの証拠 |

正確な公開型は [complexalgebraic](../../src/complexalgebraic/pkg.generated.mbti) と
[complexroots](../../src/complexroots/pkg.generated.mbti)、[complexfactor](../../src/complexfactor/pkg.generated.mbti) を参照。

## 二つの実代数的数で複素数を表す

`Number` は `a+i*b` を表す。各座標は定義多項式と一根区間を持つ `realalgebraic.Number` である。
実部・虚部は `real_part` と `imaginary_part` で取り出す。
違う定義多項式や区間でも同じ数を表し得るため、表現の一致と数としての等号を区別する。
等号は両座標について共通因子と選択根を調べ、区間が重なるだけでは等しいとしない。

演算は実数の演算へ分解する。除算では `c²+d²` を一度作り、
`(a+i*b)/(c+i*d)` の実部 `(a*c+b*d)/(c²+d²)` と虚部 `(b*c-a*d)/(c²+d²)` で共有する。
零除算はエラーとし、未完了の計算と区別する。
一次の定義多項式から有理数を取り出せる場合は、有理数の厳密演算を使う。
一般の代数的座標では既存の実数の演算証拠を使い、中間値と固定した演算手順を検査する。

`check_arithmetic_for` と `check_equality_for` は、呼び出し元が指定した入力・演算・返却値も検査する。
証拠だけを受け取る検査器は、その証拠に埋め込まれた問題に対する検査である。
燃料切れは再開状態を返し、等しくないという判定や零除算へ置き換えない。

## 複素根の列挙を実解の被覆へ帰着する

有理係数の非零多項式 `p(z)` に対し、次の恒等式を有理係数の二変数多項式として作る。

\[
p(x+iy)=R(x,y)+iI(x,y).
\]

実数の組 `(x,y)` が `R=I=0` を満たすことと、`x+i*y` が複素根であることは同値である。
`complexroots` はまず `g=p/gcd(p,p')` をモニックにし、重根を除いた方程式を
[realvariety](../../src/realvariety) の分離線形形式・Gröbner基底・実根隔離へ渡す。
一つの共通パラメータαと座標多項式 `x=h_x(α), y=h_y(α)` を使い、座標間の依存関係を保つ。
返す根の順序はパラメータ順であり、複素数の大小順ではない。

探索は0から整数の分離線形形式を試す。`start_from` で開始値を指定することもできる。
どの整数が良いかは入力に依存し、特定の開始値が常に分離を保証するわけではない。

被覆証拠は、指定された元の多項式、平方因子を除いた式、その実部・虚部、
F4の元idealへの証拠、全実根の一根区間へ結び付ける。
異なる根の個数が `degree(g)` と一致することも検査する。
非零定数は空集合、零多項式は無限個の根を持つため有限列挙の入力エラーとする。

### 重複度を戻す

各根で元の `p` の微分を順に調べ、初めて非零になる微分の階数を重複度とする。
微分の実部・虚部を同じ座標多項式へ代入し、パラメータの定義多項式で剰余を取る。
その値の零判定にはSturm–Tarskiの証拠を使う。
各階の二成分の符号と、重複度の合計が元の次数と一致することを検査する。

たとえば `(z²+1)²(z-1)` では `1` の重複度が1、`i` と `-i` がそれぞれ2になる。
重根のために同じ点を複数回探索する必要はない。

### 根を演算へつなぐ

列挙結果の `Root` は共有パラメータ表現を保つ。`materialize` は各座標の乗算行列から
定義多項式を作り、一根区間を選択して複素数へ取り出す。
座標番号、元の点・問題、実際に返した二座標を `check_materialization` で検査する。
探索途中、座標の取り出し途中とも、燃料を追加して再開できる。

## 有理数上で分解してから列挙する

`complexfactor` は既存のBerlekamp–Hensel–Zassenhaus分解を前段に置く。
`p=u*Π f_j^m_j` の分解証拠を検査し、各因子の全複素根を `complexroots` で列挙する。
異なる因子の根を混ぜた消去問題を作らずに済み、重根も因子の重複度から戻せる。
元の式が可約なときの中間次数を抑える経路であり、既約な高次数の費用は残る。
平方因子を除いた次数nの組n²が、因子ごとの次数d_jに対するΣd_j²へ分かれる。

`prepare` は候補素数と分解・検証の予算を受け取る。
`Prepared` の場合に探索を開始し、分解未完了や検証の `Undecided` は空集合へ置き換えない。
探索の再開では完了した因子の根集合と現在の探索を保つ。燃料・試行回数は、一回の呼出しで
現在扱う因子に対する予算であり、全因子の総実時間上限ではない。

`check_result` の `Proven` は、元入力への分解、正の重複度、因子同士の互いに素なこと、
因子ごとの元入力に束縛した全根被覆、実際に返した根と重複度、元の次数との一致を確かめる。
`Refuted` と `Undecided` も区別して返す。
`root` で内部の根を取り出して `materialize` へ渡せるが、そこでの証拠は当該因子に対するものになる。
元の多項式への所属と重複度は、外側の `RootFamily` の証拠と併せて使う。

## 範囲と費用

入力は有理係数の一変数多項式であり、複素代数的係数の多項式を直接列挙するAPIではない。
基底を固定した反復演算には、[K(i) と一生成元の表現](complex-fields.md)を使える。
一般の複素数体の自動合成、分解体の自動構成、QQ上のGalois群計算は別の課題として残る。

実部・虚部の方程式を複素数上で見ると、次数nから最大n²個の点を持つ消去問題が現れる。
実数の組だけが最終的な複素根になるが、中間の基底やパラメータ多項式は大きくなり得る。
この実装は既存部品を接続する厳密な経路であり、高次数の実用速度を保証しない。
燃料は外側の仕事の回数を制限し、一つの有理演算・基底簡約・証拠検査の実時間を固定しない。

独立した有限例の方程式・根・重複度・有理区間は
[Fraction・SymPyの参照記録](../research/complex-oracle-20261117.md)に残す。
[接続の判断と同条件比較](../research/complex-algebra-20261117.md)には、遅い直接経路と未採用の案も残す。
一般の正しさの形式証明と、有限例・証拠検査による確認は区別する。
