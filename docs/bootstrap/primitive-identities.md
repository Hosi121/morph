# 共有Binaryの恒等則と比較の入口

基点は公開snapshot `2eb67ba`。binaryの既存表現/API/厳密値を保ち、
0/1/2の積、1/2による商、同じ値の商とGCDを一般の算法へ入る前に処理する。
0除算は従来どおりNone。返せるリストは共有し、1を掛けるためだけに全桁を作り直さない。
GCDは再帰途中で除数が1になった場合にも終了する。

同値を確かめるために毎回全wordを比較すると通常の短い除算が遅くなった。
そこで低位四bitの一致を入口のfilterにし、異なれば元の長除算へ直接進む。
filterは答えを推測せず、正確な比較による早期終了を試すかどうかだけを選ぶ。
元の算法へのfallbackがあり、精度や表現は変更しない。

native release、CPU4固定、入力構築除外、各10標本、同じsource fixture：

| 2048bitの例 | 旧版 | 採用候補 |
| --- | ---: | ---: |
| n*0 | 26.41 µs | 9.63 ns |
| n*1 | 58.42 µs | 7.06 ns |
| n*2 | 67.21 µs | 15.06 ns |
| n/1 | 81.41 µs | 14.56 ns |
| n/n | 6.16 ms | 5.19 µs |
| gcd(n,1) | 80.56 µs | 15.59 ns |
| gcd(n,n) | 6.34 ms | 5.29 µs |

ns級は恒等則で共有する構造操作で、通常の大整数演算がnsになるという意味ではない。
全桁比較自体の計算量は変更していない。

| 同じ上位処理、final checker込み | 旧版 | 採用候補 |
| --- | ---: | ---: |
| LLL 3×3 | 371.11±12.31 µs | 264.29±10.66 µs |
| LLL 3×4 | 445.05±25.52 µs | 283.42±5.92 µs |
| Smith→LLLの依存3×4 | 332.51±14.78 µs | 236.45±5.18 µs |

この比較には後続のexact専用最適化を混ぜていない。
通常の128/64bit除算は55.29→54.81µsで大きな差はなく、
短い64除算のgroupは66.29→70.63µsと悪化も残った。
全入力の高速化とは主張せず、恒等則の無駄な走査と上位LLLの改善で採用する。

初期の無条件比較案は通常入力を遅くし、一部sampleには大きな分散もあったため採用しなかった。
そのログも`*-unconditional.txt`に保持する。
後半はCPUを分けているが、VM/ホスト全体の負荷や周波数を固定してはいない。

0〜4095と各0/1/2/3の積・商の境界、GCD恒等則、別々に作った4096bitの同値wordを検査した。
既存の全小算術・Python fixture・RLE/有限体/素数証明などの上位検査も維持する。
Boolリストの核にmachine数値、配列、可変状態、FFIは追加していない。

生ログ：`docs/measurements/primitive-{identities,distribution,lll}-{before,after}.txt`。
再現は`primitive_test.mbt`/`division_distribution_test.mbt`とLLLのbenchをCPU4に固定して実行する。
