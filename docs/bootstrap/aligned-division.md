# 除算の桁幅差を制限する試作

この文書は初回試作の段階を記録する。現在の通常経路への採用と広げた検証は
[adaptive-division](adaptive-division.md)にまとめた。

`binary/division_trial_wbtest.mbt`は通常経路へまだ採用していない比較用実装である。
通常のLSB列の除算は上位の小さなprefixにも全体幅の除数との比較を繰り返す。
二つの幅が近い場合は、除数を幅差だけ左shiftしてから降順に減算する方法を試した。
幅差の上限0/1/3/5/8を比較し、大きい差では既存経路へ戻す。

0〜127と1〜127の全対で、五種類の上限ごとに商・余りとGCDを
組み込み整数oracleへ照合した。大きな入力を含む一般の正しさの証明はまだない。
128bitの近い幅の除算は53.56 µsから14.34〜14.57 µs、同じbenchmarkの
GCDは345.20 µsから235.31〜274.08 µsになった。
幅が大きく違う商では範囲が重なり、短い入力や上位算法への影響も未確定である。
単一比較だけで全面置換せず、独立の多倍長fixtureと対照を追加して採否を判断する。

次の候補は、GCDや剰余演算で使わない商を構築しないkernelである。
