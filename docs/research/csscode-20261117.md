# CSS stabilizer algebra from exact binary chain complexes

This milestone connects the existing immutable matrix, finite-field row
reduction, and simplicial boundary packages. The question is whether the same
pure ADT representation can check CSS stabilizer codes and recover small exact
logical distances, including a binary class caused by integral two-torsion.
`src/csscode` implements that algebra and an explicitly bounded resumable search.
It describes stabilizers and binary errors; it does not simulate quantum states,
amplitudes, measurements, or fault-tolerant circuits.

## Binary conventions and API

Inputs `Hx` and `Hz` are checked `matrix.Matrix[Bool]` values of the same width
`n`, with rows describing X and Z stabilizer generators respectively. A `true`
entry selects that physical coordinate. Empty matrices retain their width, and
zero or duplicate rows are permitted. `validate(Hx,Hz)` returns an opaque `Code`
exactly when their widths agree and `Hx * transpose(Hz)` is zero over GF(2).

The package supplies `field()` for `rowreduce` and `scalars()` for matrix
products. Their addition is **XOR**, multiplication is AND, additive negation is
the identity, and only `true` has a multiplicative inverse. The existing
`algebra.booleans()` uses OR/AND for reachability and cannot be substituted here:
the dot product of `(true,true)` with itself is zero over GF(2) and true over
that Boolean semiring. A regression explicitly distinguishes those outcomes.

`parameters(code)` returns `physical`, `rank_x`, `rank_z`, and `logical`, with

\[
k=n-\operatorname{rank}(H_X)-\operatorname{rank}(H_Z).
\]

This follows because the independent pure X and Z generators contribute the
sum of those ranks. The supplied matrices commute, so their rowspaces are
orthogonal and the sum cannot exceed `n`. These conventions are the binary CSS
specialization of the stabilizer formalism in
[Gottesman, *Stabilizer Codes and Quantum Error Correction*, §§3.2–3.4, 8.6](https://arxiv.org/pdf/quant-ph/9705052),
and the classical dual-containing construction described by
[Steane, *Simple Quantum Error Correcting Codes*](https://arxiv.org/abs/quant-ph/9605021).

For `axis=X`, `syndrome(code,axis,error)` returns `Hz * error`; for `axis=Z` it
returns `Hx * error`. `in_stabilizer` tests membership in the rowspace of the
same-axis stabilizers. `is_logical` implements

\[
X:\;\ker(H_Z)\setminus\operatorname{row}(H_X),\qquad
Z:\;\ker(H_X)\setminus\operatorname{row}(H_Z).
\]

All three operations return `None` on a vector of the wrong physical width.
The zero vector is a stabilizer and is never a nontrivial logical operator.
Each valid vector operation is exact; no numerical tolerance is involved.

## Algebraic parameter certificates

`certificate(code)` exposes a source-bound `Certificate` with its actual
`Parameters` and a `RankWitness` for each input matrix. To produce a rank
witness the existing generic `rowreduce.rref` reduces `(A | I)` over the binary
field. Splitting the result gives `R` and an invertible row transform `U`;
`rowreduce.inverse` produces `U^-1`. This reuses the existing elimination engine.

`check_rank(A,witness)` checks matrix shapes, actual source equality,

\[
R=UA,\qquad UU^{-1}=I,\qquad U^{-1}U=I,
\]

and the RREF shape of `R`: increasing first nonzero columns, zero rows at the
bottom, and each pivot column a unit vector in the appropriate row. Those
pivot columns must equal the supplied pivot list. Thus the number of pivots is
the rank and the rowspace is preserved. The checker performs matrix arithmetic
and structural recursion, without calling row reduction or inverse search.

`check_parameters(code,actual,witness)` binds both rank sources, the actual code,
and the returned parameters; rechecks commutation; verifies both rank witnesses;
and checks the exact rank-sum identity. Public witness fields allow independently
produced certificates and tampering tests. A code or certificate accessor is not
an untrusted-witness checker.

## Exact distance, fuel, and minimum verification

`start_distance(code,axis)` creates an immutable `DistanceState`.
`run_distance(state,fuel)` enumerates vectors in increasing Hamming weight,
starting at weight one. An immutable depth-first combination frontier generates
only vectors in the current layer. It does not allocate an entire layer of
subsets or enumerate duplicate candidates.

The result is one of:

- `Paused(state)`: all supplied candidate fuel has been used; the retained state
  can be passed directly to `run_distance` with more fuel.
- `Found(witness)`: an exact minimum for this axis, with original-coordinate
  logical vector, distance, actual source code, and axis.
- `NoLogical`: the set of nontrivial logical operators is empty. In particular,
  `k=0` returns this with zero fuel. Its distance is absent, never zero.

One unit of fuel tests one completed candidate vector for logical membership.
Generating the next combination, rank construction, syndrome/rowspace work per
candidate, and checking are not separately metered. `progress(state)` reports
the number of candidates already tested and the active weight. No wall-clock,
memory, or primitive-operation bound is claimed. Worst-case enumeration is
exponential, so callers should use small repeated candidate batches. `Paused`
is not a mathematical distance result or a checked lower-bound certificate.

A short logical vector proves nontriviality and gives an upper bound; it does
not certify minimality. `check_distance(code,axis,witness,fuel)` first checks the
source, axis, vector width, nontriviality, nonzero claimed distance, and exact
vector weight. It then **replays every vector of strictly smaller weight**.
The check returns `Verified`, `Rejected`, or `CheckPaused(state)`; the last is
resumed with `resume_check`. Distance one needs no exclusion candidates. A valid
but heavier logical vector is rejected when replay finds a smaller one. Minimum
verification is exponential and deliberately not presented as search-free.

For `k>0`, the ordinary CSS Pauli distance is `min(dX,dZ)`. Indeed a commuting
mixed Pauli has an X component in `ker(Hz)` and a Z component in `ker(Hx)`.
If both components are same-axis stabilizers, their product is a stabilizer;
otherwise at least one is a pure nontrivial logical whose support is contained
in the mixed operator's support. Pure operators themselves are allowed, giving
equality. This is a specialization of the normalizer-minus-stabilizer distance
criterion in Gottesman's thesis, §3.2. The API exposes the two exact distances
individually and does not conflate them with an exhausted search.

## Simplicial adapter and what it shows

`from_complex(K,degree)` uses the existing oriented integer boundary maps,
reduces each integer by parity of its magnitude, and constructs

\[
H_X=d_{\mathrm{degree}}\bmod2,\qquad
H_Z=(d_{\mathrm{degree}+1}\bmod2)^T.
\]

The exact boundary identity supplies commutation, which `validate` rechecks.
Physical coordinates are the lexicographic simplices of the requested degree.
This retains unreduced degree-zero and all empty matrix-shape conventions of
`homology`. In edge degree, vertices are X checks and faces are Z checks. This
is the surface-code pattern described in
[Kitaev, *Fault-tolerant quantum computation by anyons*, §1](https://arxiv.org/pdf/quant-ph/9707021).
The present adapter accepts finite abstract simplicial complexes rather than a
general cell complex or periodic square lattice.

| Example | n | rank X | rank Z | k | dX | dZ |
| --- | --- | --- | --- | --- | --- | --- |
| Steane checks | 7 | 3 | 3 | 1 | 3 | 3 |
| Triangle boundary, edge degree | 3 | 2 | 0 | 1 | 1 | 3 |
| Tetrahedral sphere, edge degree | 6 | 3 | 3 | 0 | absent | absent |
| Six-vertex real projective plane, edge degree | 15 | 5 | 9 | 1 | 5 | 3 |
| Seven-vertex torus, edge degree | 21 | 6 | 13 | 2 | 6 | 3 |

Steane uses the three Hamming check rows with least-significant-coordinate
integer masks `85`, `102`, `120` for both check matrices. Masks occur only in
the test/oracle representation. Both surface facet lists are frozen from the
[official Sage simplicial complex examples](https://github.com/sagemath/sage/blob/develop/src/sage/topology/simplicial_complex_examples.py)
already used by `homology` (`RealProjectivePlane` and `Torus`).

The projective plane's integral `H1=Z/2` has free rank zero, whereas its binary
first homology has dimension one. The adapter therefore produces one logical
qubit from this triangulation. Binary reduction retains this mod-two class but
cannot by itself recover the integral torsion order. Distances depend on the
specific triangulation, rather than only the underlying topological space.

## Independent evidence and reproduction

`tools/generate_csscode_fixtures.py` imports no production algorithm or numerical
library. It represents rows as machine integer masks, explicitly enumerates all
row combinations to obtain rowspaces, tests every physical vector by parity,
and minimizes Hamming weight over the resulting nontrivial-logical sets. This
is independent of the production row-reduction and combination-search paths.

The small cohort contains every ordered pair of subspaces of GF(2)^n for
`0 <= n <= 3`: 82 commuting pairs are accepted and 204 noncommuting pairs are
rejected. All 583 physical vectors across the valid pairs have syndrome,
rowspace, and logical membership checked against the independent oracle; both
distances and all parameters are compared. Duplicating, reversing, and adding
zero check rows preserves the results. The surface oracle enumerates all
`2^15` and `2^21` vectors to determine the distances in the table; tests compare
the entire adapter matrices before checking those results and their minimum
witnesses.

Other tests distinguish GF(2) from OR/AND, reject invalid widths and
noncommutation, cover empty codes and unreduced degree zero, exercise one-candidate
resumption against uninterrupted search, and reject modified sources, axes,
rank transforms/inverses, RREF pivots, returned parameters, vector weights,
stabilizers, and nonminimal logical witnesses.

Validation on 2026-11-17: all nine CSS test blocks pass on native, JavaScript,
and wasm-gc, and the scoped warning-free compiler check passes. The repository
source-purity gate passes with 304 kernel files in this worktree. These counts
describe this finite regression cohort and are not a completeness theorem.

```sh
tools/measure --cpu 4 python3 tools/generate_csscode_fixtures.py --check
tools/measure --cpu 4 tools/moon test src/csscode --target native -j 1 --deny-warn
tools/measure --cpu 4 tools/moon test src/csscode --target js -j 1 --deny-warn
tools/measure --cpu 4 tools/moon test src/csscode --target wasm-gc -j 1 --deny-warn
tools/measure --cpu 4 tools/moon check -p src/csscode -j 1 --deny-warn
tools/measure --cpu 4 tools/moon info src/csscode
tools/measure --cpu 4 tools/moon fmt src/csscode --check
python3 tools/audit_purity.py
```

All production code uses immutable `Chain`, `Nat`, `Bool`, existing exact
integer parity, and recursion; machine integers, arrays, mutation, and masks are
confined to tests and the independent oracle. This milestone makes no scaling
or speedup claim. It provides no decoder, logical quotient basis or canonical
paired logical operators, mixed stabilizer tableau, encoding circuit, noisy
quantum channel, hardware backend, or proof of universal correctness/termination.
The reused arithmetic/matrix routines, generated derives, compiler, and runtime
remain within the trusted computing base. Local source purity is checked by the
repository gate, rather than asserted as a runtime theorem.
