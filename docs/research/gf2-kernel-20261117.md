# Pure ADT GF(2) decomposition, 2026-11-17

## Scope and decision

Baseline: `4d9e6c4e0795f3e950fbeaac2b191f195eea45b5`. This work adds an exact
GF(2) kernel without changing existing `rowreduce` APIs or production data
representations. Boolean values, immutable `Chain`, unary `Nat`, tuples, records,
pattern matching, and recursion remain the production representation. This is
not packed-word or hardware SIMD linear algebra.

Two mechanisms were implemented, then tuning stopped:

1. Specialized Boolean elimination avoids normalization and field-operation
   dictionary calls, shares unchanged rows when the elimination coefficient is
   false, and XORs only the active suffix. A source-bound factorization augments
   with the identity while reducing only the original source columns. It stores
   a reverse log of self-inverse adjacent row swaps and row additions, allowing
   the inverse row transform to be constructed by replay instead of a second
   Gaussian elimination. RREF-only calls do not construct a transform or log.
2. One-shot `solve` reduces only `A | rhs`. The first prototype called `factor`
   and replayed its operations for every one-shot solve; exploratory timings
   showed small/tall regressions. `solve_factor` retains the explicit reuse path
   for callers already needing a factorization.

`multiply` intentionally retains generic exact matrix multiplication. Its use in
the certificate checker provides a check separate from the elimination/log
implementation. No optimized multiplication mechanism was added.

## API and certificates

The generated interface is `src/gf2/pkg.generated.mbti`. `factor` returns an
immutable `Factorization` constructed by the kernel. `source`, `reduction`, and
`transform` expose its source, canonical `rowreduce.Reduction[Bool]`, and row
transform `U`. `inverse_transform` lazily replays the reverse operation log.
`solve_factor` and `nullspace_factor` reuse the factorization; free variables
remain in ascending column order, matching generic `rowreduce.solve` exactly.

The explicit certificate fields are `source`, `reduced`, `transform`,
`inverse_transform`, and `pivots`, matching CSS `RankWitness`. The checker binds
both its explicit source and its explicit supplied reduction to the certificate,
checks all dimensions, verifies `R = U A` and both products of the claimed
inverse, then structurally verifies reduced row echelon form and pivot order.
It does not invoke elimination or inverse search.

## Correctness validation

The four package tests compare against the unchanged generic implementation and
an independent indexed, imperative Boolean Gauss-Jordan oracle. They enumerate
all 689 binary matrices with each dimension in `0..3`, and all 5,054 right-hand
sides for those matrices. They also exercise 28 seeded rectangular/dense/sparse/
dependent cases, all empty-dimension boundaries, singular and nonsquare inverse
rejection, determinant, nullspace order, direct and reused solves, multiplication
dimension checks, and independently computed rectangular products.

Certificate mutation tests change the explicit source/result, stored source,
stored reduction, pivots, forward/inverse transforms, dimensions, and an
algebraically consistent but noncanonical echelon form. These are finite tests,
not a whole-program formal proof.

Milestone `b67e9ab` passed the four tests on native, wasm-gc, and JS and passed the
production purity gate. Milestone `2f6b4df` added the RHS-only solve route and the
benchmark harness; the expanded suite passed all four tests on native, wasm-gc,
and JS as well.

## Measurement protocol

`src/cmd/gf2kernelbench` contains baseline and specialized routes in the same
native release artifact, as a prototype comparison. Baseline factorization
reproduces the existing CSS algorithm: generic reduction of `A | I`, extraction
of `R` and `U`, then generic inversion of `U` when a certificate is needed.
One-shot solve compares the generic and specialized public solve calls.
`reuse` includes factorization, certificate construction and verification, and
four solves against the same source; the baseline re-eliminates the source for
each solve, while the specialized route replays its retained operations.

The process interval includes source construction, generic reference computation,
API calls, full result validation, digest calculation, output, and teardown.
Factor timing includes verification of `U A = R`; certificate/reuse timing
includes the complete algebraic certificate check. Setup-only samples with zero
iterations are retained separately; setup time is never subtracted from measured
process times. Each repeated result is fully checked, and the driver also rejects
any difference in the complete baseline/specialized JSON result.

The shared Git performance lock and CPU affinity 4 serialize builds and timings.
The driver calibrates a common repetition count per case, then records five
ABBA rounds (`baseline, gf2, gf2, baseline`), each sample in a fresh process.
All samples, calibration/setup samples, source and artifact hashes, compiler,
CPU, elapsed time, and per-process `wait4` maximum RSS are preserved in JSON.
Maximum RSS is whole-process memory; it is not an allocation or retained-data
measurement. In this Python launcher it includes the pre-exec child high-water
mark inherited when spawning, which dominates these small executables and grows
with the launcher's retained JSON. Equal recorded RSS therefore provides no
evidence of equal kernel memory or a kernel memory improvement. Matrix sources
and validation are identical within each comparison.

```sh
tools/measure --cpu 4 tools/moon build src/cmd/gf2kernelbench --target native --release -j 1 --deny-warn
tools/measure --cpu 4 python3 tools/measure_gf2_kernel.py \
  --output docs/research/raw/gf2-kernel-abba-20261117.json \
  --rounds 5 --minimum-seconds 0.08
tools/measure --cpu 4 tools/moon test src/gf2 --target native -j 1 --deny-warn
tools/measure --cpu 4 tools/moon test src/gf2 --target wasm-gc -j 1 --deny-warn
tools/measure --cpu 4 tools/moon test src/gf2 --target js -j 1 --deny-warn
```

Exploratory raw data are retained in `raw/gf2-smoke-20261117.json` and
`raw/gf2-solve-smoke-20261117.json`; these short one-round runs are diagnostic
evidence only. Public CSS/cohomology baseline/final source comparisons are a
separate integration measurement; the same-artifact prototype results do not
establish their speedup.

## Final paired results

All 600 timed processes passed complete output validation, and the final driver
verified unchanged source and artifact hashes. This single Intel Core Ultra 7
255H run, pinned to CPU 4, found improvements in all 30 measured cases. The
smallest ratio was 1.448× (one-shot solve, 4×5 source); the largest was 7.016×
(factorization, 36×12 source). RREF ranged 1.790–5.707×, factorization
1.865–7.016×, certificate construction plus verification 2.034–5.755×, one-shot
solve 1.448–4.248×, and factorization/certificate plus four reused solves
2.095–5.174×. These ratios describe the recorded whole-process interval.

mechanisms are complete; no further tuning was attempted.
