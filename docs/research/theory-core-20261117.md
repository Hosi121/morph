# 既存の被覆から小さな理論衝突節を作る

[研究記録](README.md) / [非線形実数SMT](../handbook/algebraic-solving.md)

[CDCL状態の保持](retained-cdcl-20261117.md)で、理論衝突後の再始動を省いた。
それでも、候補の算術割当て全体を拒否する方式では同じ不可能性を何度も調べていた。
今回は、既に得たCAD被覆から不可能性を示せる原子だけを残し、より短い理論節を学習する。

## 原子を外しても偽か調べる

元の割当てが `A ∧ B ∧ C` で不可能だったとしても、`A ∧ B` が不可能とは限らない。
元のUNSATというラベルだけを流用してはいけない。

`cad.refute_on_cover` は、同じ射影族に対して新しい式の係数判定計画を作り、元の木を辿る。
親セル全体で新しい式が偽と分かれば、その先は `Leaf(false)` で閉じる。
未確定なら、既存のStackの全ての子を調べる。
元の木が短い葉で終わり、その領域で新しい式を確定できなければ、削減を拒否する。
一点での代入値から領域全体を偽にはしない。

この削減処理では、新しい射影の構成、代数拡大体上の演算、根隔離、追加のCAD探索を行わない。
有理係数の計画構築と木の走査は行い、最終checkerは通常どおり射影や幾何を再検査する。
元の被覆に情報が足りない場合は保守的に失敗する。
実際には不可能な部分式でも、元の短い葉の先に必要な分割がなければ削減できない。

SMTは原子を一つずつ外し、返された証拠で不可能性を確認できる場合だけ削除を確定する。
毎回使うのは**最初の被覆**であり、一度縮めた証拠木ではない。
先の削減で捨てたセルが、次の削減に必要になることを防ぐ。
空の連言は非空な実数領域上で真なので、不可能な核として使わない。

## 射影を上位集合として共有する

短い連言の全原子は、元の射影証拠のsourceに厳密に含まれている必要がある。
余分な多項式は空間を分割する補助として使えるが、その等式や不等式を仮定したことにはならない。

`cad.check_cover(arity, formula, proof)` は次を検査する。

- 要求された変数数・式と、証拠の変数数・式が一致する。
- 式の全多項式原子が、射影証拠のsourceに含まれる。
- 全Collins階層が、その射影自身のsourceに対して正しい。
- 全根の被覆、兄弟セル、代表点、符号、短い葉の一様な真偽が正しい。

`cad.check` は引き続き、渡されたProblemと証拠の式・射影を厳密に一致させる。
通常の `prepare` が返すProblemに、別の射影証拠を持ち込めるようにしたわけではない。
元式からのatom再構築と係数計画の再構築も維持する。
射影を共有する入口では、要求された短い式に結び直して全検査を実行する。

公開するLemmaの構造は変えていない。
検査器は残した原子IDと極性から短い式を再構築し、共有被覆の証拠を確認してから拒否節を返す。
元の問題・Boolean符号化・補助変数の区別・最終RUPの検査も維持する。

## 探索の区切りと比較用の入口

削減は明示的なReducing状態を持ち、外側の一遷移で一つの削除候補を調べる。
燃料切れではそのまま再開でき、未完了をUNSATへ置き換えない。
各遷移内の係数計画や木の走査は一定時間ではない。

| 入口 | 理論節 |
| --- | --- |
| `realnlsmt.start` / `start_core` | 既存被覆で証明できる範囲で原子を削減 |
| `realnlsmt.start_retained` | 以前どおり算術割当て全体を拒否。CDCLは保持 |
| `realnlsmt.start_restarting` | 全割当てを拒否。枝刈りCADとCDCL再始動 |
| `realnlsmt.start_full` | 完全CADとCDCL再始動 |

最小の原子数を持つ核や、数学的に全ての不要な原子を除いた核を保証するものではない。
`core_probes` と `core_literals_removed` で、削減の試行と成功を別々に数える。

## 同条件で確認する

比較用の `retained` と新しい `core` は、同じrelease実行ファイルを使う。
新しい共有被覆checkerは両方式で共通なので、過去のGit snapshotそのものとの速度比ではない。
準備・探索・最終の外部検査を含め、内部の理論補題検査も探索時間へ含める。

原子を減らせる定数・二次式の例と、共同でないと矛盾しない例、衝突のない例を比較する。
削減できない入力では係数計画と木の再走査だけが増えるため、その費用も記録する。
ソース `14990c3`、release版をCPU 4へ固定し、共通lockで直列化した。
12入力・3 backendでABBAを3回ずつ、各方式6回、計432回の結果を検査した。
各起動は独立プロセスで、VMの定常状態だけを測った値ではない。

## 独立検査と採用判断

CAD単体では、六つの関係を持つ30個の二次式の解析的oracle、
SATになる弱化、無理根と退化、余分な分割多項式、不正な射影・原子・根被覆・符号を検査した。
別担当は18組の元式と部分式を作り、36件の正確なZ3参照とSMT-LIB再実行を保存した。
部分式の期待値は9 SAT / 9 UNSATであり、SATへの弱化は全て拒否できた。
真にUNSATでも元の短い葉が情報を持たない部分式は、安全に `None` を返すことも確認した。
[厳密な参照入力](../measurements/theory-core-review-oracle-20261117.json)に理由とlibrary hashを記録した。

代表点だけの検査では見逃す対照として、旧被覆の全代表点で `x²−2=0` が偽になるが、
実際には `±√2` が解である例も作った。
その式を射影のsourceへ含めず、古い偽ラベルだけを移す攻撃を拒否した。
通常のcanonicalなProblemへ別の射影を持ち込む攻撃や、兄弟セルの欠落も拒否する。
これらは有限検査であり、CADやコンパイラ全体の形式証明ではない。

以下は準備・探索・最終検査の全体時間の中央値。
比が1未満なら削減方式が遅い。CPU条件や係数構成を別の測定系列と混ぜない。

| 入力 | native 全割当て→削減 | native比 | JS比 | WasmGC比 |
| --- | ---: | ---: | ---: | ---: |
| 定数原子・4個 | 2.859→1.017 ms | 2.81× | 2.29× | 1.94× |
| 定数原子・6個 | 16.797→1.562 ms | 10.76× | 3.11× | 5.56× |
| 不可能な二次式・3個 | 72.551→31.362 ms | 2.31× | 1.68× | 1.69× |
| 不可能な二次式・4個 | 345.526→97.005 ms | 3.56× | 1.84× | 1.35× |
| 二次式の代替SAT・3個 | 77.324→17.105 ms | 4.52× | 2.23× | 2.44× |
| 二次式の代替SAT・4個 | 316.077→45.529 ms | 6.94× | 2.72× | 2.06× |
| 単一原子UNSAT・削減なし | 2.269→2.975 ms | 0.76× | 0.93× | 1.07× |
| 共同で矛盾する2原子 | 1.126→0.970 ms | 1.16× | 0.92× | 0.92× |
| 従属4変数・削減なし | 177.594→180.690 ms | 0.98× | 0.98× | 1.12× |

定数原子は `OR(k<0)`、二次式は `OR(x²+k<0)` で、k=1..n。
代替SATでは最後に `x≥0` を加える。
共同で矛盾する2原子は `x=0 ∧ xy=1`、従属4変数は
`x=y ∧ y=z ∧ z=w ∧ x²=2 ∧ w²≠2`。

6個の定数原子では理論衝突63→6、最終の理論補題に含まれる原子数合計378→6となった。
4個の二次式でも衝突15→4、原子数合計60→4、SATの代替分岐では衝突30→4へ減った。
二次式4個のnative比較は、全ての生値についても最小の旧時間/最大の新時間が2.93倍だった。
同じ保守的な比でJS/WasmGCも1を上回った。

必要な原子を削れない2原子例では、削減probeが2回増える。
JS/WasmGCの中央値は約8〜9%遅くなり、ここでの改善は主張しない。
単一原子ではprobeを実行しないが、nativeの一変数UNSATの中央値は0.76倍となった。
衝突のない例にも遅い中央値と範囲の重なりがあるため、これらを削減の効果とは扱わず、生値を残す。

通常の `start` は削減付きの `start_core` を使う。
複数の独立した不可能性を含む実数式で、全backendの検査込み改善を確認できたためである。
一方、全ての入力が速くなるとは結論せず、`start_retained` に全割当ての比較経路を残す。
より小さい理論節も必ず元式へ結び直して検査し、元のSAT/UNSATの意味は変えない。

## 残る課題

短い理論節でも、射影証拠は元の大きい多項式集合を共有する。
原子を減らした後の最小の射影や証拠を作っているわけではない。
局所射影、算術側の学習状態、仮定のpush/popは別の課題として残る。
