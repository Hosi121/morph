# Exact finite-state Markov kernels

This branch adds a separate `markov` package without depending on the concurrent
finite probability or information geometry work. Production code uses immutable
Chain/Nat/Binary and exact rational ADTs, with no machine numerics, arrays,
mutation, FFI, floating tolerance or implicit normalization.

Validation correction: the first two milestones ran compiler/tests but omitted
the repository's lexical purity audit. Root caught prohibited equality-operator
tokens in that review. Production comparisons now use explicit ADT equality or
pattern matching, and the complete `tools/audit_purity.py` gate passes. The earlier
test results were not purity-gate results. This correction changes no API or
mathematical equations.

The convention is a row distribution: `mu_next = mu P`. `compose(first, second)`
applies first and then second, so its matrix is `P_first P_second`. A Kernel is
opaque and can only be constructed after checking a nonempty square matrix,
nonnegative entries, and exact row sums of one. Empty state spaces are rejected:
there is no normalized distribution on the empty set. State labels are unary
indices in `0..states-1`.

## Milestone 1: checked kernels and exact evolution

`kernel`, `identity`, `states`, `transitions`, `evolve`, `compose`, `power(Binary)`
and `evolve_steps` are implemented. Distribution boundaries check dimensions,
nonnegativity and exact normalization. Kernel products/powers recheck the resulting
stochastic invariant. Exponent zero returns the identity; powers of periodic
chains are not treated as convergent approximations.

`check_evolution` evaluates each original scalar coordinate equation without
calling the row-accumulator producer or generic matrix multiplication.
`check_composition` checks every row through these equations. These checks still
share core/exact arithmetic, so they are not a wholly independent implementation.

The standalone `tools/generate_markov_fixtures.py --check` independently regenerates
all expected values using Python Fraction and indexed host matrix arithmetic.
The first corpus covers 203 complete powers/evolutions and eight ordered
compositions. It exhausts quarter-probability two-state kernels and includes
identity, periodic, reducible and transient examples. Handwritten tests cover
empty/malformed shapes, negative mass, normalization violations, noncommuting
composition, checker rejection and a periodic exponent of 65537.

Milestone 1 validation: 39 tests on native, JS and wasm-gc; scoped native
deny-warn, generated interface and fixture regeneration checks. No performance
claim is made: this is a new exact feature, not a measured optimization.

## Milestone 2: complete stationary families

`stationary_affine` solves the entire normalized system
`A pi = b`, where `A=[P^T-I; ones]` and `b=[zeros;1]`. The opaque result retains
its kernel, an affine origin and independent directions. It represents every
normalized stationary linear solution. Its origin and directions are signed
linear-algebra values, not unchecked probability distributions.

`stationary_member(family, parameters)` constructs the affine combination and
checks coordinatewise nonnegativity, dimension, total mass and the original
stationary equations. Thus its accepted parameter domain is exactly the
stationary probability polytope. Parameters themselves need not sum to one.
`unique_stationary` only returns a checked distribution when the affine direction
space is empty; otherwise it reports NonUniqueStationary. In particular, an
identity kernel does not silently choose a point mass. A reducible kernel can
still have a unique stationary distribution, and a periodic kernel can have a
unique stationary distribution without converging to it from arbitrary starts.

`check_stationary_family` checks original scalar equations and total masses,
then independently checks direction independence and full nullity by exact RREF.
If `r=rank(A)` and `d` is the number of independent directions, `r+d=n` establishes
completeness. It does not trust the producer solve's particular/basis fields.
The checker still shares the exact RREF/arithmetic implementation; independent
Python Fraction full-system elimination is retained as separate evidence.

The extended generator includes 37 complete stationary families, including
identity kernels through five states, separate closed periodic classes, transient
states and random rational kernels. Complete origins/directions and accepted or
rejected parameter combinations are checked. Tampered tests cover omitted,
dependent, wrongly normalized and foreign-kernel families. Small canonical
parameter examples verify the nonnegative constraints, rather than returning
arbitrary eigenvectors. Milestone 2 passes 79 tests with deny-warn on each of
native, JS and wasm-gc, plus interface and fixture regeneration checks.

## Milestone 3: certified hitting and unconditional times

`hitting(kernel, targets)` analyzes `T=min{n>=0: X_n in targets}`. Target indices
must be valid; duplicates/order are normalized. Targets need not be absorbing in
the original kernel because the question stops at the first visit. Starting in a
target has chance one and time zero. An empty target set has chance zero and
Infinite time from every state. This covers absorbing-chain questions as well as
first entry into arbitrary subsets.

The opaque result retains its kernel/target context, all exact hitting
probabilities, all unconditional expected times, and a reachability certificate.
`Some(path)` gives a route with strictly positive transition probabilities to a
target. States with None form a target-disjoint set closed under every positive
transition. The producer discovers paths with at most n bounded extensions. The
checker instead validates each path and the closed complement locally; it never
calls the discovery algorithm or linear solver.

For probabilities, target coordinates are fixed to one, unreachable coordinates
to zero, and the others solve `h_i=sum_j P_ij h_j`. These boundary conditions are
essential: harmonic equations alone allow nonminimal solutions on closed classes
that never reach a target. The test suite includes such a wrong harmonic vector
and requires rejection.

Why this selects the exact solution: every state outside the boundary has a
finite positive-probability path to a target. Finitely many such paths give a
uniform finite block length and a strictly positive chance of leaving the
interior per block. The interior process therefore exits almost surely with a
geometric tail. The Dirichlet system is unique and its result is the minimal
nonnegative hitting solution. The path/closed-complement certificate establishes
the needed graph facts independently of the solve output.

If `h_i<1`, unconditional E[T] is Infinite. This does not substitute a finite
expectation conditioned on eventual success. If `h_i=1`, finiteness of the state
space and the same path argument establish a finite expectation, solved by
`t_i=1+sum_j P_ij t_j` outside targets and zero at targets. Positive transitions
from such a state cannot lead to `h_j<1`. The checker verifies this through the
original expectation equations; zero-probability edges to Infinite are skipped
without defining an arithmetic value for `0*Infinite`. Infinite denotes the
chain's hitting time, not nontermination or exhausted fuel in the analysis.

The checker does not use reach_paths, solve, RREF or the producer's Dirichlet
matrix builder. It still shares core/exact arithmetic and target-index validation.
The independent Python oracle uses Floyd reachability and reduced transient
systems with host index remapping, rather than the producer's full boundary-row
systems. It checks 190 complete target problems, including every target subset
for the fixed kernels and sparse random examples through five states. Tamper
tests reject wrong contexts, targets, reachability, probability bounds, harmonic
but nonminimal values, and finite/negative/wrong target times. Geometric and two
consecutive-head examples separately check known exact expectations 2 and 6.

Final Markov validation: **115 tests on each of native, JS and wasm-gc with
deny-warn**, 203 full powers/evolutions, eight compositions, 37 full affine
families and 190 hitting problems under an independent reproducible Fraction
oracle. Generated interface, fixture --check, format and full repository purity
gate pass. Shared arithmetic/RREF dependency limits remain as stated above.
No convergence, mixing-time or stationary-limit approximation is implemented.

The mathematical convention and distinction between stationary distributions and
periodic evolution follow the author's
[UCSD stochastic-process lecture notes](https://www.math.ucsd.edu/~tkemp/285.LectureNotes.pdf),
Sections 1.2, 2, 3 and 6.2. Implementation and fixtures derive and check their exact
equations directly.
