# Exact relative Sturm isolation over a selected real number field, 2026-11-16

`orderedsturm` counts and isolates the **distinct real roots** of a univariate polynomial in `Q(alpha)[y]`, where `alpha` belongs to an existing checked, irreducible, real-embedded `numberfield.Field`. It returns finite exact tower-root descriptors: the fixed base embedding, a relative polynomial, and a rational half-open interval `(lower,upper]` containing exactly one relative real root `beta`. It does not construct the field `Q(alpha,beta)`, implement arbitrary tower arithmetic, or claim full CAD.

[Generated API](../../src/orderedsturm/pkg.generated.mbti), [field sign bridge](../../src/orderedsturm/scalar.mbt), [relative arithmetic](../../src/orderedsturm/polynomial.mbt), [system certificate checker](../../src/orderedsturm/system.mbt), [half-open root counting](../../src/orderedsturm/count.mbt), [isolation and coverage checker](../../src/orderedsturm/isolation.mbt), [independent fixture generator](../../tools/generate_orderedsturm_fixtures.py).

The verified package currently passes **48 tests on native, JS and WasmGC**, with warning/interface/format checks, oracle freshness and the symbolic-purity gate passing.

## Entry points and exact context

`polynomial(field,coefficients)` accepts an ascending immutable chain of `numberfield.Element`, checks every element has the **same field including the exact selected-root interval**, and trims trailing zero coefficients. Existing quotient-field operations implement exact addition, multiplication, differentiation, Horner evaluation at rational `y`, and Euclidean division. Mixed fields are errors, including two representations of the same base root with different isolating intervals. `evaluate` returns an Element in the fixed base field; it does not return a tower element.

`scalar_sign(e)` feeds `numberfield.embedding(parent(e))` and the canonical rational polynomial `representative(e)` to `tarski.root_sign`. Thus it orders the selected real embedding without refining the base root interval. `check_scalar` binds the supplied Element, its full embedding, Ordering payload, and Sturm–Tarski proof. Zero residue and zero sign must agree; irreducibility of the checked Field makes this valid. No floating point is used.

`system(p)` rejects the zero polynomial and prepares a normalized square-free system. A nonzero constant is supported and has no roots. The source polynomial, field embedding, and canonical coefficient representatives are recorded in `SystemCertificate`. `system_from_certificate` independently checks a supplied certificate before constructing the opaque System.

`count_between(system,interval)` returns `CountCertificate`, whose `count` counts distinct relative real roots in `(a,b]`. Rational endpoints must satisfy `a<b`; equal or reversed bounds are errors. `check_count(system,interval,count,certificate)` also binds the separately supplied interval and Nat payload. It does not interpret zero count as any statement outside that interval.

`isolate(system)` initializes a state, and `advance(state,fuel)` returns `Isolated(SolutionSet)` or `Paused(State)`. Resumption retains the same checked System and pending intervals. Fuel counts a bound comparison or a processed bisection node; it does not bound bit complexity, recursion, memory, certificate checking, or elapsed time. Zero fuel can return an already completed pending-empty state, but cannot invent a completed answer from unprocessed work. `refine(root,steps)` performs exactly the requested number of bisections and returns a still-valid one-root descriptor; zero steps returns the same descriptor. It makes no claim to meet an unstated width tolerance.

## Algebraic witnesses and endpoint convention

The source theorem is Sturm root counting in a real closed extension, computed by negative Euclidean remainders over the coefficient field. [Eisermann, Theorem 3.15, Corollary 3.16 and Remark 3.18](https://arxiv.org/html/0808.0097v4#S3.SS7) distinguishes roots in a real closure from roots merely in the coefficient field: this distinction is essential for `y^2-sqrt(2)`, whose roots are not in `Q(sqrt(2))`. The cited paper uses half-weight boundary conventions. We instead derive and check the required half-open convention using right-hand signs, as in the existing [Tarski endpoint derivation](tarski-20261116.md); the paper's endpoint formula is not copied unchanged.

For original nonzero `p`, the producer makes `A=p/lc(p)`, computes a signed Euclidean PRS of `A,A'`, normalizes its final member to monic `G`, and forms `F=A/G`. In characteristic zero this is the monic square-free part. A second negative PRS starts with `F,F'`; its final member must have degree zero. The checker verifies the initial polynomials, every quotient identity `S_(i-1)=q_i*S_i-S_(i+1)`, strict degree descent, exact final division, monic normalizations, and `G*F=A`. It does not accept a truncated chain or equate a mere product identity with square-freeness. Supplied raw field representatives must already be canonical and coefficient chains must already be trimmed.

For a rational endpoint `a` and a nonzero sequence member `S`, the first nonzero derivative value `S^(k)(a)` lies in the base field. Its sign is the right-hand sign of `S` near `a`, because the Taylor coefficient divisor `k!` and a sufficiently small positive displacement power are positive. An `EndpointJet` records this least order, the canonical field representative, and its Tarski sign certificate. The checker verifies every earlier derivative vanishes, the recorded derivative does not vanish, the exact representative agrees, and `k<=degree(S)`. This prevents accepting an arbitrary later derivative.

If `V_+(a)` is the variation count of these right-hand signs, the root count is `V_+(a)-V_+(b)`. Choose a sufficiently small positive epsilon with no sequence root strictly between either endpoint and its shifted endpoint. The open-interval Sturm theorem at `a+epsilon,b+epsilon` then counts exactly the roots in `(a,b]`. A root at the lower endpoint is excluded, and one at the upper endpoint is included. Repeated roots were already removed by the checked square-free quotient. The difference is computed with a symbolic signed Integer before conversion to Nat, so an impossible negative count becomes an error.

## Global coverage and the tower boundary

For monic `F=y^n+sum(i<n,a_i*y^i)`, the code computes the field Element `T=1+sum |a_i|`. Every coefficient absolute value has a sign certificate. It tries rational radii `B=1,2,4,...` until an exact scalar certificate proves `B-T>0`. This is a conservative Cauchy bound. Direct justification: for real `|r|>=B>1+sum|a_i|`, with `n>0`, the lower terms have magnitude at most `(sum|a_i|)*|r|^(n-1)<|r|^n`, so `F(r)` cannot vanish. Constant `F` has no roots. This short bound argument is our explicit derivation; [Basu–Pollack–Roy, §2.2.2](https://perso.univ-rennes1.fr/marie-francoise.roy/bpr-ed2-posted2.pdf) and the preceding Sturm reference supply the real-root counting framework, not a different coefficient bound silently substituted here.

The whole interval `(-B,B]` therefore covers every real root. Exact rational bisection retains the half-open ownership rule. Zero-root nodes are discarded, one-root nodes become Root descriptors, and other nodes are split. Pending work can only yield `Paused`, never an empty complete answer. All roots are eventually separable in the usual mathematical model, but this implementation claims no global runtime bound.

`SolutionCertificate` records the strict bound, whole-interval count, and the ordered one-root certificates. `check_isolation(p,proof)` validates the external source polynomial and base context, the bound, every endpoint/count witness, ordered pairwise disjoint containment in the whole interval, and equality between the number of one-root intervals and the whole count. Thus missing roots, duplicate roots, reordered overlapping intervals, and extra roots are rejected. `check_isolation_result` additionally binds the opaque SolutionSet payload and its Root payloads to the supplied proof, including each internal source/context, square-free polynomial and derived Sturm sequence. These fields are inaccessible to external constructors; white-box negative tests still alter them to verify the payload check. Root has analogous `check_root` and `check_root_result` APIs. Representation binding is exact; mathematically equivalent alternative base intervals or relative source polynomials are deliberately not interchangeable.

An interval with one relative root can contain other roots of an absolute norm resultant from different embeddings of alpha. Consequently Root is not an existing `realalgebraic.Number`, and the package does not pretend that its relative isolating interval is automatically an absolute one-root certificate. For example `y^2-alpha` with `alpha=+sqrt(2)` has two relative real roots, whereas the same polynomial at `alpha=-sqrt(2)` has none; both have norm resultant `y^4-2`. The fixed embedding distinguishes them.

## Independent validation and composition

The generated [oracle artifact](orderedsturm-20261116-fixtures.json) contains 40 relative systems over the positive and negative embeddings of `Q(sqrt(2))` and `Q(sqrt(3))`, 200 half-open interval queries, 52 distinct relative roots, and 40 exact norm resultants. Exact known roots include nested square roots, real cube roots, algebraic linear roots, zero/rational endpoint roots, mixed factors, repetitions, no-real-root polynomials, and constants. Expected interval counts come from exact SymPy radical comparisons, independently of Sturm variation. A separate dense Python `Fraction` implementation in the quadratic field computes the square-free part and complete signed PRS; MoonBit agrees coefficient by coefficient. SymPy resultants annihilate every known relative root, and refined MoonBit relative intervals retain a positive absolute resultant root count without claiming that absolute count is one.

Additional tests cover the degree-one rational-field entrance, an irreducible cubic base field, close rational roots separated by `1/1024`, every fuel boundary around a known completion, pause/resume, division by zero, mixed fields, malformed source/PRS/quotient/square-free certificates, changed count or sign payloads, wrong selected embedding, wrong Root payload, missing roots and changed bounds. The base alpha interval is checked unchanged. These are executable cross-checks, not a formal proof of the implementation or an optimal complexity result.

The bootstrap path is now: existing real root certificate -> checked minimal polynomial -> checked `numberfield.Field` -> exact residue sign by Tarski -> relative square-free Sturm System -> complete checked tower-root cover -> rational refinement/evaluation. It supports a downstream bivariate lifting stage while leaving construction and arithmetic of higher tower fields outside this package.
