# 数体・線形従属・Smithの算法改善

[研究記録](README.md) / [基礎部品の最適化](../KERNELS.md)

五つの候補を三担当で実装・比較し、四つを通常経路へ採用しました。
持続ホモロジーのpivot索引は二方式とも安定した改善がなく、本体を元に戻しました。
型の不変条件と不変な状態の再利用で、純記号の表現を維持したまま処理を省いています。

## 採否と接続先

| 候補 | 判断 | 実装と理由 |
| --- | --- | --- |
| 数体の加減算 | 採用 | 正規代表元の和・差は次数d未満を保つ。選択根を含む体の一致検査後、剰余の再計算を省く。乗算は従来の簡約を維持 |
| 座標抽出 | 採用 | 降順・重複なしの項列を一度進め、零を補う。数体・複素数体・乗算行列が共有 |
| 増分の有理線形従属 | 採用 | `linearspan.State`に独立列の正規化残差と元列への係数を保存。数体・複素数体の最小多項式とFGLMへ接続 |
| Smithの列操作 | 採用 | 全転置を二度作る経路を、各行の対象位置の直接更新へ変更。U/D/Vと燃料の遷移を維持 |
| 持続ホモロジーのpivot索引 | 不採用 | 常時構築と最初の衝突時構築を比較。索引の費用を回収できず、本体・import・公開APIを基準と同じバイト列へ復元 |

個別の不変条件、独立oracle、試作の全生値は、[数体](nf-kernels-20261117.md)、
[増分線形従属](incremental-span-20261117.md)、[Smithと持続性](structural-kernels-20261117.md)にあります。
増分状態の保持量は有理数セルでO(dr+r²)です。整数のbit長や実メモリ量の上界・実測値を示すものではありません。

## 対照と限界

数体の乗算本体を変えていない対照は49.825→51.564 ms、比0.966で、5組中4組が遅い側でした。
担当単独の同じ対照は比0.989、ブロックの範囲は0.944〜1.039です。
この統合版には約3.5%の時間増加を観測しており、無変更の経路まで速くなったとは扱いません。
複素平方の小差も一般的な改善には数えません。
持続性の本体を復元した三対照の比は1.010 / 0.988 / 0.987です。
別ビルド・起動・環境の変動を含み、速度改善を主張しません。

既存の最小多項式検査・FGLM証拠検査・Smith検査の算法は維持しています。
ただし生成側と検査側が共有する数体演算・座標抽出も今回変更しています。
旧実装との照合、Fractionや行列式による別の参照値を加えても、全プログラムの形式証明とは異なります。
速度はこの有限な入力・係数サイズ・native環境での結果です。JS/WasmGCの速度や一般入力の性能は未計測です。

## 作業境界と再現

準備コミット `93878f2` は旧座標抽出をそのまま共有関数へ移し、`numberfield.coordinates`を公開しました。
測定CLIは追加APIを呼ばないため、元の基準でも同じソースで動きます。
基準worktreeの追跡済みライブラリ・module・compiler wrapperのバイト列は基準のままです。
三つのCLIだけを未追跡でコピーしたため、担当が順に測った基準全体のmanifestは異なる場合があります。
個別のharnessと実行ファイルのhash、および追跡済みライブラリの同一性を別々に検査しています。

実装は `e65a718`（加減算）、`1a56cc6`（座標）、`fc090d9`・`41f3f44`（増分従属）、
`51ccc10`（Smith）、不採用・復元は `4703f38` です。元の担当コミットも各記録に残しています。
今回の区切りは五機構それぞれの採否、統合比較、逆依存先の検証、文書・commit・push・片付けです。
公開関数の既存結果・エラー・証拠の条件と純記号の制約を維持し、
加えたAPIとopaque状態のcacheはコンパイラ生成interfaceで記録しています。
最終検証と片付けの証跡は[検証ガイド](../VALIDATION.md)から辿れます。
