# Fixed-degree principal subresultant coefficients

This second elimination milestone adds [generic PSC determinants](../../src/elimination/principal.mbt) and [QQ coefficient/PSC entry points](../../src/elimination/principal_variable.mbt) without changing the earlier implementation or signatures. The frozen Berkowitz dependency is still root `1f067d2`, local `9db352a`, byte-identical. The [generated API](../../src/elimination/pkg.generated.mbti) is extended using `moon info`.

For nominal degrees `n,m` and `0<=k<=min(n,m)`, let `N=n+m-2k`. `principal_matrix` uses the shifted rows

```text
y^(m-k-1) f, ..., f, y^(n-k-1) g, ..., g
```

and keeps the first `N` descending coefficient columns, corresponding to powers `y^(n+m-k-1)` through `y^k`. `principal_subresultant` takes this square determinant through the division-free Berkowitz kernel. Invalid `k` returns `None`; the QQ wrapper returns `DegreeTooSmall`. `principal_coefficients` lists indices from zero upward, including the terminal determinant. `PSC_0` agrees with the existing resultant sign.

This is the truncated-Sylvester determinant convention described by [Geiger–Meek, §3, principal-subresultant construction](https://dang.cs.technion.ac.il/conf_papers/GeigerM99.pdf), equivalently obtained from the full shifted-row matrix by removing the first `k` rows of each block and the first/last `k` columns. The terminal extension is explicit: if `n=m`, the top coefficient is the empty determinant **one**; otherwise it is `lc(smaller)^abs(n-m)`. Degree-zero cases agree with the earlier resultant conventions. Some sources instead append the smaller polynomial itself and use its leading coefficient as the terminal PSC, such as [Chen, §3.1](https://www.csd.uwo.ca/~mmorenom/Publications/Changbo.Chen-Thesis-UWO.pdf). Those terminal normalizations must not be compared numerically without adjustment.

Over a field, for two nonzero polynomials whose actual degrees equal the nominal degrees, the least index with nonzero PSC is the exact gcd degree. The ordinary subresultant theorem and specialization conditions appear in [El Kahoui, *An elementary approach to subresultants theory*](https://doi.org/10.1016/S0747-7171(02)00135-9), and [Chen, Theorem 3.2](https://www.csd.uwo.ca/~mmorenom/Publications/Changbo.Chen-Thesis-UWO.pdf). At the terminal index our determinant is nonzero under these hypotheses, so the different terminal convention gives the same degree decision. `first_nonzero` only returns an index; it does not claim or check those algebraic hypotheses. Zero polynomials, zero derivative, leading-degree loss, arbitrary rings and zero divisors are outside that gcd-degree inference.

Every PSC remains its fixed-degree determinant after leading coefficients specialize to zero. This does **not** automatically make its first nonzero index the actual specialized gcd degree. For example two nominal quadratics which both specialize to nonzero constants have PSCs `[0,0,1]`, although their actual gcd degree is zero. For a nonconstant polynomial and a nominal positive-degree zero derivative, all PSCs can vanish. A nominal constant and its constant-zero derivative instead use the total-degree-zero list `[1]`; it is a convention, not a gcd theorem for zero inputs.

`coefficient_polynomials(Input)` exposes the complete descending QQ coefficient list in one fewer variables, preserving nominal padding and zero cells. `principal_variable` and `principal_coefficients_variable` use the same private homogeneous coefficient carrier as the first milestone. Their input compatibility checks bind source arity and selected variable. Generic `PrincipalCertificate` and QQ `PrincipalVariableCertificate` embed both inputs, both nominal degrees, index and value. Their checkers compare the external query and payload before recomputing the determinant; a proof for another index, padded degree, source problem or payload is rejected. These are recomputing executable checks, not an independent formal determinant proof.

[The independent generator](../../tools/generate_elimination_principal.py) builds all truncated matrices numerically and expands their determinants by Fraction permutations. It checks 77 input pairs, including equal-degree, unequal-degree, terminal powers, zero/constant polynomials, leading-zero specialization and known nontrivial gcds. A separate dense Fraction Euclidean algorithm and SymPy gcd agree on the gcd degree; the first-nonzero claim is tested only when both actual degrees are preserved. Another 24 QQ coefficient-ring cases independently expand symbolic permutation determinants and check every coefficient, PSC, index and query certificate. One boundary group explicitly checks equal-degree top one, constants and zero derivatives.

The 102 new tests pass with the prior 228 elimination tests: **330 total** per backend. The retained `.tools/elimination-principal-20261116/oracle.json` holds the exact fixtures and gcd eligibility flags; the validation transcript records nonzero test counts, commands, exit status and the unchanged Berkowitz source hashes. The strict symbolic-purity gate, formatting, warnings-as-errors and API generation are included. Generic callbacks still require commutative-ring laws; this milestone adds no division, machine numeric kernel type, numeric literal, array, mutation, FFI or unwrap. All heavy work uses the shared CPU 10 lock. Finite test coverage, matrix/coefficient growth and whole-stack trust limits from the first milestone continue to apply.
