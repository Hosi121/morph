# Exact rational pointwise metric jets

The new `riemann` package computes coordinate geometry at one point from a
supplied metric value and its first and second partial derivatives. It validates
a symmetric nondegenerate metric two-jet; it does not construct an analytic
manifold, identify chart domains, integrate curves, or establish global geometry.
Indefinite metrics are accepted. Invertibility is never treated as positivity;
`is_positive_definite` separately applies exact Sylvester leading-minor checks.

## Frozen inputs and conventions

`metric_jet(g, first, second)` returns `Result[MetricJet, JetError]`, with an opaque
successful value. The metric is an n×n rational `Matrix`. `first[k]` is the n×n
matrix of ∂k g_ij; `second[k][l]` is the n×n matrix of ∂k∂l g_ij. Both derivative
axes have exactly n entries. Every matrix is symmetric and the derivative axes
commute. Validation checks metric shape, first shape, second shape, metric
symmetry, first symmetry, second symmetry, mixed derivative symmetry, then
invertibility, in that order. The corresponding error constructors are
`MetricShape`, `FirstDerivativeShape`, `SecondDerivativeShape`, `MetricSymmetry`,
`FirstDerivativeSymmetry`, `SecondDerivativeSymmetry`,
`MixedDerivativeSymmetry`, `SingularMetric`. The n=0 jet is valid.

All indices are zero-based `Nat`. Tensor2/3/4 are dense nested immutable Chains
with indices in their written order. A Connection retains its checked MetricJet,
and a Curvature retains its Connection. Component lookups return None for absent
indices. Full tensor getters preserve all n^rank entries.

The connection and curvature conventions follow David Tong's author-published
[General Relativity, sections 3.2 and 3.4](https://www.damtp.cam.ac.uk/user/tong/gr/grhtml/S3.html),
especially equations 3.110 and 3.131:

```
C_ijk = (∂j g_ik + ∂k g_ij − ∂i g_jk)/2
Γ^i_jk = g^ia C_ajk
R^i_jkl = ∂k Γ^i_lj − ∂l Γ^i_kj + Γ^i_ka Γ^a_lj − Γ^i_la Γ^a_kj
R_ijkl = g_ia R^a_jkl
Ric_jl = Σ_i R^i_jil
scalar = Σ_jl g^jl Ric_jl
```

In particular a unit round two-sphere has scalar +2. Christoffel symbols are
coordinate quantities, not tensors. The production curvature route computes
lowered curvature directly from metric second derivatives and Christoffel
products, then raises the first index. This avoids differentiating a matrix
inverse in the kernel. All arithmetic is exact `Rational`; all indexing and
traversal are immutable `Nat`/`Chain`. Inversion/determinants reuse `linear`.

The round sphere fixtures use g_ij = 4r² δ_ij/(1+Σx²)², the dimensionless
stereographic coordinate chart. The unit-radius chart formula also appears in
[Benjamin Schmidt's Riemannian Geometry notes, chapter 3](https://www.wim.uni-mannheim.de/media/Lehrstuehle/wim/schmidt/FSS2024/Riemannian_Geometry/Web/RGch3.html).
Scaling by r² yields sectional curvature 1/r².

## Independent finite oracle

`tools/generate_riemann_fixtures.py` uses only Python standard-library Fraction
and second-order automatic differentiation of rational expressions. Its
curvature route differentiates the inverse metric and second-kind Christoffel
formula, then contracts; it does not use the production lowered-curvature route
or any MoonBit output. It asserts inverse identities, torsion freedom, metric
compatibility, all lowered curvature pair symmetries, the algebraic Bianchi
identity, and known constant-curvature formulas before emitting fixtures.

The initial 17 fixtures cover empty dimension, a nonconstant 1D metric, flat
Euclidean and indefinite null-basis metrics, flat polar metrics at three rational
radii, a flat nonlinear shear chart, round spheres at rational points and
radii, affine/nonlinear sphere charts, a 3-sphere chart, hyperbolic upper half
plane, Lorentz de Sitter, and a general symmetric 3D two-jet. Every inverse,
first/second-kind Christoffel, lower/mixed Riemann, Ricci, scalar and positivity
classification is compared exactly. Invalid shape, symmetry, mixed derivative,
singular and out-of-range cases are tested separately.

Initial native milestone: four test blocks pass, including all 17 complete
fixtures. Cross-target validation and pointwise vector operations follow in
later milestones; no performance or large-dimension scalability claim is made.
The oracle generator's `--check` also verifies canonical generated source bytes,
using the pinned SDK's moonfmt solely for formatting.
