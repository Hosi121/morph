# Shape-position real solutions and rational univariate representation

[ドキュメント](../README.md) / [研究・探索記録](README.md)

This package connects the symbolic F4 basis, Sturm root isolation, and exact real-algebraic representations. It solves the explicitly checked shape case of a zero-dimensional rational polynomial system, using the last variable as parameter `t`. It also searches a family of separating linear forms through a checked graph augmentation. It does not implement general CAD or an unconditional zero-dimensional solver.

The F4 dependency is the frozen source commit `ae6f76b3d529ae86c63d065a77f9f5b380ddd1a6` (locally cherry-picked as `daf9e74`). No F4 implementation files are edited here. The first RUR commit `b0aa543` passes **25 tests**; the RUR and coordinate-materialization commit `fe5699b` passes **92 tests**. With the separating-form search, the package passes **111 tests on native, JS and WasmGC**.

## Supported representation and certificate

[Shape extraction/checking](../../src/realvariety/shape.mbt), [exact substitution](../../src/realvariety/substitution.mbt), [complete real-root enumeration](../../src/realvariety/solutions.mbt), [generated API](../../src/realvariety/pkg.generated.mbti).

For `n >= 1`, a checked presentation consists of

```text
g(t), x_0-h_0(t), ..., x_(n-2)-h_(n-2)(t), t=x_(n-1).
```

The implementation extracts a nonconstant parameter-only row and a row `a*x_i+q(t)` with nonzero rational constant `a` for each other variable. The chosen rows must actually occur in the supplied basis. The eliminant is normalized to monic `g`, each `h_i` is reduced modulo `g`, and the final coordinate expression is exactly `t`. Every basis polynomial must then substitute to remainder zero modulo `g`.

These checks give both ideal containments without relying on a heuristic shape test. Let `I` be generated by the supplied basis and `J=<g,x_i-h_i>`. Actual-row provenance gives `g in I`; dividing the chosen coordinate row by its nonzero scalar and reducing its univariate part modulo `g` gives `x_i-h_i in I`. Thus `J` is contained in `I`. Conversely, reducing every substituted basis polynomial modulo `g` to zero proves each basis generator lies in `J`, so `I=J`. This also explains why provenance and checking **all** basis rows are separate obligations.

For every complex root `alpha` of `g`, the tuple `(h_0(alpha),...,h_(n-2)(alpha),alpha)` is a solution. Every solution has exactly this form because the shape equations are actual consequences of the basis. Distinct parameters give distinct tuples through the last coordinate. A tuple is entirely real exactly when its final parameter is real. Therefore isolating every distinct real root of `g` enumerates exactly the real solution set.

The classical shape lemma explains when a radical zero-dimensional ideal with a separating last coordinate has this form; see [Szántó, lecture notes on geometric resolution, Theorem 1.1](https://aszanto.math.ncsu.edu/MA722/ln-03.pdf), and the [research report statement of normal position and its solution parametrization](https://www.ricam.oeaw.ac.at/files/reports/23/rep23-01.pdf). This implementation checks the equations and both ideal directions directly: it does not assume radicality, generic position, or the shape lemma's hypotheses merely from a dimension claim. A repeated `g` is supported as a presentation of a nonradical ideal, while the returned solution set lists distinct points and does not encode multiplicity or local algebra.

## F4 to exact solution points

The intended bootstrap path is:

```text
rational input equations
  -> @f4.f4 / run
  -> @f4.verify(Basis): both ideal directions plus reduced lex basis
  -> @realvariety.from_basis / start_basis
  -> checked shape g(t), h_i(t)
  -> Sturm isolation of all distinct real roots alpha
  -> @realvariety.points: shared @realalgebraic.Number alpha and h_i(alpha)
```

`from_basis` first calls the frozen `verify`, then reads `variables` and `polynomials`. `check_basis_shape`, `check_basis_unit`, and `check_basis_solutions` additionally bind the RUR certificate to that verified basis, so the original F4 input ideal is preserved. The raw `extract`/`start` entry points instead certify precisely the supplied equation list; they do not assert that it was derived from some other input ideal.

A `Point` stores one shared algebraic parameter plus all rational polynomial coordinate expressions. `coordinate_expressions` and `coordinate_expression_at` expose these expressions; `parameter` supplies the checked real-algebraic root. This keeps correlations such as `(alpha,alpha^2)` explicit and avoids degree explosion from separately evaluating every coordinate with repeated algebraic addition/multiplication. A point certificate verifies its shape and the selected parameter root. A solution-set certificate additionally verifies the ordered disjoint one-root intervals cover **all** distinct real roots using the Sturm checker.

A nonzero constant actual basis row yields `NoSolutions(UnitCertificate)`, whose checker validates provenance and nonzero constancy. A supported shape whose `g` has no real roots instead yields a checked `Complete` empty set. Failure to extract shape, including positive-dimensional and zero-dimensional non-shape examples, yields `UnsupportedSystem`; it never yields `NoSolutions`. Zero variables are unsupported except for a directly certified unit ideal. Dimension mismatches and invalid certificates are explicit errors.

Root enumeration fuel counts Sturm interval nodes, and `Paused` retains pending work. No partial root list is returned as complete. Exact substitution, F4 verification, and arithmetic within a Sturm node are not covered by this node-count budget.

## Materializing a coordinate without degree explosion

The optional [coordinate evaluator](../../src/realvariety/coordinate.mbt) turns `h_i(alpha)` into a standalone checked `@realalgebraic.Number` while keeping the original RUR intact. For `d=degree(g)` it builds the `d*d` matrix `M_h` of multiplication by `h_i` in the rational quotient algebra `Q[t]/(g)`, using the power basis `1,t,...,t^(d-1)`. Column `j` is the exact remainder of `h_i*t^j` modulo `g`.

For any root `alpha` of `g`, the nonzero row vector `v=(1,alpha,...,alpha^(d-1))` satisfies `v*M_h=h_i(alpha)*v`: evaluating each column remainder at `alpha` removes its multiple of `g`. Consequently `h_i(alpha)` is a root of `C(z)=det(zI-M_h)`. This argument does not require `g` to be square-free. The multiplication-matrix/eigenvalue correspondence is described by [Verschelde, lecture 12, Stickelberger's theorem](https://homepages.math.uic.edu/~jan/mcs563s14/lec12.pdf); our univariate evaluation-row argument supplies the needed existence direction directly. Since the determinant is monic of degree `d`, the output annihilator degree is bounded by `degree(g)` regardless of the coordinate expression degree.

`coordinate_start` and `coordinate_advance` compute determinant samples at `0,...,d` and interpolate exactly. A separate checker rebuilds the multiplication matrix, recomputes all samples, imposes degree at most `d`, and evaluates the claimed polynomial there; it does not replay interpolation. Closed rational Horner interval arithmetic encloses `h_i(alpha)`, then pads both ends by the current parameter-interval width. This positive padding keeps extrema and rational endpoint roots inside the half-open interval. If more than one distinct root of `C` remains, the source parameter is bisected and the range recomputed. Both the range and padding converge to the correct coordinate value. The output polynomial is normalized to monic square-free form by the real-algebraic constructor, and need not be minimal.

One fuel unit computes one determinant/interpolation sample or one source-root bisection. `CoordinatePaused` preserves either unfinished phase. Out-of-range coordinate indices return `Err(InvalidCoordinate)`. The shared-parameter `Point` remains the preferred complete tuple representation, since materializing independent coordinates discards their explicit correlation.

`check_coordinate` checks the result root and coordinate relation embedded in a certificate. `check_coordinate_result(value, proof)` additionally binds a separately supplied `Number` to the exact normalized polynomial and interval recorded by that certificate. Similarly, `check_point_result` and `check_solutions_result` bind separately supplied points and solution sets to their exact certificate representations. These are representation checks: equivalent values encoded with different intervals or shape data are deliberately not interchangeable. The original proof-only checkers remain available.

## Searching a separating linear form

[Graph augmentation and resumable search](../../src/realvariety/separation.mbt) and [projection](../../src/realvariety/projection.mbt) extend the supported input systems while preserving the shape core. `problem(n, inputs)` creates an opaque, dimension-checked source problem with `n>=1`. For seed `s=0,1,2,...`, the algorithm adds the final auxiliary variable `t`, appends zero to every original monomial exponent list, and appends

```text
t - (x_0 + s*x_1 + ... + s^(n-1)*x_(n-1)) = 0.
```

Original variables retain their order and coordinates. F4 computes the augmented lex basis; the existing shape checker tries to represent **all original coordinates** as polynomials in `t`. A candidate succeeds only if its full F4 ideal witness, actual-row shape provenance, all substitution remainders, and all Sturm real-root intervals check. A failed shape attempt is recorded diagnostically and the next seed is tried. The coefficient at `x_0` is one even when `s=0`; later coefficients are zero in that case. All powers and coefficients are exact symbolic binary integers/rationals.

For any source solution `a`, the augmented graph has exactly the solution `(a,L_s(a))` above it. Conversely any augmented solution projects to a source solution. This graph correspondence is a bijection over both the complex and real fields and does not assume radicality. Once the augmented ideal has a checked shape representation, every augmented solution is enumerated and projection simply keeps the first `n` coordinate expressions. Projection neither loses nor duplicates points because the discarded `t` is already fixed by the original coordinates. There is no inverse coordinate transformation.

The checker takes a **separately supplied source `Problem`**. It recomputes the complete ordered augmentation from that problem and seed, checks its source description, dimension, graph relation and lifted inputs, then calls `@f4.check(augmented_variables, recomputed_inputs, groebner_certificate)`. Thus a basis verified only against some other source is insufficient. The shape basis must equal the certified F4 basis; the projection dimension must equal the original variable count. Original lifted inputs and the graph relation are additionally substituted directly modulo `g`. `check_separation_result` also binds a separately supplied `SeparatedSet` payload. Unit-ideal proofs have the same source/augmentation/F4/projection binding through `check_separation_unit`.

`projected_points` returns shared-parameter tuples containing only original coordinate expressions. `check_projected_point_result` binds their parameter, source, full solution proof, and projection. `evaluate_projected_coordinate` delegates to the bounded-degree coordinate materializer while rejecting the auxiliary coordinate index. `check_projected_coordinate_result` binds the source problem, projected point, coordinate index and numeric payload together.

The search has two independent, replenishable budgets. `attempt_fuel` counts newly initialized seeds in that call. `work_fuel` counts F4 steps (including finalization) and Sturm interval nodes across candidates. `SeparationPaused(state, AttemptLimit | ComputationFuel)` retains the current F4/isolation state and the next unused seed; resuming with zero attempt fuel can finish an existing candidate but cannot start another. Initialization, exact field operations, full witness checking and substitution within these steps are not bit-operation or wall-clock bounds. History from `failed_attempts` is diagnostic and is not a proof that no future form works.

For finitely many distinct points, equality of `L_s(a)` and `L_s(b)` means that the nonzero polynomial `sum((a_i-b_i)*s^i)` vanishes. Each pair therefore has finitely many bad seeds. The classical radical shape lemma motivates this search, but point separation alone does not certify a nonradical quotient algebra is generated by `t`. The implementation does not certify radicality or zero-dimensionality in advance and makes **no unconditional success claim for all zero-dimensional ideals**. In particular `{x^2,y^2}` remains non-shape for the tested seeds `0..3` despite having a real point. Its finite search is paused rather than declared empty. Positive-dimensional input behaves similarly. `SeparationNoSolutions` is returned only for a checked augmented unit ideal; an accepted shape with no real roots returns a completed empty projected set instead.

The [independent separation generator](../../tools/generate_realvariety_separation.py) uses SymPy lex bases and `solve_poly_system`, compares the complete projected real tuple set exactly, and retains [27 seed attempts across 12 systems](realvariety-20261116-separation-fixtures.json): **9 completed systems with 27 real points**, **2 paused systems**, and **one unit ideal**. `{x^2-1,y^2-1}` rejects seeds 0 and 1 and succeeds at seed 2 with `g=t^4-10t^2+9`; `{x^2-2,y^2-3}` rejects seed 0 and succeeds at seed 1 with `g=t^4-10t^2+1`. Both original systems were unsupported by the direct shape entry point. Additional cases include three variables, repeated one-variable roots, independent and dependent quadratic irrationalities, rational points, and a nonunit ideal with no real solutions.

Negative tests reject a correct proof from another problem, rewritten source metadata without matching lifted inputs, recomputed foreign augmentations paired with an old F4 witness, a foreign valid F4 basis/solution certificate, changed seed/relation/input order/dimensions, wrong projection size, a missing root, and materialization of the discarded auxiliary coordinate. Exact source binding also applies to unit certificates. This completes the bootstrap from an originally non-shape polynomial system through augmentation, F4, checked RUR, projection, and exact individual coordinates.

A [three-variable eight-point SymPy pilot](realvariety-20261116-separation-pilot.json) is retained separately. An extended MoonBit regression containing that pilot was interrupted after observing 206 seconds on its task-owned test runner without a final summary. It is excluded from the verified regression; no isolated cost attribution or MoonBit correctness verdict for that extra pilot is claimed. The final verified set includes three-variable examples with smaller quotient dimension. No scalability improvement is claimed.

## Independent fixtures and boundaries

The [generator](../../tools/generate_realvariety_fixtures.py) uses SymPy 1.14.0's reduced lex basis, `solve_poly_system`, exact real roots, and rational isolating intervals. It checks equality between the full real solution tuples from `solve_poly_system` and those reconstructed from the independent shape representation. The retained [fixture artifact](realvariety-20261116-fixtures.json) has **17 supported systems with 30 real points**, **one unit ideal**, and **three unsupported systems**. Every supported MoonBit case checks the F4 ideal witness, expected eliminant and coordinate polynomials, all original-input substitution remainders, full root coverage, and exact parameter equality to the SymPy intervals.

Examples include nonrational coordinates, rational/nonmonic input coefficients, three variables, nonlinear original equations from which F4 must derive linear shape rows, repeated eliminants, a one-variable fourth-power equation, a shape with no real roots, closely spaced rational roots, and close irrational roots around one. Unsupported cases include a four-point zero-dimensional system whose last coordinate fails to separate its points and positive-dimensional systems.

The generator also creates **62 coordinate-materialization fixtures**. The full characteristic polynomial is independently computed as `resultant_t(g(t),z-h_i(t))`, including repeated factors for nonradical eliminants; the selected numeric coordinate is independently represented by its SymPy minimal polynomial and a rational isolating interval. Coefficients beyond machine-word bounds are encoded by signed binary magnitudes in test fixtures, so they do not silently truncate. Every materialized coordinate matches both oracles, and its value-bound certificate is checked.

Adversarial tests reject fabricated shape coordinates, absent chosen rows, changed variable counts, an extra unsatisfied basis constraint, altered eliminants, a missing real root, duplicated root intervals, invalid point parameters, and zero unit witnesses. A mixed row such as `x*y-1` is deliberately unsupported by raw extraction; F4 derives `x-y/2` when combined with `y^2-2`, after which the certified path succeeds. Coordinate tests additionally cover zero and constant coordinates, raw degree-17 coordinates reduced modulo a quadratic before evaluation, exact sample-fuel boundaries, unfinished refinement after sampling, wrong valid conjugates, out-of-source intervals, a degree-too-high polynomial matching all samples, and normal proofs paired with wrong payloads.
