# GF(2) monotone nullspace construction, 2026-11-17 night sprint

Adopt `db9690f`: build ordered nullspace vectors by walking canonical pivot
rows and variable indices together. The public baseline is
`ab22a4a22625f4beb2bd2a49b836f769c941ef90`; the frozen public-only harness is
`d90ed45`. This was one mechanism, one measured implementation, no follow-up
and no threshold tuning.

## Actual call path and scope

The initially suggested `gf2.multiply` has no external producer call sites in
the repository. It still delegates to the generic matrix implementation and
is used internally by `gf2.check_certificate`. Adding an unused specialized
product would not establish an ordinary-consumer improvement, so no product
kernel was added and that independent checker remains untouched.

The optimized private `nullspace` is reached by:

- `cohomology.compute -> gf2.nullspace_factor -> nullspace`;
- `gf2.solve_factor -> gf2.nullspace_factor -> nullspace`;
- `gf2.solve -> nullspace`.

Production changes are confined to `src/gf2/solve.mbt`. No cohomology or CSS
integration edits were needed. `gf2/kernel.mbt`, all generic certificate
checkers, public API metadata and consumer source are byte-unchanged.

Previously, nullspace construction called `row_for` from the beginning of the
pivot-row list when deciding every free variable, and again for each
coordinate of each free-variable vector. The two internal callers supply
strictly increasing canonical RREF pivots. `free_columns` now merges the
ascending variable list with those pivots; `nullspace_vector` makes the same
monotone walk for each basis vector. A pivot-row cursor advances at most once
per walk. This removes repeated visits to prior pivot-row list nodes while
preserving ascending free-variable order and every basis coefficient.

This is a traversal-count improvement, not a constant-time numeric-index
claim: Nat comparisons and coefficient `nth` traversals remain recursive ADT
operations. Boolean arithmetic, RREF pivot selection, operation logs,
transforms, rank witnesses, affine particular solutions, errors and dimension
checks are unchanged. No primitive numbers, arrays, mutation, FFI, new public
API or cache fields were added to production.

## Frozen comparison and independent checks

`src/cmd/nightgf2bench` is identical in baseline and candidate. All builds and
heavy checks use the shared Git-directory lock via `tools/measure --cpu 4`;
native release builds and test/check commands use `-j 1`, and info has no
`-j`. `tools/compare_field_kernels.py` runs five ABBA blocks per case with
independent processes: ten observations per binary per case, 120 total.
Every stdout, stderr, exit status, duration, compiler version, source manifest,
harness hash, binary hash and affinity is retained in
[monotone-abba.json](night-gf2-20261117-raw/monotone-abba.json).

Whole-process time includes startup, source/host-oracle setup, factorization
where declared, all repetitions, original result/certificate checks and
complete output serialization. No checksum substitutes for equality. The
calibration log predates the final repetition counts and is not comparative
evidence.

The host oracle uses indexed Boolean arrays and Gauss-Jordan elimination,
independent of the production linked-list pivot lookup. It constructs every
ordered nullspace coefficient and complete affine solution. Factor source,
canonical RREF/pivots, U*A=R and both U*Uinv=I identities are checked against
host multiplication and the original public checker. The reuse cases prepare
the factor once, as the API permits; the setup case reconstructs it and checks
its full certificate on every repetition.

The ordinary consumer is degree-one cohomology of the existing seven-vertex
triangulated torus (21 edges, 14 triangles). Host face deletion constructs
incidence independently of production boundary/coboundary functions. Host
RREF/nullspace, column selection and matrix inversion construct the expected
coboundaries, two representative classes, complete basis, inverse basis and
incoming coordinates. Every repeated public `compute` result compares the
full certificate and all those expected fields; the unchanged public
`check_result` is also called each time, in addition to `compute`'s internal
completion check. Both embedded rank witnesses receive independent host
matrix checks. Serialization occurs once after the checked repetitions.

## Results and decision

Native release complete-process medians in milliseconds:

| Case | Repetitions | Baseline | Monotone | Before / after | Block ratio range |
| --- | ---: | ---: | ---: | ---: | ---: |
| Tiny 1×3, rank one | 500,000 | 119.040 | 83.388 | 1.428 | 1.370–1.506 |
| Sparse 8×32, gapped pivots | 2,000 | 197.213 | 66.415 | 2.969 | 2.862–3.091 |
| Dense 16×32, mixed pivot/free columns | 2,000 | 208.906 | 61.416 | 3.402 | 3.113–3.650 |
| Dense solve, factor reused | 2,000 | 247.568 | 95.096 | 2.603 | 2.409–2.641 |
| Dense solve, fresh factor + certificate | 500 | 169.581 | 130.134 | 1.303 | 1.264–1.332 |
| Torus cohomology, full checker cost | 200 | 237.404 | 231.424 | 1.026 | 0.997–1.048 |

All 120 runs passed full-result checks. All five blocks favor the candidate
for the first five cases. The torus consumer has a small median difference
and one losing block: treat its improvement as uncertain. The primitive and
solve results are consistent, including tiny and fresh-setup controls, and
the optimized function is already used by the real cohomology producer.
Adopt on that evidence; do not present a 3.4× primitive gain as a 3.4×
cohomology gain.

The small public consumer result is consistent with substantial work remaining
in factorization, basis inversion and generic certificate checking. Their
individual time shares were not profiled, so that explanation remains an
inference. No memory or universal-shape performance claim is made. Large
coefficient-index traversals remain a possible future bottleneck, outside
this trial's scope.

## Correctness, API and handoff

New white-box tests compare the frozen legacy lookup route and an independent
indexed Boolean oracle over 42 cases: empty and zero-width matrices, tall and
wide shapes, sparse gapped pivots, dense/dependent patterns and free-variable
ordering. They also preserve zero-dimension Unique/Affine behavior and
malformed RHS rejection. Existing exhaustive binary matrices through 3×3
with every RHS, seeded larger matrices and forged-certificate rejection tests
remain in place.

Scoped GF2, cohomology and CSS suites pass 195/195 tests on each of native,
JavaScript and wasm-gc in release mode with warnings denied. `moon info
src/gf2` leaves public metadata unchanged; the repository purity gate passes
327 kernel files, and repository-wide `moon check --deny-warn -j 1` passes.
Full validation command output is retained in
[validation.json](night-gf2-20261117-raw/validation.json).

Baseline/candidate ELFs and exact source snapshots are handed to the root
artifact archive; [artifacts.json](night-gf2-20261117-raw/artifacts.json)
records their hashes and build/measurement commands. The worker does not push,
merge, deploy, modify shared indexes or remove worktrees. Integration, final
push and archive cleanup belong to the root task.
