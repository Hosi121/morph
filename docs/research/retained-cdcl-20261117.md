# 理論衝突の後もCDCLの状態を使う

[研究記録](README.md) / [非線形実数SMT](../handbook/algebraic-solving.md)

前段階の[円柱の枝刈り](incremental-cad-20261117.md)では、算術候補を早く判断できるようになった。
今回は、算術上不可能なBoolean割当てを拒否するたびにCDCLを最初から始める費用を減らす。
同じBoolean探索へ理論節を追加し、学習節・trail・watch・累積統計を保持する。

## 単調な節追加

`cdcl.run_incremental` は、SATモデルとともに探索の継続状態を返す。
`cdcl.add_clause` は新しい入力節を追加し、その状態から探索を続ける。
通常の `start / run / run_measured` と既存の証拠形式は維持した。
途中のPaused状態へ追加する場合も扱う。
節や変数の削除、仮定のpush/popは今回の範囲に含めていない。

追加時には重複literalを除き、恒真節を捨てる。
恒真節の途中で現れた変数も、末尾の変数もモデルの対象へ登録する。
既存の学習節とproof履歴、trailとlevel、watch索引、値のtrieを保持し、
割当て済みliteralのイベントを再投入する。
新しい節で本物の衝突が起きたら、既存のfirst-UIPとbackjumpが不要な割当てを戻す。
矛盾した割当てを保持し続けることを状態再利用とは呼ばない。

## 遅れて単位節になる場合

追加した時点で満たされている節でも、後のbackjumpでその充足literalが未割当てになる。
残りのliteralが既に偽なら、その節は新たな単位節になる。
追加直後のイベント再生だけでは、この変化を見落とす場合がある。

外から追加した節の一覧を持ち、追加時とbackjump時に、その一覧の単位節・衝突を再確認する。
得られた含意と理由節を通常の伝播へ渡す。
元からあった節や学習節のwatchを作り直さず、追加節の再確認だけを行う。
追加節が増えればこの走査の費用も増えるため、性能上の限界として計測する。

## 理論節とRUPを混同しない

追加した入力節は、元のCNFから導出した節とは限らない。
非線形SMTでは、それぞれの理論節を元の算術atomへ結び付け、CADで不可能性を検査してから追加する。
RUPの履歴へ、証明のない入力節を導出結果として紛れ込ませない。

以前の学習節は、以前の入力からRUPで正当化されている。
入力節を追加した強いCNFでも同じ単位伝播による矛盾は保たれる。
したがって、最終反証は**元のCNFと全ての検査済み理論節**に対して、保持した学習履歴を順に再検査する。
理論節を外した元のBoolean CNFだけがUNSATだとは主張しない。

SMTのTheory状態には、その候補を出したCDCL cursorを保持する。
算術探索がPausedでもcursorを捨てず、理論衝突が確定した後でのみ節を追加する。
公開するモデル・理論補題・最終反証の構造と、元の問題への束縛は変えていない。

## 比較する経路

| 入口 | 算術探索 | 理論衝突後のBoolean探索 |
| --- | --- | --- |
| `realnlsmt.start_retained` | 円柱の枝刈り | 同じCDCLへ節を追加 |
| `realnlsmt.start_restarting` | 円柱の枝刈り | 新しいCDCLを開始 |
| `realnlsmt.start_full` | 完全CAD | 新しいCDCLを開始 |

`boolean_restarts` は開始時を除く再始動回数を返す。
状態保持のテストでは、衝突後のcursorが `add_clause` の結果と一致し、累積統計も保持されることを確認する。
単に同じ最終SAT/UNSATを返すだけを、再利用の証拠とはしない。

計測は同じrelease artifactで、再始動→保持→保持→再始動を交互に実行する。
準備・探索・外部のモデル/反証検査を含め、SMT内の通常の理論補題検査も含む。
Booleanの比重が大きい定数原子の対照と、二次多項式、SAT/UNSAT、衝突のない対照を分ける。
ソース `dfc2dbd`、CPU 4固定・共通lockで直列化したrelease版を使った。
12入力・3 backendについて、ABBAを3回、各方式6回ずつ、計432回を検査付きで実行した。
各起動は独立したプロセスであり、VMの定常状態だけを測った値ではない。

## 独立検査と採用判断

CDCL単体は全729個の3変数の節対と、3,543個の増分prefixを独立な真理値表へ照合した。
別担当はPythonの全割当て列挙で160スケジュール・1,440入力prefixの期待値を生成し、
watch/scanningの両方で2,880回の完了結果を各backendで確認した。
探索を0・1・2・3・100 stepだけ進めてから節を追加する場合も含む。
backjump後の単位節、watch bucket処理中の追加、SATからUNSATへ残る学習履歴を検査した。

SMTでは既存の正確なZ3参照41入力を新しい通常経路で検査し、再始動方式との比較も行った。
入力節や必要な理論補題を外した反証、未完のRUP履歴、別の元問題への差替えは拒否する。
[独立入力と全割当ての記録](../measurements/retained-cdcl-review-oracle-20261117.json)を保存した。
これらは有限検査であり、CDCLやCAD全体の形式証明ではない。

以下は準備・探索・最終検査の全体時間の中央値。比が1未満なら保持方式が遅い。
差の重なる例を、個別の改善として扱わない。

| 入力 | native 再始動→保持 | native比 | JS比 | WasmGC比 |
| --- | ---: | ---: | ---: | ---: |
| 定数原子・15衝突 | 1.877→1.111 ms | 1.69× | 1.39× | 1.48× |
| 定数原子・63衝突 | 25.856→8.318 ms | 3.11× | 1.97× | 2.69× |
| 二次式のUNSAT・7衝突 | 36.441→36.190 ms | 1.01× | 1.00× | 1.02× |
| 二次式のUNSAT・15衝突 | 189.702→164.792 ms | 1.15× | 1.01× | 1.01× |
| 二次式の代替SAT・14衝突 | 33.922→35.338 ms | 0.96× | 1.03× | 0.97× |
| 二次式の代替SAT・30衝突 | 151.163→151.604 ms | 1.00× | 1.08× | 1.07× |
| 一変数SAT・衝突なし | 0.402→0.393 ms | 1.02× | 0.94× | 0.96× |
| 円周SAT・衝突なし | 0.661→0.744 ms | 0.89× | 0.99× | 0.97× |
| 従属4変数UNSAT・1衝突 | 80.713→77.940 ms | 1.04× | 1.03× | 1.05× |

定数原子の対照は `OR(k < 0)`、k=1..4または1..6であり、Boolean再始動の比重を調べる人工入力である。
二次式のUNSATは `OR(x²+k < 0)`、代替SATはその末尾に `x≥0` を加えた式。
単に定数式の結果を全ての非線形問題へ一般化しない。

63衝突の対照は、どのbackendでも再始動63→0、SMT遷移3,853→243となった。
nativeの全体時間は25.856→8.318 ms、最小の再始動時間/最大の保持時間でも2.27倍だった。
JSは同じ保守的な比で1.77倍、WasmGCは2.22倍。
二次式の代替SAT・30衝突も遷移1,563→648へ減ったが、nativeの全体時間はほぼ同じである。
算術とCAD証拠検査の費用が残ることを確認した。

衝突のない入力は両方式で同じCDCL/CAD遷移を通るが、プロセス間の計測には揺れがある。
たとえばnativeの円周SATの中央値は0.88倍だった。
二次式の代替SAT・14衝突にもnative/WasmGCで約3〜4%遅い中央値があり、改善を主張しない。
予備計測で見えたWasmGCの二次式UNSATの大きな遅れは、最終比較では両入力とも約1.01〜1.02倍で範囲が重なった。
予備値も `.tools/retained-cdcl-20261117/pilot*` に残す。

通常の `start` は `start_retained` を使う。
単調な理論節追加に対して探索状態を保てることと、Booleanの比重が高い対照で全backendの改善を確認したためである。
一般の非線形問題が速くなったとは結論せず、再始動経路を比較・切替用に残す。
学習履歴を保持した最終RUPの追加節数も記録し、検査費用を探索時間の外へ隠していない。

## 残る課題

全Collins射影と候補ごとのCADは残る。
Boolean探索を再利用しても、算術と証拠検査が支配的な例の全体時間は大きく減らない。
局所射影、算術側の学習状態、より小さな理論衝突節、push/popや仮定は別の段階である。
