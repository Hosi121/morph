# 有理係数の F4 Gröbner 基底、2026-11-16

[ドキュメント](../README.md) / [研究・探索記録](README.md)

[研究・探索記録](README.md) / [既存 Gröbner 実装](../../src/groebner/groebner.mbt)

この実装は既存の lexicographic な有理係数多項式を使い、複数 S ペアを同時に Macaulay 行列へ変換する F4 の基本経路を追加する。既存 Buchberger の呼び替えではなく、symbolic preprocessing と実際の exact RREF が S ペア処理を行う。手書き計算核は不変 ADT・Bool・Peano Nat・Chain・クロージャだけを使う。

## 公開 API

[生成 API](../../src/f4/pkg.generated.mbti)、[driver](../../src/f4/f4.mbt)、[symbolic preprocessing / Macaulay 行列](../../src/f4/macaulay.mbt)、[ideal witness と独立検査器](../../src/f4/witness.mbt)。

- `f4(variables, inputs, fuel)` は `Complete(Basis)` または再開可能な `Paused(State)` を返す。
- `start` / `step` / `run` で同じ状態を段階的に進める。
- `variables(basis)` は変数数、`polynomials(basis)` は monic reduced lex Gröbner 基底。単項式順序は既存 polynomial の「最初の変数が最大」の lex に固定する。
- `certificate(basis)` は各基底多項式と、元入力の順序に対応した係数多項式列を返す。
- `verify(basis)` または `check(variables, inputs, certificate)` は、入力 ideal と基底 ideal の両包含および全 S ペアの零剰余を別経路で検査する。
- `history(basis)` / `state_history(state)` は各 batch の選択ペア数、seed / reducer 行数、列数、新規行数を返す。これは構造上の記録であり性能指標ではない。

`State` / `Basis` は検証済み入口から構築する。証拠は公開データなので、改ざんしたものも検査できる。入力の変数数不一致は `DimensionMismatch`。内部の形や行変換が一致しなければ `InternalInvariant` を返し、黙って計算を続けない。

## 真の F4 経路

各段で、現在の未処理 S ペアのうち先頭単項式 LCM の全次数が最小のものをすべて選ぶ。一つのペアにつき、先頭項が一致するよう正規化した二つの基底倍を seed 行にする。symbolic preprocessing は未処理の単項式を走査し、現在の基底の先頭項で割れるものごとに、その単項式を先頭に持つ基底倍を一行追加する。追加行の末尾に現れる単項式も閉包に含める。

列を lex 降順の単項式、行を準備した多項式の有理係数として実際の Macaulay 行列 `A` を構成する。`A | I` の exact RREF を既存 `linear.rref` で求め、左側を多項式へ戻す。現在の基底の先頭項で割れない新規先頭項を持つ非零行を追加し、既存行および同じ batch の追加行との新しい S ペアを作る。通常の多項式長除法を各 S ペアの処理に使う経路はない。

これは [Faugère, *A new efficient algorithm for computing Gröbner bases (F4)*, 1999, §2.3](https://wstein.org/129-05/refs/faugere_f4.pdf) の基本構成に対応する。現時点では pair criteria、Simplify cache、疎行列専用消去、DRL や sugar strategy を実装していない。完了時だけ通常の多項式除算で最小基底を interreduce し、monic・lex 降順に整える。

具体例 `x²−y, xy−1, x−y²` の最初の段は二つの S ペアを選択し、seed 四行と追加 reducer 一行から、単項式六列の行列を作る。そこから一つの新しい基底行を得る。この記録は [compiler-generated snapshot](../../src/f4/batch_trace_wbtest.mbt) で固定し、複数ペア・追加 reducer の実在を検査する。

fuel は「Macaulay batch 一つ、または最後の interreduction 一回」につき一単位。symbolic preprocessing や一回の行簡約の内部時間・メモリ量を直接制限するものではない。fuel ゼロなら状態をそのまま `Paused` として返す。

## ideal-membership 証拠

各行には `g = Σ h_i f_i` の係数多項式 `h_i` を保持する。初期行は単位ベクトルを入力の monic 正規化とともに scale する。基底倍を追加するときは witness も同じ単項式で掛ける。`A | I` の右側には行変換係数が残るので、これを使って新しい行の witness を線形結合する。生成した行は左側の係数行列から復元した多項式と一致することも確認する。最後の interreduction では多項式除算の quotient から witness を更新する。

独立検査器は F4 の行列・symbolic preprocessing・探索状態を参照せず、次を検査する。

1. 元入力の全多項式が、提案基底による通常の多項式除算で零剰余になる。
2. 基底の各行が、元入力と提示された係数多項式列の正確な線形結合に一致する。
3. 提案基底の全 S ペアが零剰余になる。

一と二が ideal の一致を、三が Buchberger の判定条件を与える。入力の零剰余だけを満たす大きすぎる ideal、単に元入力を並べた非 Gröbner 基底、改ざん・欠落・次元不一致の witness を試験する。検査器は Gröbner 基底の性質を検査し、提示された任意の証拠が reduced であることまでは要求しない。生成器の reduced 正規形は独立 CAS との一致でも検査する。

## 検証と制約

[独立 SymPy fixture generator](../../tools/generate_f4_fixtures.py) は SymPy 1.14.0、`QQ`、`lex` を明示する。二〜四変数の固定系十五件と、固定 seed の二変数二次系四十八件、計六十三件で reduced 基底全体を照合する。同じ入力を既存 Buchberger にも渡して結果を照合する。各出力の ideal witness と S ペアも検査する。空 ideal、零入力、定数からなる単位 ideal、非定数生成元から単位 ideal に至る系、同じ先頭項の異なる入力、非 radical ideal、有理数係数を含む。

初期 suite は native・JS・Wasm GC の各 backend と `--deny-warn` で検査した。

| 検査 | 結果 |
| --- | --- |
| native / JS / Wasm GC、`--deny-warn` | それぞれ 71 passed / 0 failed |
| purity gate | 130 kernel files passed、この worktree の Blossom と Zassenhaus を含む |
| SymPy fixture 再生成 | formatter を含めた生成結果の byte 一致 |

コマンド・生ログ・SymPy fixture data は `.tools/f4-20261116/` に保存する。公開 `.mbti` は `moon info src/f4` で生成する。root 側が共有 inventory と文書 navigation を更新する。

```sh
tools/measure --cpu 6 python3 tools/generate_f4_fixtures.py
tools/measure --cpu 6 tools/moon test src/f4 --target native --deny-warn
tools/measure --cpu 6 tools/moon test src/f4 --target js --deny-warn
tools/measure --cpu 6 tools/moon test src/f4 --target wasm-gc --deny-warn
python3 tools/audit_purity.py
tools/measure --cpu 6 tools/moon info src/f4
```

基本 F4 がこのプロジェクトの不変 ADT から構成でき、元入力までの ideal-membership witness を行簡約をまたいで保持できた。実装は dense な不変リスト行列を使い、identity block と witness が大きくなる。疎行列を使う高性能 F4 との性能比較、大規模 benchmark、最大メモリ量・スタック上限、機械化した正当性・停止証明は今回の成果物に含めない。有限検査の成功を、任意入力に対する形式証明や既存 Buchberger より速いという主張に読み替えない。
