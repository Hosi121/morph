# Fraction-free Bareiss determinant experiment

[ドキュメント](../README.md) / [研究・探索記録](README.md)

**Current integration:** [the ordinary determinant path now uses Bareiss](bareiss-adoption-20261116.md). The following records the isolated experiment before adoption.

The isolated `src/bareiss` package implements an integer Bareiss determinant and a QQ wrapper which clears denominators with one positive LCM per row. It leaves `linear`, `rowreduce` and `berkowitz` unchanged. The initial correctness commit `e3b9b96` passes 134 tests per backend. The precision extension passes **140 tests on native, JS and WasmGC**, including 138 independent determinant fixtures. The measured determinant cohorts support adoption of this separate algorithm; changing the ordinary path remains root's integration decision.

[Integer kernel](../../src/bareiss/bareiss.mbt), [rational wrapper](../../src/bareiss/rational.mbt), [generated API](../../src/bareiss/pkg.generated.mbti), [independent generator](../../tools/generate_bareiss.py), [paired benchmark cohorts](../../src/bareiss/cohort_bench_wbtest.mbt).

The trailing matrix recurrence is `(pivot*a_ij-a_ik*a_kj)/previousPivot`, starting with previous pivot one. [Bareiss, *Sylvester's Identity and Multistep Integer-Preserving Gaussian Elimination*, §I equations (6)–(8), §II.A.2 and the pivot discussion/Figure 3](https://www.ams.org/mcom/1968-22-103/S0025-5718-1968-0226829-0/S0025-5718-1968-0226829-0.pdf) derives integer preservation and the determinant identity, and discusses row interchange when a pivot vanishes. This implementation uses the one-step algorithm with immutable shrinking trailing matrices. Moving the first available nonzero pivot row to the front records the parity of every adjacent row interchange. A missing pivot makes the determinant zero; negative pivots are retained as signed previous divisors.

Every integer division uses magnitude quotient/remainder and explicitly requires remainder zero. `exact_divide` returns `ZeroDivisor` for divisor zero and `InexactDivision` for a nonzero remainder; there is no rounding. Tests exhaust signed numerators `-16..16` and divisors `-8..8`, and inject an invalid previous divisor into the internal recurrence to confirm an error is reported. Non-square matrices return `NotSquare`; the empty determinant is one. No kernel machine number, array, mutation, FFI or unwrap is used.

For QQ, each row is scaled by the LCM of its canonical positive denominators. All scale divisions are checked exactly. Integer Bareiss is then applied and the signed determinant is divided by the product of row scales, yielding a normalized exact Rational. This wrapper does not invoke field Gaussian elimination.

The independent oracle uses direct Fraction permutation expansion for sizes through five and a separate Fraction Gaussian implementation for six/eight. The two oracle methods agree on every small fixture. Cases include all 81 matrices of size two with entries in `{-1,0,1}`, random rational matrices through five, dense integer/rational six/eight, singular and first-column-zero eight, first/intermediate row pivots and a three-row cycle. Six further 4x4/6x6 cases use full-width 128/256-bit signed coefficients. Two use large nonbinary denominators of similar width, multiplied by 3, 5 or 7. Signed hexadecimal-magnitude adapters preserve every bit; no machine-width conversion occurs. Tests check the new result, `@linear.determinant`, and the frozen WB reference against the independent answer; integer inputs also check `integer_determinant`.

All heavy work uses the shared CPU 10 lock. `.tools/bareiss-20261116/oracle.json` retains inputs and exact answers; `validation.json` and its logs retain commands, UTC completion, return status and nonzero test totals. `frozen-dependencies.json` records byte equality against `a8e7207` for `linear`, `rowreduce` and `berkowitz`. Formatting, API generation, warnings-as-errors, fixture drift and the symbolic-purity gate pass. These finite executable checks are not a formal proof of the compiler or exact-arithmetic implementation.

The eight prebuilt benchmark cohorts are small, integer six/eight, rational six/eight, singular eight, pivot eight and early-zero eight. Each cohort contains two or three matrices. Both algorithms are compiled into the same backend artifact; input construction is outside the timed closure. The candidate measurement includes QQ row-denominator conversion, even for integer-valued matrices, so it compares the practical rational APIs. The 128/256-bit extension is correctness-tested, not benchmarked.

## Frozen reference and repeated measurements

[The WB reference](../../src/bareiss/frozen_reference_wbtest.mbt) copies the original rational field dictionary and RREF/rank/factor determinant body from `a8e7207`. Its benchmark call does not dispatch through `@linear.determinant`, so adopting Bareiss there later cannot make both benchmark sides use Bareiss. The [benchmark driver](../../tools/benchmark_bareiss.py) compares the copied bodies token-for-token with their original definitions, allowing only qualification of the RREF call, and requires the entire RREF dependency to remain byte-identical. Those checks and hashes are retained in `frozen-reference.json`. A deliberate future RREF change therefore requires renewed reference review rather than silently changing the baseline.

The final run used two independent invocations per backend, five SDK samples per benchmark, and adaptive approximately 100 ms batches. All 16 benchmark entries succeed per invocation. Reference and candidate are in the same native ELF, JS program or WasmGC program, and program hashes remain identical across both repetitions. Native C, executables, JS, Wasm and runner metadata are copied under `.tools/bareiss-20261116/executables/` with SHA-256 checks. Source hashes, individual means/deviations, raw logs and repeated-run summaries are retained. The original first experiment, which directly called the unchanged `@linear.determinant`, is separately preserved with its original package source and verified artifact paths under `.tools/bareiss-first-cohort-20261116/`.

The table reports reference time divided by Bareiss time, using the ratio of the medians of two SDK-reported means. Times are per complete cohort invocation, not per matrix.

| Cohort | Native | JS | WasmGC |
| --- | ---: | ---: | ---: |
| Small 2x2/3x3 | 1.83x | 2.12x | 14.35x |
| Integer 6x6 | 2.31x | 3.52x | 16.65x |
| Integer 8x8 | 2.36x | 2.59x | 2.61x |
| Rational 6x6 | 1.86x | 1.95x | 13.94x |
| Rational 8x8 | 1.91x | 2.70x | 7.07x |
| Singular 8x8 | 4.33x | 4.64x | 20.10x |
| Pivot 8x8 | 2.62x | 2.68x | 9.86x |
| Early-zero 8x8 | 69.93x | 172.61x | 710.76x |

All 24 backend/cohort comparisons favor Bareiss in both repetitions. Even `min(reference means)/max(candidate means)` remains above 1.50 for every comparison. That cross-repeat ratio is not a confidence interval. WasmGC and early-zero measurements show substantial runtime/GC variability, so their large point ratios are not stable performance forecasts. Early-zero benefits especially from returning zero before eliminating later columns. Dense native improvements are 1.86–2.36x in these cohorts. The frozen baseline computes full RREF, including work beyond forward determinant elimination; this experiment does not compare against a separately optimized forward-only rational Gaussian algorithm.

The host is an Intel Core Ultra 7 255H, pinned to logical CPU 10 under the common repository lock. Compiler versions are moon `0.1.20261104`, moonc `v0.10.20+65efd5b93`, with explicit release builds. Inputs, targets, sample counts, arithmetic results and reference code are held fixed. Source/artifact equality is checked before and after the experiment. These results support a determinant-path adoption decision for the measured workloads, with exact-value tests also covering large coefficients. They do not establish a universal improvement for every denominator/size distribution. No norm/resultant speedup has been measured or inferred, and no existing linear/RREF/Berkowitz source was changed here.

Reproduce the complete correctness and paired-performance runs with:

```sh
python3 tools/generate_bareiss.py --check
tools/measure --cpu 10 tools/moon test src/bareiss --target native --deny-warn
tools/measure --cpu 10 tools/moon test src/bareiss --target js --deny-warn
tools/measure --cpu 10 tools/moon test src/bareiss --target wasm-gc --deny-warn
tools/measure --cpu 10 python3 tools/benchmark_bareiss.py
```
