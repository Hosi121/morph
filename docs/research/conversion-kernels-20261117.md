# 変換監査からの基礎改善

[研究記録](README.md) / [表現変換の監査](conversion-audit-20261117.md) / [基礎部品](../KERNELS.md)

利用者の継続指示を受け、監査の候補を基準`a63dcbc`から比較しました。
前の4件は[3バックエンド各3,667テストと720公開プロセス比較](late-kernels-20261117.md)まで完了し、`8287a9e`でpush済みです。
この記録では、その後の四候補の採否と検証を分けます。

## 担当別の採否

| 候補 | 採否 | 根拠と制約 |
| --- | --- | --- |
| Smithの商群情報の共有 | 採用 | [同じcokernelを列ごとに作らない](conversion-smith-20261117.md)。多列1.087倍・基底変更1.154倍、各5/5 block改善。空列0.954倍、上位consumerの効果は未確定 |
| 先頭係数1のmonic | 採用 | [canonicalなQQの+1を既存bit形から判定して返す](monic-identity-20261117.md)。初回の疎入力process1.136倍、inner1.119倍全5block。密・多変数・上位全体の小差は未確定 |
| 多段体の定数共有 | 不採用 | [tuple案とtupleを省く一回の再試作](conversion-tower-20261117.md)。深い埋込みの小改善に対しbase/cold/実乗算は不確実。元の構築へ復元 |
| 既約剰余の再還元を省く | 不採用 | [負入力1.041/1.077倍に対し正入力対照の追試0.909倍](modular-signed-reduction-20261117.md)。全5 blockの負値を雑音と断定せず元へ復元 |

全比較はnative release・CPU4・共通ロック・5組のABBAで、起動・準備・全結果と証拠の検査を含みます。
採否にはsourceだけの演算数や、変更していないbranchだという説明だけを使いません。
公開API・値・エラー・context・燃料を保ち、旧実装と独立参照を併用します。

Smithの二つのhelper外、smith coreと証拠検査は変更していません。空列では商群情報を準備しません。
monicは零を先に返し、先頭係数が+1以外なら従来のnonzero/reciprocal/mapへ戻ります。
checker本体が同じでも、共有するmonic算術は変わるため、旧monicとFraction期待値を別に照合しています。

## 見送りも再利用できる形で残す

多段体はソース上の構築呼出木を減らせても、tupleのheap/参照カウント、構造Eq、scalar検査と出力の費用が残りました。
初回はJSONのRepr escapeで比較開始前に停止しました。比較sampleは0で、旧CLI/ELF/失敗ログを保存し、
両側を同じ修正CLIで再buildしてから有効な比較を行っています。失敗分を成功sampleへ混ぜていません。

剰余案は同じ実装の追試と同before ELFのA/Aを保存しています。A/Aで変動があっても、対照の負値の原因が確定したとは扱いません。
二つの棄却案は本体を基準のbyte列へ戻し、旧oracle・独立fixture・再現patchと各target検査を残しました。

## 記録の検査も通常の保守へ

[check_evidence.py](../../tools/check_evidence.py)を追加し、共通形式の比較記録の圧縮前後hash、全ABBA slot、
stdoutとpayload、全結果、標本から再計算した集計値、byte位置付き検証ログを通常の`tools/check`へ接続しました。
改変・欠落・出力不一致・集計不一致・log重複など12件の負例/正例を含み、Pythonは計55テストです。
過去の実行を再現したことや、数学的な正しさをこの整合性検査だけで証明したことにはしません。

担当別の最終scoped検査と、親が固定した統合ソースの逆依存検査・公開比較を分けて記録します。
