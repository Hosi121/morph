# 商構成の試作と採否

**現状：商構成の本体とテストは保持しています。** 簡単化の際に一度撤去したが、一般の商環・単元判定・検証済みの体との接続という依頼の中心まで削る判断だったため復元した。
`quotient` と `quotientfield` は既存の数体・有限体を置換しない試作である。未使用であることや行数だけでは、その数学的役割を不要と判断しない。
比較専用CLIは通常ソースから外し、全出力・測定ソース・検証ログは保存する。再計測には固定版 `86cee8e` を使う。

[Phase 1の監査](mathematical-constructions-20261118.md)を受け、Phase 2–4を実装・評価した記録。
測定ソースは `cf08aaa8cb9fd1f943094fbd875c36e4eff5eb6b`。既存の galois / numberfield / complexfield の本体・APIは変更していない。

**同じ商構成から複数の環の演算を得る仮説は、小規模な厳密検査で支持された。一方、コード総量削減と既存実装の高速化は達成していない。**
従って新しい共通核は比較可能な試作として残し、既存の最適化済み通常経路を置換しない。

## 実装した最小構成

[quotient](../../src/quotient/README.md) は既存 `rowreduce.Field[A]`、正確な零判定、係数の有効性判定、親キー、monic正次数法fから `Context[A,K]` を作る。
型変数Kはキーの型であり、数式の係数体Kとは別である。係数体の法則、validな係数の演算閉性、同一キー間の辞書・零判定の一致はtrusted interface contractとする。
実行時の型推測、キャスト、一般の体公理検査器は追加していない。

| 一度実装した知識 | 導出・利用するもの |
| --- | --- |
| monicな法の先頭項相殺 | 正規化、積の法還元。一意な次数制限代表、先頭逆数・商の生成を省く |
| 次数制限の和・差での保存 | 再還元しない加減算、opaque Residueの境界 |
| 有限次元代数の乗法作用素 | ab=1を既存rowreduceで解く単元の逆。可約商でも非単元を区別 |
| 既約商の非零元は単元 | checked Fieldアダプタの逆元。失敗は内部不変条件違反 |
| F₂の係数表現とmonic法 | Bool ChainのXOR/shift/reduce専用積、汎用積と同じ文脈・結果 |
| Fieldの演算を忘れる | `quotientfield.semiring`。算術定義を足さずSemiringを得る |

逆元では要求時にd×dの行列を生成する。これは独立した既存solverへの接続であり、Euclidより速い逆元の発明ではない。
商の構築時や乗算時に全乗算表を生成しない。代表元は常に具体的な係数列であり、任意の式グラフを遅延する仕組みは試していない。

[quotientfield](../../src/quotientfield) は既存のopaqueな checked NF/galois Fieldを受け取る。未検査の既約性Boolからの昇格はない。
NFの選択根のRootCertificateをキーに含め、元のFieldも保持する。共役根・別根区間を混ぜず、既存の実現・逆元証明書・checkerへ戻れる。
疎な既存多項式と密な係数列の変換は入口・出口だけであり、内部の演算ごとに往復しない。
既存のpublic error/零逆元の契約を変更したのではなく、試作には別のResult/Option APIを設けている。

GF₂専用化は `gf2_context` がBool係数を型で固定し、`Generic/Carryless` を明示選択する小規則である。
policyは親の同一性に含めず、混在時は左オペランドの経路を使う。`gf2.field()`の辞書を再利用する。
機械語bit packingではない。galoisの素体がF₂であることを確認するadapterだけが既存0/1 Binary係数をBoolへ変換する。

## 厳密性・不変条件

- コア4テストは、F₂の次数1〜4の全30monic法（可約も含む）、4,680組の積、全340元の単元判定を検査。一般積・専用積・policy混在を独立な整数bit畳み込み＋長除算・全探索逆元oracleと比較する。
- QQは4法・7入力の正規化と196積を独立整数長除算と比較。分数、次数1、零、冪零元、1+εの逆、非零nonunit、法・係数・親の不正も扱う。
- アダプタ5テストはQQの次数1/2/4、Fpのp=2/3/5、NFの別実根・別根区間、異なるprime/法の零混在を確認。乗算・加算・逆元を既存経路と照合する。
- 非素体の標数2も対照にする。GF(4)の元を係数としてGF(4)[T]/(T²+T+ω)を同じ一般核で構成し、全256積を独立整数GF(4) oracle、16元の逆元を積で確認する。ω²≠ωを保ち、標数2からF₂の係数規則を誤継承しない。
- 一般辞書の法則や任意次数の形式証明ではない。既存の証明器・独立checkerは改変しない。

独立静的レビューで指摘されたvalid carrierの閉性はREADMEへ明記し、finite adapterの別親拒否の直接テストを追加した。
この検査のために定理証明器や新しい型クラス階層は導入していない。

固定ソース `60f8d9e` で、新規3packageの9テストはwasm-gc・JS・native releaseの全てで成功した。
global型検査、84 Pythonテスト、395本体ファイルの純粋性検査、既存形式モデルの検査も通過。
[固定checkpoint・全コマンドとログ](../measurements/quotient-prototype-20261118-validation.json)を保存した。
既存checkerや形式モデルの通過を、新しい一般商構成の形式証明とは扱わない。

## コード量と、追加構造の費用

単位は空行・`//`コメントを除く非空行。括弧・型宣言・署名を含むsource-line指標で、AST LOCや保守時間ではない。生成interfaceは除外する。

| 対象 | 本体の物理行 / code行 | テストの物理行 / code行 |
| --- | ---: | ---: |
| quotient（5ファイル） | 662 / 558 | 379 / 336 |
| quotientfield（2ファイル） | 361 / 291 | 324 / 307 |
| benchmark CLI | 237 / 228 | 0 |

ライブラリは **1,023物理行・849 code行の純増**。旧側の削除は0。新規公開型はContext/Residue/Error/Policyの4型とchecked adapterの3型、計7型である。
測定・oracleのPython、生成interface、文書、証拠は表のライブラリ本体へ含めず、リポジトリには併せて追加されている。
Phase 1の192行のコピー候補や整数商の委譲候補は削除しておらず、削減実績へ加算しない。

一般の正規化・加減算・畳み込み・単元逆元の定義は試作内で各1個で、複数の係数体・法が利用する。専用積は別のカーネルとして1個残る。
**リポジトリ全体では旧実装も存続するため、重複する数学的知識の定義数が減ったとはいえない。** 辞書のslotやwrapper関数を個別の算術算法として数えてもいない。

同じ係数体の新しい法には、context構築の1呼出しと法データだけを追加し、商の加算・積・逆元のコードは0行追加である。
新しい係数体には、その体の辞書・零判定・valid・キーを用意する費用が残る。
実例のGF(4)係数では、既存galois.Fieldを再利用する辞書が15物理行、context構築が7物理行で、商算法の変更は0行。
これはテスト内のtotalなchecked fixture用adapterであり、失敗可能な外部APIを無条件にtotal化する本番adapterの費用まで示したものではない。

再集計は各ディレクトリの本体mbtについて `len(read_text().splitlines())` と `sum(bool(line.split('//',1)[0].strip()))` を取る。
`_test.mbt/_wbtest.mbt`、生成mbti、manifestを分離する。コピー候補・異なる数学的公式・実装のfootprintは合算しない。

## 時間とメモリの比較

[完全な生データ・ソースsnapshot・hash](../measurements/mathematical-constructions-20261118.json)、[保存済み証拠の検査器](../../tools/construction-bench.py)。
Intel Core Ultra 7 255H / WSL2、Moon 0.1.20261104・moonc v0.10.20+65efd5b93、native release、CPU4・共有ロック。
5 ABBA組×7比較=140プロセス、**全3,276,800結果**を独立整数多項式積＋monic長除算と照合した。上位solverや係数辞書をoracleとして再利用しない。

反復はF₂各32,768、Fp 16,384、QQ各8,192。入力はそれぞれ64/25/16組の固定周期で、QQは整数係数・整数monic法。
F₂既存経路には既に採用済みのcarryless、QQにはprepared remainderを含む通常の既存APIを使った。
既存側を遅い汎用参照へ差し替えた比較ではない。

時間は内部ループ中央値msで、入力・証明書・context構築と出力変換は除外し、全結果の確保・保持を含む。
RSSはKiBで、同じ子プロセスのruntime・共通setup・保持・出力変換・JSON表示を含む最大常駐量。
一時確保量やカーネル単独の保持量ではなく、時間列とは測定範囲が異なる。各経路はsetupで比較用の全表現を共通に作る。

| 入力 / 新経路 | 既存 ms | 新 ms | 既存/新のpaired比 | 全process RSS: 既存 / 新 KiB |
| --- | ---: | ---: | ---: | ---: |
| gf2-d4 / generic | 5.362 | 23.120 | 0.238 | 8,192 / 8,192 |
| gf2-d8 / generic | 22.361 | 111.334 | 0.202 | 12,928 / 12,288 |
| fp5-d2 / generic | 13.990 | 14.134 | 0.940 | 5,504 / 5,376 |
| qq-d2 / generic | 4.558 | 5.531 | 0.782 | 6,144 / 4,992 |
| qq-d4 / generic | 26.092 | 26.876 | 0.945 | 13,056 / 10,240 |
| gf2-d4 / fused | 5.425 | 6.188 | 0.892 | 8,192 / 7,168 |
| gf2-d8 / fused | 21.485 | 31.597 | 0.689 | 12,928 / 11,776 |

paired比は各ABBAのA0/B1、A3/B2の計10比の中央値で、単純な二つの中央値の比とは異なる。1超なら新経路が速い。
RSSは10プロセスずつの中央値で、誤差帯・raw値はJSONに残す。近い差を速度の確定的な優劣とは扱わない。

専用化で一般GF₂経路の大きな遅れは縮まるが、既存carrylessには届かない。
RSSは同程度か小さくなったが、allocatorの累積確保量を測ったものではない。
全process時間も記録しているが、旧側の出力をBoolへ移す変換など表示経路が異なるため、内部乗算の速さへ読み替えない。
QQの小さい整数、固定周期、次数2/4という範囲を、大係数・疎密全般・高次数・逆元性能へ外挿しない。
メモリ・時間はnativeのみ。JS/WasmGCの性能、構築のみの性能、専用Euclidとの逆元比較は未計測である。

## 採否と次の判断

商構成とそのテストは残し、既存経路の一括置換は見送る。旧コードの実際の委譲・削除に至っていないため、簡単化を達成したとは主張しない。
既存の数学的能力や構成の研究目的を維持したうえで、重複した実装・選択肢・中間表現を減らす。能力そのものの撤去をコード削減の成果に数えない。
構成から性質を得ることだけでは、既存の疎表現・準備済み還元・専用二次公式・小カーネルの費用は消えない。

次に本採用を判断するには、一つの実callerを選び、入力境界と証拠を保ったまま旧コードを実際に委譲・削除し、adapterを含むnet LOCと構築込みの費用を測る必要がある。
inverseは高次数ではEuclid等の別経路を残す候補であり、一般核の行列法を無条件に広げない。
最小多項式の探索・座標処理、整数商の誘導写像はPhase 1の別候補として残し、この試作の成果に数えない。

現在のソースで保存済み証拠を再検査する:

```sh
python3 tools/construction-bench.py --verify docs/measurements/mathematical-constructions-20261118.json
```

現在の商構成のテストは `tools/measure --cpu 4 tools/moon test src/quotient src/quotientfield --target native --release --deny-warn -j 1` で実行できる。比較CLIを含む再計測は固定版 `86cee8e` のcheckoutで行う。測定producerのソースも記録内のsnapshotに含む。

全出力を損失なく圧縮保存し、harnessと依存25package・102ファイルのsource、ELFの前後SHA256、各runのRSS/時間を記録した。
`.tools/construction-bench/frozen/constructionbench.exe` はローカルの凍結実行ファイルとして保持する。
履歴の `--verify` は再計測せず、保存された出力・独立oracle・集計・hashを検査する。
