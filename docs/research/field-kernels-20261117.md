# 体の算法の専用化と再利用

[ドキュメント](../README.md) / [基礎部品の最適化](../KERNELS.md)

基準 `4d9e6c4` から、有理数・素体・GF(2)線形代数を独立に調べた記録です。
純粋な不変ADT、厳密な計算結果、元の問題に対する証拠検査を維持しました。
各担当は最大二つの機構、複素積は一案までの有限な探索とし、採否を決めたところで検証・整理へ移りました。

## 採用と見送り

| 経路 | 判断 | 根拠・限界 |
| --- | --- | --- |
| GF(2)専用消去・分解再利用 | 採用、CSS・コホモロジーへ接続 | [専用核の30比較](gf2-kernel-20261117.md)と、下記の変更前後の公開API比較。係数はBool列のまま |
| 有理数の零係数で行を共有 | 採用、`linear`へ接続 | [Fraction 1,539例とABBA](rational-elimination-20261117.md)。単位行列・疎逆行列・整数ホモロジーの逆で改善。密な行列等は未確定 |
| p=2の素体辞書 | 採用 | [未還元入力を含む比較](prime-arithmetic-20261117.md)。直接の混合演算・逆元に改善。Fp多項式全体の改善は示せず、奇標数の小差も未解決 |
| 一般剰余で先に入力と法を比較 | 不採用 | 小さい正規化済み入力には有利だが、GF(2)混合演算が全5ブロックで悪化 |
| 複素積を四つから三つの体の積へ | 不採用 | 下記の5対照のうち4つが悪化。追加の加減算・中間値処理が候補原因だが、内訳は未計測 |

有理数の行共有は型と操作辞書を保つ共通化、GF(2)は体の法則を直接使う専用化です。
構造化の考え方は[体の共通算法と専用カーネル](../handbook/field-kernels.md)にまとめています。
専用化した生成器と、従来の汎用行列積を使う検査器を併用します。

## CSS・コホモロジーの公開API比較

`src/cmd/gf2consumerbench` の同一ソースを基準版と採用版でnative releaseビルドしました。
CPU 4、共有ロック、5組のABBA順、各例20プロセス、合計120の検査済み出力（rank・checksum）が一致しました。
コンパイルを除き、入力構築・既知rankまたは独立配列oracle・通常API・証拠検査を含みます。
両版で各証拠を検査し、既知rankまたは独立oracleと照合します。
旧・新版の証拠の成分やcochain代表ベクトルのバイト同一性は、このベンチマークのJSONでは比較していません。
プロセス時間には起動と一回のwarm-upも含みます。内側の `elapsed_us` とは区別します。

最終の値は[全サンプル・ソースと実行ファイルhash](../measurements/gf2-consumers-20261117.json)に保存しています。
| 公開APIの例 | 旧版 ms | 採用版 ms | 旧 / 採用 | 5ブロックの比の範囲 |
| --- | ---: | ---: | ---: | ---: |
| css-sparse | 45.381 | 14.624 | 3.103× | 2.725–3.390 |
| css-dense | 46.619 | 18.170 | 2.566× | 2.317–2.946 |
| css-singular | 41.205 | 14.037 | 2.935× | 2.853–3.369 |
| css-rectangular | 52.487 | 18.935 | 2.772× | 2.349–3.073 |
| coho-circle | 41.736 | 22.845 | 1.827× | 1.581–2.073 |
| coho-torus | 179.064 | 57.571 | 3.110× | 2.900–3.368 |

CSSは16×16の疎・密・従属行と16×24の矩形、コホモロジーは円周と7頂点トーラスの次数0〜2です。
各反復で既存の証拠を検査します。大規模な符号、最小距離探索、cup積の全積表の計測ではありません。
異なる担当の局所倍率や以前の行列式・整数算術の倍率を掛け合わせません。

初回の接続は `d4bbea7` です。独立レビューで、候補基底のピボットだけを使う箇所にも
変換行列と逆変換の証明を生成していることを指摘され、`4cb13d3` でRREFだけに変更しました。
どちらも最終の汎用証拠検査を通します。初回の生値も
[別ファイル](../measurements/gf2-consumers-first-integration-20261117.json)に保存します。
二系列の小差だけを最後の変更単独の効果とは扱いません。

## 複素積の不採用案

`(a+bi)(c+di)` の実部を `ac−bd`、虚部を `(a+b)(c+d)−ac−bd` とする試作を、
従来の四積と同じnative artifactで比較しました。五つの正確な同値照合と混合体の拒否を確認し、
フィールドの妥当性検査・文脈照合・検査付き要素生成は両方に保ちました。

| 対照 | 四積の平均 µs | 三積の平均 µs |
| --- | ---: | ---: |
| Q(i) | 9.64 | 24.62 |
| 二次数体 | 271.13 | 333.19 |
| 四次数体 | 771.49 | 1160.00 |
| 実部だけ非零 | 30.72 | 55.92 |
| 相殺のある一例 | 206.02 | 155.51 |

SDKの適応bench一回の試作比較で、入力生成は内側の区間外、各値10サンプルです。
正しさの照合は別テストで行いました。これは不採用判断用であり、最終公開APIの高速化の証拠ではありません。
[試作ソース](../measurements/complex-product-20261117-trial.mbt.txt)、
[生ログ](../measurements/complex-product-20261117-trial.txt)、
[条件とhash](../measurements/complex-product-20261117-trial.json)を保存し、本体は元に戻しました。
相殺の一例だけに合わせた追加dispatchは行っていません。

## 比較の保守と再現

有理数の変更は、古いBareiss比較の参照が現行の `rowreduce` 全ファイルに依存していることも検出しました。
元のソースのバイト列とWB専用の旧RREFを凍結し、元の四つのhashを維持しました。
正規化した関数宣言と補助型を照合し、11種類の意図的変更を拒否します。
型や共有算術は共通のため、過去のELFそのものや全依存を固定した性能を保証するものではありません。
詳細は[参照ロック](../measurements/bareiss-20261116-reference.json)です。

各担当の元のコミットIDは計測時の来歴として残しています。公開mainの同じパッチは次のとおりです。

| 担当の元ID | mainの対応ID | 内容 |
| --- | --- | --- |
| b67e9ab / 2f6b4df | 59b0867 / 3212198 | GF(2)核・右辺だけの一回solve |
| 5edf9ad / 2e02abe / 566ada5 | 82fdd9d / 81bfa35 / ba9417b | 有理数の行共有・比較 |
| cf38549 / 5c8577a / 56eb8bf | cd5a505 / 0b7c8e3 / 56eba65 | 剰余試作・標数2・試作の撤回 |
| e36fe64 | e2453f7 | 旧Bareiss参照の独立化 |

`git show cd5a505` で不採用の剰余案も復元できます。
比較driverは `tools/compare_field_kernels.py`、専用核は `tools/measure_gf2_kernel.py` です。
driverは同一harness・全非時間出力・実行ファイルのhashを確認し、全生値とブロック別比を残します。
未変更ELFの対照でも数%の揺れがあるため、小差を改善や無回帰の保証へ読み替えません。

## 検証と残る範囲

独立したGF(2)配列oracle、Python Fraction、未還元の素体入力、既存証拠への改変検査を用いました。
各担当の有限テストは各記録にあります。統合時は旧・現のimport graphの逆依存と、
全体の型・API・純記号制約・既存Lean対応を検査します。
新しい核全体の形式証明、配列・機械語への置換、メモリ削減の測定は行っていません。


統合コード `af279b4` の84 packageは各3,545テスト×3対象で通過しました。
全体の保守・型・公開API・純記号制約・既存Leanも通過しています。
[実行範囲と保証の区別](../VALIDATION.md#体のカーネルの影響範囲検証)に正本をまとめました。
[担当範囲・判断の記録](../measurements/field-kernels-20261117-orchestration.json)と
[片付け記録](../measurements/field-kernels-20261117-cleanup.json)を保存しています。

既存の型・行列積・整数算術は共有するため、独立oracleはそれらを含む有限の結果照合です。
証明全体の独立性や任意長入力に対する新しい形式証明を主張しません。

影響範囲の検証を再実行する場合は、クリーンなcheckoutと既存のMoonBit/Lean環境で次を実行します。

```sh
mkdir -p .tools/field-optimization-20261117
tools/measure --cpu 4 python3 docs/measurements/field-kernels-20261117-harness.py
```

性能比較の古いworktreeは片付け済みです。再計測時は基準 `4d9e6c4` と採用コードのcheckoutを別に作り、
同一の `src/cmd/gf2consumerbench` を両方に置いて、それぞれnative release・`-j 1`でビルドしてください。
`tools/compare_field_kernels.py --help` の二つのsource root・artifact・harnessを指定し、
6つのcaseを `--case` で列挙します。各raw JSONにcase・hash・反復数・順序を残しています。
SDKの共有には `.tools/moon` だけをリンクし、`_build` は共有しません。
