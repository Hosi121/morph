# Integer simplicial homology from checked Smith transforms

This milestone asks whether the existing exact Smith implementation can recover
the integer homology of finite simplicial complexes, including torsion, without
introducing a second integer elimination implementation. `src/homology` answers
that question for finite regression cases, with a checker that accepts a result
only when it is bound to the actual complex and requested degree.

The production representation uses `Chain`, unary `Nat`, `Bool`, exact binary
integers, and recursion. Arrays and machine arithmetic occur only in tests and
the independent Python fixture generator. This is an executable exact algorithm
with checked witnesses, not a universal formal proof or a scalability claim.

## Input and orientation conventions

A simplex is a nonempty `Chain[Nat]` with strictly increasing vertices. Its
increasing order supplies its orientation. `validate` accepts an explicitly
complete list of simplices, rejects duplicate simplices and missing nonempty
faces, and stores the outer list in lexicographic order. Outer list order has no
mathematical significance. Reversed vertices and repeated vertices are rejected,
rather than normalized in a way that could hide an orientation error.

`closure` accepts canonical nonempty generators and adds every nonempty face.
Repeated generators and shared faces are deliberately merged. An isolated vertex
must be supplied as a singleton generator or face. `closure(Nil)` and
`validate(Nil)` denote the empty complex. Empty simplices in either input are
rejected; no augmented chain group is introduced.

`simplices(K,k)` supplies the lexicographic basis of `C_k`. `boundary(K,k)` has one
column per k-simplex and one row per (k-1)-simplex. Its entries are exact integers
from the alternating deletion formula

\[
\partial[v_0,\ldots,v_k]
=\sum_{i=0}^k(-1)^i[v_0,\ldots,\widehat v_i,\ldots,v_k].
\]

In degree zero the target is the zero group: `d_0` has zero rows and one column
per vertex. Thus homology is **unreduced**: a nonempty connected complex has
`H_0 = Z`, isolated vertices each contribute a summand, and the empty complex has
zero homology in every supported degree. All supported degrees are nonnegative
`Nat` values. Degrees above the top simplex retain the correct empty matrix
shapes and return zero homology. `boundary_squared_zero(K,k)` multiplies the two
actual consecutive boundaries and checks every entry is zero.

These conventions implement the alternating boundary and cycle-mod-boundary
definition in [Hatcher, Algebraic Topology, Chapter 2, section 2.1](https://pi.math.cornell.edu/~hatcher/AT/ATch2.pdf).
The source describes more general delta complexes as well; this package's input
is the narrower finite abstract simplicial complex.

## Why the kernel basis must be integral

For `A=d_k`, the existing Smith checker certifies

\[
UAV=D,\qquad U,V\text{ unimodular}.
\]

Let `r` be the number of nonzero diagonal entries. The last `n-r` columns of `V`
are a complete **integer** basis of `ker(A)`. A rational nullspace basis would
not by itself justify quotienting integral cycles: its integer span can be a
proper sublattice of all integral cycles. Using unimodular coordinates preserves
the lattice and avoids this error.

For `B=d_(k+1)`, form

\[
E=V^{-1}B=\begin{pmatrix}0\\C\end{pmatrix}.
\]

The first `r` rows must vanish because `AB=0` and the corresponding nonzero
diagonal entries of `D` annihilate no nonzero integer. The remaining matrix `C`
expresses the actual boundaries in the complete cycle lattice. Consequently

\[
H_k(K;\mathbb Z)\cong\mathbb Z^{n-r}/\operatorname{im}(C).
\]

A second checked Smith decomposition of `C` gives the free rank and cyclic
torsion factors. Zero diagonal entries contribute free summands, unit factors
contribute no summand, and factors greater than one are retained in divisibility
order. The implementation delegates this extraction to `smith.cokernel`.

The existing `linear.inverse` is reused only to produce `V^-1`, not to choose the
integer cycle lattice or compute torsion. Every returned rational denominator
must equal one, and both exact integer identities `V*V^-1=I` and `V^-1*V=I` are
checked. No new elimination engine is introduced. The existing Smith checker
already uses the exact rational determinant routine to test unimodularity.

## API and trust boundary

`compute(K,k,fuel)` runs the existing Smith machine on `d_k`, constructs the
coordinate image, and runs Smith again on its bottom block. Each Smith run has
at most `fuel` transitions. `BudgetExhausted` is explicit, distinct from
`InvalidWitness`, and never returned as a mathematical answer. The fuel is a
transition bound per Smith pass, not a wall-time or memory bound; boundary
construction, inversion and checking are not metered by it. Paused computations
are not retained in this first homology API.

`Computed(certificate)` includes `result(certificate)`, with `free_rank: Nat` and
`torsion: Chain[Binary]`. `cycle_basis(certificate)` gives the full cycle basis in
the original simplex coordinates. It is a basis of cycles before quotienting,
not a minimal list of homology representatives.

`check_result(K,k,actual,certificate)` independently checks the following without
calling Smith search, homology computation or rational inversion:

1. The witness source and degree equal the actual requested source and degree;
   the source is a valid canonical complex; the witnessed group equals `actual`.
2. Reconstructed `d_k` is the source of its Smith witness, and `smith.check`
   verifies its dimensions, unimodularity, `U*A*V=D`, signs and divisibility.
3. The actual `d_k*d_(k+1)` is zero. Both integer inverse identities hold.
4. The stored coordinates equal `V^-1*d_(k+1)`, their first `r` rows are zero,
   and the stored image presentation is exactly their remaining rows.
5. The second `smith.check` validates that presentation, and the resulting
   cokernel invariants equal the actual returned group.

Public certificate fields permit independently supplied witnesses and tampering
tests. Opaque checked Smith decompositions are still rechecked. Accessors alone
do not validate an untrusted certificate; use `check_result` with the actual
returned value. This avoids accepting a coherent certificate for some unrelated
complex or result.

## Finite evidence

| Complex | Nonzero unreduced integral homology | Euler characteristic |
| --- | --- | --- |
| Empty | none | 0 |
| Three isolated vertices | `H_0 = Z^3` | 3 |
| Triangle boundary | `H_0 = Z`, `H_1 = Z` | 0 |
| Filled triangle | `H_0 = Z` | 1 |
| Triangle boundary, isolated vertex, disjoint edge | `H_0 = Z^3`, `H_1 = Z` | 2 |
| Tetrahedral sphere | `H_0 = Z`, `H_2 = Z` | 2 |
| Filled tetrahedron | `H_0 = Z` | 1 |
| Six-vertex real projective plane | `H_0 = Z`, `H_1 = Z/2` | 1 |
| Seven-vertex torus | `H_0 = Z`, `H_1 = Z^2`, `H_2 = Z` | 0 |

The projective-plane and torus generators are the exact facet lists in the
[official Sage simplicial complex examples source](https://github.com/sagemath/sage/blob/develop/src/sage/topology/simplicial_complex_examples.py)
(`RealProjectivePlane`, `Torus`, read 2026-11-17). They have f-vectors `(6,15,10)`
and `(7,21,14)`. Sage's sample generic homology convention is reduced; the
`H_0=Z` entries above follow this package's explicitly unreduced convention.
The facet data are frozen in both the tests and generator, so later upstream
changes do not silently alter the regression cases.

`tools/generate_homology_fixtures.py` uses an independent standard-library Python
model. It enumerates all 167 closed nonempty-face sets on subsets of four
labelled vertices, including the empty complex. For each one it computes exact
rational ranks by `Fraction` elimination and ranks over GF(2). MoonBit tests
compare all four nonnegative degrees through degree three with the resulting
free ranks and check the Euler identity. In this finite cohort all homology is
torsion-free. A separate test-only array algorithm recomputes GF(2) ranks from the
actual MoonBit boundary matrices.

For both surfaces the generator independently builds exact signed boundary
matrices and field ranks; tests compare the entire actual matrices, including
zero-width/zero-height shapes. For the projective plane its rational Betti
numbers are `(1,0,0)`, whereas its GF(2) Betti numbers are `(1,1,1)`. This detects
two-primary torsion, but field ranks alone do not distinguish order two from
order four or higher powers of two. To remove that ambiguity, the generator
computes all 3003 ten-by-ten maximal minors of its rank-ten `d_2` using Bareiss
integer determinants. Their gcd is **2**, proving the product of its integral
torsion factors is two independently of Smith search. The torsion of this
boundary cokernel equals the torsion of `H_1`: its quotient by `H_1` is the free
abelian group `im(d_1)`. Together with the rational free rank this gives exactly `Z/2`.

The tests also check cycle vectors directly against the actual boundary;
canonical/closure rejection; source, degree and returned-result mismatches;
changed inverse, coordinate matrix and both Smith witnesses; finite fuel
exhaustion; isolated vertices; and degrees above the complex dimension.

## Connection to existing domains and limits

The image presentation `C` makes each homology group an ordinary finitely
presented abelian group. Its Smith invariant factors use exactly the same
integer arithmetic and cokernel reasoning as the existing Smith package. Over
GF(2), boundary matrices also define parity constraints: cycles satisfy
`d_k*z=0`, while quotienting by the next image identifies homologous cycles.
The projective-plane example shows why binary ranks alone cannot recover
integral torsion orders.

There is no persistence filtration, cohomology, cup product, relative/reduced
homology, simplicial map, or geometric realization API in this milestone.
Closure may generate exponentially many faces of a large generator. Dense
recursive matrix products and exact Smith search are appropriate for the small
finite cases tested here; no large-complex performance advantage is claimed.
Search-free checking still uses exact determinants and matrix arithmetic and is
not claimed to be cheap. The trust boundary includes the reused exact arithmetic,
matrix, rational determinant and Smith checker implementations and the MoonBit
runtime. Universal termination, algebraic correctness and runtime purity are
not formally proved by these tests.

## Reproduction

Use the repository SDK through `tools/moon`. Heavy commands must retain the
shared CPU/lock wrapper (Moon runs use one job):

```sh
tools/measure --cpu 4 python3 tools/generate_homology_fixtures.py --check
tools/measure --cpu 4 tools/moon test -p homology --target native -j 1 --deny-warn
tools/measure --cpu 4 tools/moon test -p homology --target js -j 1 --deny-warn
tools/measure --cpu 4 tools/moon test -p homology --target wasm-gc -j 1 --deny-warn
tools/measure --cpu 4 tools/moon check -j 1 --deny-warn
tools/measure --cpu 4 tools/moon info -p homology
tools/measure --cpu 4 tools/moon fmt src/homology --check
python3 tools/audit_purity.py
```

This SDK's `info` subcommand does not expose a job-count flag; it is still pinned
to CPU 4 and protected by the shared lock. Check and test commands use one job.

Validation on 2026-11-17: the package's 10 tests pass on native, JavaScript and
wasm-gc. These ten test blocks include 668 integral homology computations from
the exhaustive small-complex cohort (167 complexes times four degrees), in
addition to the named examples and witness rejection cases. The fixture
regeneration check, module-wide `check --deny-warn`, scoped interface generation,
format check and repository purity gate pass. The purity gate counts 294 kernel
files in this branch. These counts describe this finite milestone, not a
mathematical completeness claim.

The generator needs Python's standard library and the repository's `moonfmt`
only for canonical source formatting; it imports no MoonBit algorithm or
third-party numerical library. Validation results and the milestone commit are
recorded with the integration handoff.
