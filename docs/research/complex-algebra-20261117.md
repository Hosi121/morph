# 複素代数的数と全複素根（2026-11-17）

[研究索引](README.md) / [設計とAPIの選択](../handbook/complex-algebra.md)

有理数上の因数分解、実代数的数、F4、分離線形形式、Sturm–Tarskiをつなぎ、
複素代数的数の演算と有理係数多項式の全複素根を扱う経路を実装した。
計算核の純ADT制約と、未完了を数値結果へ置き換えない方針を維持する。

## 実装の接続

複素数の等号は各座標の厳密な実根比較で決める。定義多項式や区間の一致とは異なる。
演算証拠の検査では表現を一致させ、別の問題・共役・値への流用を拒否する。
有理数の定義が一次の場合は、検査可能な有理数演算へ戻して不要なresultantを避ける。
除算では `c²+d²` を二座標で共有する。これら単独の速度倍率は計測していない。

## 複素根を実解へ帰着する理由

有理多項式に対し `p(x+i*y)=R(x,y)+i*I(x,y)` を正確に展開する。
実数の組 `(x,y)` で `R=I=0` であることと、複素数 `x+i*y` がpの根であることは同値である。
平方因子を除いた多項式を使い、一つのパラメータαと二つの座標多項式で全実点を表す。
異なる複素根の個数と平方因子を除いた次数が一致することを検査する。
重複度は元のpの微分を根で評価し、初めて非零になる階数から求める。

複素数上で `u=x+i*y, v=x-i*y` と置けば、同じ方程式は `p(u)=p(v)=0` となる。
次数nの平方因子を除いたpからはn²個の組が生まれる。実数の組だけが必要でも、
消去計算の中間次数と証拠にはこの大きさが現れる。

## 表現コストから因数分解の先行へ

`(z²+1)²(z-1)` を直接列挙すると、平方因子を除いても次数3の消去問題になる。
一回のスタック採取では、F4の行結合と元idealへの証拠多項式の加算を実行中だった。
分離線形形式の開始値を変える案も試したが、問題を解消できず、既定値の変更は採用しなかった。
`start_from` と `separation_start_at` は再現・探索の明示的な入口として残す。

次に既存のQQ因数分解を先行し、`z²+1` と `z-1` を別々に列挙した。
各因子の次数をd_jとすれば、消去の対象となる組はn²からΣd_j²へ分かれ、この例では9から5になる。
異なる因子間の不要な組を作らず、重複度は元の分解から戻せる。
因数分解自体の費用と、既約な高次数の費用が消えるわけではない。

`RootFamily` の検査は、元の多項式のunit・因子・重複度、因子間の互いに素なこと、
各因子の全根、実際の返却リストの位置と値、重複度の総和を結び付ける。
因数分解の未完了と、既約性検査の `Undecided` も独立した結果として残す。

## 独立参照と改竄検査

[Fraction・SymPyの参照](complex-oracle-20261117.md)は12入力、21個の異なる根、
重複度の総和25、42個の座標の定義・有理区間を含む。
方程式の展開はFractionのHorner演算とSymPy、根と重複度は正確な代数式・微分・次数で照合した。
MoonBit側は有理の箱への所属をSturm–Tarskiで検査し、近似値や根の並び順を期待値にしない。

12入力の全根と重複度は因数分解先行の経路で検査する。
直接列挙の参照経路では11入力の全根を検査し、重い混合因子の入力は展開を検査する。

有効だが別の微分query、座標の混同、半開端点、正確な燃料と試行回数の再開を調べた。
この有限範囲で正しさの不具合は見つからなかった。

## 残る制約

演算は複素代数的数まで閉じるが、多項式の全根APIの入力係数は有理数である。
基底を持つ一般の複素数体、分解体の自動構成、QQ上のGalois群計算は未実装である。
演算や消去で次数・係数・証拠が増大し得る。既約な高次数に対する実用速度は保証しない。

因数分解の準備は途中状態を保持せず、既約性検査が未確定なら返された分解を再検査できる。
根の探索と座標の取り出しは再開可能で、因子間では完了した根集合を保つ。
燃料は仕事の回数であり、最終検査や一つの有理演算の実時間上限ではない。
既存のLeanモデルを、この複素代数全体の形式証明として扱わない。
