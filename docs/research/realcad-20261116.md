# 一変数の実数多項式制約を符号不変なセルで決定する

[ドキュメント](../README.md) / [研究・探索記録](README.md)

`realcad`は、有理係数の一変数多項式に対する六つの関係と、否定・論理積・論理和を扱う。
実数直線を符号不変な区間と根の点に分け、存在する解と全称式の反例を厳密に求める。
無理数の点は、問題に属する定義多項式と有理数の一根区間で表し、近似浮動小数点へ変換しない。

**入口:** [API](../../src/realcad/pkg.generated.mbti) · [データ型](../../src/realcad/data.mbt) ·
[符号判定](../../src/realcad/signs.mbt) · [生成・再開](../../src/realcad/machine.mbt) ·
[証拠検査](../../src/realcad/decomposition.mbt)

## 足場と対象

既存の`Polynomial`、`Rational`、Sturmの根数・隔離をそのまま使う。
原子式は`p(x) < 0`、`<= 0`、`= 0`、`!= 0`、`>= 0`、`> 0`。
`Formula`の任意の有限Boolean結合を入力でき、定数と零多項式も区別して扱う。
多変数や、自由パラメーターを残す量化消去は対象に含まない。

`prepare`は全原子の変数数を検査し、重複する多項式をまとめる。
零多項式を除いた原子の積を作り、その平方因子を除いた多項式を`R`とする。
`AlgebraicPoint(interval)`の意味は、`root_polynomial(problem)`の区間内の唯一の根である。
区間だけを取り出して、問題と無関係な代数的数としては扱わない。

## 符号分割が十分な理由

1. 非零の原子多項式の実根は、すべて`R`の根でもある。
2. それらの根の間では、各原子の符号は一定である。
3. `R`の一根区間`(a,b]`には、どの原子も高々一つしか実根を持たない。
4. 原子がその区間に一根を持てば、それが`R`の隔離された根と同じ点であり、原子の符号は0。
5. 原子の根数が0なら、区間の有理中点での評価と、隔離された根における符号が一致する。

零多項式の符号は常に0として別処理する。
平方因子除去は積の根集合だけに適用し、各原子の符号評価には元の多項式を使う。
そのため偶数重根で符号が変わらない場合も、根の点での等式を失わない。

Sturmが返す半開区間は端点で接する場合がある。
有理中点を根の間のサンプルに使えるよう、隣り合う区間の間に厳密な隙間ができるまで後側を精密化する。
根が`r`個なら、両端の非有界区間を含めて`2r+1`個のセルを作る。

区間分割による決定の考え方は
[Narkawicz–Muñoz–Dutle](https://pmc.ncbi.nlm.nih.gov/articles/PMC6749613/)、
解の生成と検査を分ける一変数CADは
[Li–Passmore–Paulson](https://link.springer.com/article/10.1007/s10817-017-9424-6)を参考にした。
これらの文献にある機械証明を、このMoonBit実装の証明として流用するものではない。

## 生成・再開・検査

```text
prepare(formula) -> Problem
start(problem) -> Machine
run(machine, fuel) -> Complete(Decomposition) | Paused(Machine) | Fault
certificate(decomposition) -> Certificate
check(problem, certificate) -> Decomposition?
```

燃料は、隔離ノード、隣接区間の精密化、セルの符号判定の単位を数える。
多項式の積・GCDや有理数演算は、その一歩の内部にも準備処理にもあるため、一定実時間の予算ではない。

証拠は根の隔離区間、各セルのサンプル、原子の符号列、式の真偽を持つ。
検査器は根数・順序・全根の被覆と、セルの並び・符号・真偽を検査する。
根隔離の探索は再実行しないが、Sturmの根数、算術、符号判定の補助関数は生成器と共有する。
証拠の形式は、区間から定まる有理サンプルを使うものに限定している。

検査を通過した`Decomposition`だけから、存在の証人・全称式の反例・満たすセルの一覧を取り出せる。
`check_witness`は単独の有理点または一根区間でも元の式を検査する。
返却される型と検査器はMoonBitプログラムであり、検査器全体を形式証明した主張はしない。

## 独立検証

[生成器](../../tools/generate_realcad_fixtures.py)はSymPy 1.14.0の厳密な実根と代数的符号を使う。
MoonBit側のSturmやセル生成は使わず、各実根とその間の点でBoolean式を評価して期待値を作る。

- 係数−2〜2の次数2以下の全125多項式と全6関係。
- 共有根、偶数重根、無実根を含む8多項式の全64対と三種類のBoolean結合。
- 原子を持たない真・偽。

合計944例で、根数・全セルの真偽列・存在・全称の答えを照合する。
別の手書きテストは、無理数だけの解、矛盾、重複原子の共有、一歩ずつの再開、
不正な変数数、根の不足・逆順、偽の符号・真偽・サンプル、零根・複数根の区間を検査する。
[期待値データ](realcad-20261116-fixtures.json)と[実行テスト](../../src/realcad/fixtures_wbtest.mbt)を保存する。

## 費用と残る課題

積の次数と係数が増えるため、原子が多い入力では準備・根隔離が重くなる。
同じ結果を返すことと、他の実数制約ソルバーより速いことは別であり、速度優位は主張しない。
将来、原子ごとの根隔離や部分的な符号伝播を使う際も、全根の被覆と半開端点の規約を保つ必要がある。
