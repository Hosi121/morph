# Finite-prime polynomial coefficient products, 2026-11-17

## Decision

Adopt one bounded mechanism: normalize an arbitrary public scalar once, then
share already-canonical zero and unit products. The supported performance result
is the mixed unreduced-scalar fixture: median whole-process time fell from
214.573 ms to 50.896 ms (4.216× baseline/candidate), with all five paired ABBA
block ratios between 4.194× and 4.398×. This fixture includes zero, unit, ordinary
and a 128-bit scalar; it is not a claim about every scalar or polynomial.

Dense generic multiplication, unit-heavy multiplication, division, GF2 and the
one-shot control have unresolved or small differences. Generic multiplication
is not claimed to be faster. The same exact public outputs and errors are
preserved. No algorithm follow-up or additional mechanism was attempted.

The baseline is `ab22a4a22625f4beb2bd2a49b836f769c941ef90`. Milestones:

- `ee61787`: freeze the six public-API benchmark cases before library edits.
- `511b921`: canonical product sharing, one-time scalar normalization and tests.
- Evidence commit: this report, all samples, source manifests, API/checker audit.

Only `src/fppoly/polynomial.mbt` changes in production. No number-field or GF2
kernel code changes. New test/harness/report files remain in the worker's
announced scope. Root integration, publication and worktree cleanup are separate.

## Falsified premise and actual removed work

The initial audit suggestion that `modular.multiply` re-reduces its operands is
false at this baseline. Its entire implementation is
`reduce(modulus, binary.multiply(a, b))`: only the product is reduced. Baseline
`fppoly.scale` also does not normalize its arbitrary scalar first; it multiplies
every coefficient by the original scalar. The exact original source extracts
are preserved in `night-fp-20261117-raw/callsite-audit.json` to avoid rediscovering
the mistaken premise.

The actual change removes a product remainder when a private, canonical operand
is zero or one. `binary.multiply` already shares zero/unit products, but the
subsequent modular remainder still checks those canonical results. A private
`multiply_reduced` returns the appropriate existing operand directly for these
cases and keeps the original `modular.multiply` for all other products.

Public `scale` first preserves the characteristic-two dispatch and zero
polynomial fast exit, then reduces its arbitrary scalar once. A zero residue
returns the zero polynomial; a unit residue returns the existing polynomial.
Other canonical coefficients use the same private product helper. Thus a huge
scalar is not carried through a separate multiplication and remainder for every
coefficient. Convolution and odd-prime division leading-coefficient products use
the helper as well. No sparse-convolution rewrite, table, approximate arithmetic,
mutable storage, primitive numeric kernel or certificate shortcut is added.

## Representation and call-site audit

Opaque `Polynomial` values store canonical coefficients in `[0,p)` and omit
trailing zeroes. Public construction reduces arbitrary inputs; private addition,
negation, multiplication and division preserve that invariant. The helper is
private because returning an arbitrary other operand for `1*b` would be incorrect
if b had not been reduced.

- Convolution receives two opaque canonical coefficient chains.
- Division uses a canonical leading coefficient and an inverse returned by
  `modular.inverse`, which canonicalizes through `signed_reduce`.
- Public scale accepts any Binary scalar and now establishes the canonical
  boundary once; zero polynomials exit before that reduction.
- Derivative exponents and public evaluation points can exceed p. Their generic
  modular arithmetic is byte-for-byte unchanged and does not use the helper.
- Characteristic-two dispatch and implementation are byte-for-byte unchanged;
  unreduced GF2 coefficients, scalars and points retain their existing behavior.
- Public field-compatibility checks and error precedence are unchanged, including
  mismatched zero operands. No public function or type signature changes.

The complete irreducibility, Bezout and factorization checker source files are
byte-for-byte unchanged. Existing checks remain enabled. `callsite-audit.json`
records their hashes and unchanged derivative/evaluate/public-entry-point hashes;
`api-diff.json` records the identical generated fppoly public interface.

Final fppoly tests passed 25/25 on each of native, wasm-gc and JS, using
`-j 1 --deny-warn`. All-target `moon check --deny-warn -j 1` passed (1835 tasks),
the purity gate passed for 327 kernel files, and generated fppoly API bytes are
identical to baseline. Exact commands and outputs are recorded verbatim in
`night-fp-20261117-raw/validation.json`. The fppoly package tests include exhaustive small-prime residue-pair products and
large-prime boundary values (including products exceeding signed 32-bit range),
independent host Int64 polynomial arithmetic, arbitrary unreduced constructors,
zero/unit/multiple-of-p scalars, a 512-bit scalar, field mismatch precedence,
long derivative exponents exceeding the characteristic, and unreduced evaluation
points. Existing division, factorization and irreducibility tests remain enabled.

The new tests build expected results with host integer arithmetic rather than
calling the new helper. Every benchmark iteration also checks every canonical
coefficient against independent host arithmetic; division uses a fixed exact
host reconstruction with a proper remainder. Complete actual outputs are
serialized and compared across revisions. No checksum substitutes for equality.

The worker's targeted tests cover fppoly; root integration owns the final combined
consumer suite. No memory measurement, other-backend timing, or exhaustive claim
about coefficient sizes and degrees is made. An already-canonical nonunit scalar
now incurs one scalar reduction plus small identity tests; its standalone timing
was not isolated by this six-case fixture set.

## Frozen public comparison

Both executables are native release builds with `-j 1 --deny-warn`. Builds, tests
and measurements use the shared `tools/measure --cpu 4` lock; no worker build/test
or timing overlaps the comparison. Compilation is excluded. The harness has six
fixed cases and five independent ABBA blocks per case: ten processes per variant,
120 checked processes total. Every output matched in full and every oracle check
passed. No case, iteration count or expected result changed after freezing.

Whole-process time includes process startup, field/input setup, oracle setup,
one checked warm-up, the batch and all checks/serialization. `elapsed_us` covers
only the fixed operation batch, also including all per-iteration output checks
and serialization. The one-shot case additionally repeats field construction and
both public polynomial constructors inside each iteration. Table values are
median milliseconds per complete process, not per single polynomial operation.
Ratios are baseline/candidate; paired block ranges show variation, not confidence
intervals.

| Case | Iterations | Before ms | After ms | Process ratio | Five block ratios | Inner ratio |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| multiply65537-dense | 80 | 140.819 | 139.585 | 1.009× | 0.992–1.013× | 1.001× |
| multiply257-unit | 300 | 53.096 | 51.104 | 1.039× | 0.996–1.106× | 1.042× |
| scale257-unreduced | 300 | 214.573 | 50.896 | 4.216× | 4.194–4.398× | 4.390× |
| divide17-d24 | 500 | 20.867 | 20.629 | 1.012× | 0.938–1.103× | 1.019× |
| gf2-control | 1000 | 16.756 | 16.652 | 1.006× | 0.950–1.057× | 0.992× |
| one-shot17 | 3000 | 66.454 | 65.851 | 1.009× | 0.974–1.046× | 1.011× |

`multiply65537-dense` uses nonzero nonunit coefficients and is a negative control
for the extra identity dispatch. `multiply257-unit` mixes zeros, ones and p-1.
`scale257-unreduced` applies seven fixed scalars (0, 1, p-1, p, p+1, 7 and
`2^127+35`) to the same degree-32 polynomial. Its 4.216× process ratio is the
adoption evidence, rather than an inference that all multiplication improved.
`divide17-d24` checks a constructed quotient and nonzero proper remainder.
`gf2-control` checks multiplication, scaling, derivative and unreduced-point
Horner evaluation through the unchanged GF2/general paths. `one-shot17` measures
field/input construction and a dense multiplication with no zero/unit input
coefficients.

The dense and one-shot medians are close to one, with block ratios straddling one;
their effects are unresolved. Unit multiplication and division likewise do not
support strong general claims. The GF2 inner median is about 0.8% slower while
its whole-process median is about 0.6% faster; this unchanged-path control exposes
the measurement noise rather than an established regression or improvement.
No same-binary A/A control was run, and none of these small differences is treated
as proven speedup. Ordinary canonical-scalar scaling, other primes/degrees and
peak allocation remain unmeasured.
