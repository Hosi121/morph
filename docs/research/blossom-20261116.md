# 不変 ADT による一般グラフの Edmonds blossom matching

[研究・探索記録](README.md) / [アルゴリズム一覧](../ALGORITHMS.md)

2026-11-16 の実装記録。対象は有限・無向・自己ループなしの一般グラフの最大要素数マッチング。二部性を仮定せず、奇閉路を実際に縮約し、縮約先の増加道を元の頂点列へ展開する。計算核は Bool、Peano `Nat`、不変 `Chain`、不変 ADT、クロージャ、構造再帰で構成し、組み込み数値・数値リテラル・配列・変更可能状態・FFI を使わない。

`problem(vertices, edges)` は頂点ラベルの重複、自己ループ、存在しない端点を拒否する。ラベルは連番でなくてよい。辺の向きは区別せず、同じ辺や逆向きの重複を許す。`Problem` の構築は検証済みコンストラクタに限定する。

| 関数 | 結果 |
| --- | --- |
| `maximum_matching(problem)` | 最大マッチングの辺列 |
| `maximum(problem)` | 最大マッチングと Tutte–Berge barrier |
| `augmenting_search(problem, matching)` | 増加道の有無と実際に縮約した奇閉路列 |
| `check_matching(problem, matching)` | 辺の存在と端点の排他性 |
| `check_augmenting(problem, matching, path)` | 単純性・交互性・自由な両端点 |
| `augment(problem, matching, path)` | 検証済み増加道の反転 |
| `certify(problem, matching)` | 与えた最大マッチングに対する最適性証拠 |
| `check(problem, solution)` | マッチングと最適性証拠の独立検査 |

`augmenting_search` は入力マッチングが不正なら `None`、正常に探索を完了した場合は `Some(Search)` を返す。`Search.path = None` は増加道が存在しないという探索結果。`Search.blossoms` は縮約した順の閉路で、後続の閉路は前段の縮約後のラベルを使う。これは診断情報であり、閉路列そのものを独立証明書とはしていない。`Solution` の証明書は別途 `check` が検査する。

`maximum_matching` と `maximum` の `None` は内部不変条件の破れを防御的に表す。有限の検証済みグラフでは成功する設計。`certify` は不正・非最大の入力を最終検査で拒否する。

## 縮約と展開

自由頂点をすべて根として交互森を作る。偶数深さの頂点だけをキューに入れ、未訪問の隣接頂点とその mate を奇数・偶数の順に追加する。異なる木の偶数頂点間の辺からは増加道が得られる。同じ木なら共通祖先までの二つの道とその辺が blossom を作る。

blossom の頂点を基点のラベルへ写し、内部辺を除いて新しい不変グラフを作り、探索を再帰する。基点に到達する幹のマッチ辺だけが縮約マッチングに残る。再帰先で検出する blossom は既存の縮約頂点を含められるため、多段の入れ子に対応する。

展開では、縮約頂点に接する非マッチ辺の元の端点を探す。奇閉路上には基点からその端点への偶数辺の道が一つあり、それを挿入する。縮約頂点が増加道の端にある場合、内部にある場合、縮約頂点を通らない場合を扱う。展開後は元のグラフとマッチングだけを使う `check_augmenting` で再検査する。

探索の終端性は、森の拡張で未訪問頂点が減り、縮約ごとに頂点が少なくとも二つ減り、増加ごとにマッチング要素数が一つ増えることに基づく。今回この終端性を証明支援系で形式化してはいない。

縮約・展開の数学的根拠は [Dalhousie Algorithms II: contraction](https://web.cs.dal.ca/~nzeh/Teaching/4113/book/matching/general_maximum_cardinality_matching/edmonds/contract.html) と [expansion, Lemmas 7.33–7.34](https://web.cs.dal.ca/~nzeh/Teaching/4113/book/matching/general_maximum_cardinality_matching/edmonds/expand.html) を確認した。一般の奇閉路を無条件に縮約できるという主張はせず、現在のマッチングに対する交互森から得た blossom に限定する。[Abdulaziz–Mehlhorn の形式的正当性証明](https://arxiv.org/abs/2412.20878) も参照したが、この MoonBit 実装がその形式化によって検証されたという意味ではない。

## 独立した最適性証拠

証拠は頂点集合 `A`。検査側は `G − A` の連結成分を独立に走査し、奇数個の頂点を持つ成分の数 `q` を数える。そのうえで次の等式を検査する。

```text
2 × |matching| + q = |vertices| + |A|
```

任意のマッチングは、`G − A` の各奇成分につき自由頂点を一つ残すか、`A` への辺を一つ使う。`A` の頂点が解消できる奇成分は高々 `|A|` 個なので、上式の右辺と `q` から要素数の上界が得られる。有効なマッチングがその上界に一致すれば最適。検査器は blossom、交互森、増加道探索、総当たり oracle を呼ばない。

証拠生成には Gallai–Edmonds 分解を使う。最大マッチングにおいて自由になれる頂点の集合を `D` とし、`A = N(D) − D` を返す。既に自由な頂点は `D` に含まれる。マッチしている頂点 `v` は、その頂点とマッチ辺を削除したグラフで一回だけ増加道探索を行う。元の最大要素数を回復できれば `v` を自由にできるので `D` に含める。従って最悪で頂点数回の追加探索を要するが、証拠生成でマッチングを総当たりしていない。空集合が既に上式を満たす場合は追加探索を省く。

この barrier の存在は [MIT 18.438 Lecture 3, Theorems 1–2](https://math.mit.edu/~goemans/18438F09/lec3.pdf) の Tutte–Berge / Gallai–Edmonds の記述に基づく。生成結果も必ず独立検査器を通してから返す。

## 検証

MoonBit `moonc v0.10.20+65efd5b93`、`moon 0.1.20261104` を使用。すべての重い検査は共有 Git ディレクトリのロックを取る `tools/measure --cpu 6` 経由で実行する。

- 頂点数ゼロから五までの全 1,100 グラフで、独立の数値総当たりによる最大要素数と照合し、生成した barrier も検査。
- 六頂点の全 32,768 グラフで、独立総当たりと最大要素数を照合。
- 五頂点の全グラフと全実行可能初期マッチングの 9,984 組で、増加道の存在が「初期要素数が独立 oracle の最適値未満」と一致することを検査。
- 五頂点グラフと削除集合の全 32,768 組で、独立した数値連結成分カウンタと証拠検査器を照合。非最大マッチングに偽の barrier を付けても受理しないことを確認。
- 七〜十頂点の決定的な 1,000 サンプルを独立総当たりと照合し、辺順・頂点順を反転した場合も確認。
- 三角形、幹のある blossom、縮約頂点を道の内部で通る場合、両向きの展開、縮約頂点を通らない増加道、独立成分、孤立頂点、不正入力、偽証拠を検査。
- 一〜十六段の入れ子の blossom を構成し、実際の縮約段数と、全頂点を通る展開後の増加道を確認。六頂点の具体例では `(1,2), (3,4)` から二段の縮約を経て三辺の完全マッチングへ到達する。

## 制約と今回分かったこと

一般グラフの増加道探索に必要な blossom 縮約と再帰的な展開を、このプロジェクトの不変 ADT だけで構成できた。独立した Tutte–Berge 上界との一致も確認でき、有限総当たりのテスト範囲を越えて個々の返却結果を検査する手段がある。

対象は重みなし最大要素数マッチングであり、最大重みマッチングではない。明示的なグラフ再構築、リストの線形走査、Peano ラベル比較を使うため、配列版の典型的な計算量や速度をこの実装にそのまま主張しない。大規模グラフでの速度・スタック上限・メモリ上限は未計測。停止・再開用の fuel 状態や incremental matching は公開していない。機械化した正当性証明は今回の成果物に含まれない。
