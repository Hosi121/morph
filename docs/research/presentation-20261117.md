# Group presentations, integer matrices, and first homology, 2026-11-17

## Question and completed connection

Can a short pure ADT adapter connect finite group-presentation words to the
existing integer Smith kernel, with checked abelianization and an honest
connection to first homology? `src/presentation` provides this connection.
It adds word validation, signed exponent sums, a dimension-preserving relation
matrix, a resumable wrapper, and a source/result-bound certificate. All matrix
reduction and Smith verification remain in `src/smith`.

Here “finite presentation” means finitely many generators and relators of
finite length. The presented group need not be finite. The implementation does
not enumerate its elements, solve its word problem, or identify an isomorphism
type of the original nonabelian group.

## Algebraic and topological reason

Let P be `⟨x₁,…,x_g | r₁,…,r_k⟩`. The abelianization of the free group is the
free abelian group `Z^g`, with each word sent to its vector of signed generator
exponent sums. Conjugation disappears in an abelian group, so the normal
closure of the relators maps exactly to the integer subgroup generated by
their exponent vectors. Thus

`P_ab = Z^g / span_Z(exp(r₁), …, exp(r_k)) = cokernel(A)`.

The matrix A has g rows and k columns. This orientation matters: generators
are generators of the codomain of A, so their count supplies the cokernel's
free ambient rank. An empty row collection retains its k columns; an empty
relator collection gives g empty rows. These cases do not require a separate
classification algorithm.

For a path-connected space X, Hatcher's
[Algebraic Topology, Theorem 2A.1, p.166](https://pi.math.cornell.edu/~hatcher/AT/ATch2.pdf)
identifies `H₁(X;Z)` with the abelianization of `π₁(X)`. The presentation
description as a free group modulo a normal relator subgroup is recalled in
[Hatcher §1.2, p.51](https://pi.math.cornell.edu/~hatcher/AT/ATch1.pdf).
For a presentation 2-complex with one vertex, one oriented edge for each
generator, and a 2-cell attached by each relator, the cellular boundary into
the edge group is this same exponent-sum matrix, and the next boundary is
zero. This explains the horizontal connection between word presentations,
Smith cokernels and first integer homology. The program checks the algebraic
adapter; it does not construct a topological space or verify that a user's
geometric object has the supplied presentation.

The [GAP reference §39.16-1](https://docs.gap-system.org/doc/ref/chap39.html)
defines abelian invariants as those of the commutator quotient. GAP reports
prime-power factors and zeros; this package uses Smith invariant factors
greater than one plus a separate free rank, so the lists need not have the same
format. The official [GAP finitely presented groups chapter](https://docs.gap-system.org/doc/ref/chap47.html)
also illustrates `⟨a,b | a²,b³,(ab)⁵⟩` and distinguishes words in free generators
from elements of the quotient. These primary sources were verified online on
2026-11-17. No GAP runtime is required.

## ADT representation and verification boundary

A letter contains a natural generator ID and an inverse flag. All IDs must be
strictly below the generator count. The constructor rejects an invalid ID
even when a neighbouring inverse letter would cancel it. Relators are stored
literally; neither free reduction nor sorting changes the input context.
`inverse_word` and `reduce_word` are operations on free words, not decisions
using presentation relations.

An immutable source stores the count, literal relators and exponent matrix.
The state stores this source and `smith.Machine`. `run` delegates to
`smith.run`, preserves a paused machine, propagates a fault, and constructs a
result only after source-bound verification of a completed decomposition.
The public certificate contains the exact source count and words, input
matrix, Smith witnesses U/D/V, and claimed free/torsion invariants.

`check` first reconstructs the source matrix from the literal words. It
compares this matrix with both the source cache and certificate matrix, so
swapping a valid certificate or a cached relation matrix cannot change the
meaning of the original source. Then `smith.check` verifies dimensions,
unimodularity, `U A V = D`, a nonnegative diagonal and its divisibility chain.
The cokernel invariants are recomputed from this checked decomposition.
`check_result` additionally compares the actual source, stored certificate,
checked decomposition and cached cokernel in the returned result. Altering a
valid record alone cannot justify an unrelated returned value.

The verifier is search-free at the Smith layer and does not rerun Smith
reduction. It does share the word exponent-sum code with the producer. Tests
therefore provide a separate machine-integer array implementation of those
sums and a separate minor-based classification. This is executable checking,
not a proof-assistant development.

## Independent tests and concrete examples

The oracle builds integer arrays by scanning signed generator indices and
adding positive or negative one. For every k it enumerates all k-row and
k-column choices, expands each determinant directly, and takes their gcd
`Δ_k`. It obtains each nonzero invariant factor as `Δ_k / Δ_(k-1)`, with
`Δ_0 = 1`, and the free rank as the row count minus rank. This shares neither
the Smith pivot search nor the production binary integer arithmetic.
The mathematical identity used by this oracle is stated for rectangular
matrices in [Richard Stanley, Smith normal form in combinatorics, Theorem 2.4](https://math.mit.edu/~rstan/papers/snf_survey.pdf).

The tests exhaust all 81 two-by-two matrices with entries in `{-1,0,1}`, turn
their columns into presentation words, and compare the resulting free rank
and torsion factors with the independent determinantal divisors. Seven further
rectangular and three-by-three cases include negative entries, rank deficiency,
and multiple nontrivial invariant factors. Five edge presentations cover no
generators, no relations, and several empty relators. Named examples are:

| Presentation | Exponent matrix, generator rows | Abelian quotient |
| --- | --- | --- |
| RP2, `⟨a | a²⟩` | `[2]` | `C2` |
| Torus, `⟨a,b | a b a⁻¹ b⁻¹⟩` | column `(0,0)` | `Z²` |
| Klein bottle, `⟨a,b | a b a⁻¹ b⟩` | column `(0,2)` | `Z ⊕ C2` |
| S3 presentation, `⟨a,b | a²,b³,(ab)²⟩` | rows `(2,0,2)` and `(0,3,2)` | `C2` |
| Triangle `(2,3,5)`, `⟨a,b | a²,b³,(ab)⁵⟩` | rows `(2,0,5)` and `(0,3,5)` | zero |

Each independent model fixture also checks the certificate, the actual
returned result, reconstruction from a checked certificate and finite-order
reporting. Tests additionally check relator order reversal, relator inversion,
free cancellation insertion, duplicate relators, word inverse involution and
free reduction. These transformations preserve the computed invariants;
they deliberately do not make different literal source certificates
interchangeable.

Adversarial cases reject invalid IDs, modified source counts/words/matrices,
invalid Smith witnesses, changed free rank or torsion, source/result/proof
swaps, the same exponent matrix under different literal words, tampered
decomposition/cokernel caches, and a paused machine paired with another
source. Zero fuel and continuation from a real paused calculation are tested.

## Why zero abelianization is not group triviality

The triangle example has `gcd(2,3,5) = 1` on entries and gcd one on its maximal
minors `6,10,15`, so its two Smith factors are both one. Its abelianization
is therefore zero. The test also assigns

`a = (0 1)(2 3)` and `b = (0 2 4)`

as degree-five permutations and checks every literal relator evaluates to
identity. These images generate a complete 60-element group whose derived
subgroup is itself, with a checked `NonSolvable` certificate from `permgroup`.
This concrete nontrivial perfect quotient is compatible with zero
abelianization and rules out a claim that the original presentation must
describe a trivial or solvable group. The test establishes this quotient by
the actual relator evaluations and generated images; it does not establish
that the full presentation is isomorphic to that quotient, even though the
familiar group name A5 motivates the fixture.

## Validation and scope

The milestone passed eight package tests on each of wasm-gc, JavaScript and
native (24 backend test executions) after adding the permutation quotient
bridge. Each test command used `tools/measure --cpu 4`, `timeout 60s`, Moon
`-j 1` and `--deny-warn`. Package checking, formatting and generated public
interfaces passed; the repository purity gate passed with 297 kernel files.
`moon info` and `moon fmt` lack a `-j` flag and were package-limited under the
same CPU lock. No performance comparison is claimed.

The production additions use only ADT naturals, chains and Booleans alongside
the existing exact integer, matrix, Smith and cokernel APIs. Matrix reduction
was not duplicated. Fuel bounds Smith steps and does not bound input scans,
integer size, allocations or determinant checking. Explicit relator words are
not compressed powers. First-homology interpretations require an independently
justified presentation of the relevant connected space. Zero abelianization
alone supplies no decision procedure for the nonabelian group's isomorphism,
triviality, order, solvability or general word equality.
